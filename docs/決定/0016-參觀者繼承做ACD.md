# 0016 參觀者一位接一位：先做 A（前任的遺物）、C（挑下一位）、D（歷任參觀者牆）

- 日期：2026-11-08
- 誰決定：翊文要做繼承；A、C、D 是主線替翊文挑的（翊文：「繼承接下來做」）
- 狀態：有效

## 背景

- 翊文 11-08：

  > 「現在理智歸零以後，下一個探險者可以繼承一些東西……就像Rouge like那樣，每個帳戶是自己的進度，一個探險者後可以下一個」
  >
  > 「繼承接下來做」

- 規劃.md 第四節「參觀者一位接一位」列了 A–E 五個做法。
- 本來就留下來的：解鎖的選項、收藏、靈感、升級、圖鑑、書、結局。重來的：理智、心情、佩佩神話、怪癖、職業和技能、正在走的地下、這一位讀過哪幾本禁書。

## 決定

- **A. 前任的遺物**：換人之前，前一位留一樣東西給下一位，二選一（也可以什麼都不留）：
  - 一件收藏放進館長室的「遺物櫃」，寫「第 N 位參觀者留下的」；下一位開場心情 +10。收藏本身不會少。
  - 最拿手的技能（值最高的那個）傳下去：下一位這個技能的起點 +10。
- **C. 挑下一位**：換人之後，門口有 3 位候選人，職業不重複；每位有一個小優點、一個小缺點（8 種優點、9 種缺點，效果都小）。技能先擲好，卡片上看得到。
  - 第一位參觀者照舊從 6 個職業選，沒有優缺點。
- **D. 歷任參觀者牆**：館長室「歷任參觀者」改成一面牆，一位一張卡（第幾位、職業、優缺點、做了幾隻、地下走到第幾層、看懂幾件、怎麼結束的、留了什麼），點開看詳細。
- **先不做**：
  - B 傳承點數（永久加成）：節奏本來就偏快，會更快。
  - E 多人版排行榜：要等伺服器。
- 數字在 `shared/config.js`（`LEGACY`、`PERKS`、`FLAWS`），文字在 `shared/content3.js`（`TRAIT_TEXT`、`LEGACY_TEXT`），規則在 `shared/legacy.js`。

## 影響

- 存檔多了幾個欄位：`P.perk`、`P.flaw`、`P.cands`、`P.legacy`、`P.relics`、`P.visit`；舊存檔讀的時候自動補（`fixLegacy`）。
- `nextVisitor(P, endedBy, leave)` 多一個參數，回傳值多帶 `entry`、`left`、`cands`；不給 `leave` 跟以前一樣。
- 換人之後 `P.job` 是 null，要先挑候選人（`pickJob()` 看到 `P.cands` 就改成挑候選人）。
- 「怎麼玩」只多一行：「換下壹位參觀者時，可以留下壹樣東西、挑下壹位」（不寫什麼時候換人，見 0007）。
- 小優缺點裡沒有「少扣理智」的（理智歸零要算容易出現，見 `docs/界線.md`）；缺點有「失眠：開場理智 −5」「怕黑：地下多扣 1」。
- 跟 0018（多位參觀者共用博物館）一起看：優缺點、`P.visit`、`P.legacy` 是「這一位的」；`P.relics`、`P.history` 是「博物館的」。

## 什麼時候可以再討論

- 翊文想加 B（傳承點數）或 E（排行榜）的時候。
- 遺物要不要有效果（現在是心情 +10；`LEGACY.relicMood` 改 0 就只是紀念）。
- 第一位參觀者要不要也從候選人挑。
- 玩起來發現某個優點或缺點太強、太弱的時候（改 `PERKS`、`FLAWS` 的數字就好，說明文字會跟著變）。
