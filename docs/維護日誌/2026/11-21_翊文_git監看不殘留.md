## 為什麼要改

> 「檢視記憶體用量」→ 看到 60 個 git 程序 →「要」（結束、順便改清理腳本）

Git for Windows 安裝時在系統設定開了 core.fsmonitor（C:/Program Files/Git/etc/gitconfig）。每個 worktree 第壹次跑 git 就起壹個 `git fsmonitor--daemon` 常駐，worktree 刪掉後它不會走。11-21 下午到晚上堆了 60 個（現存 worktree 只有 17 個），約 0.8 GB。

## 改了什麼

- 當場結束 62 個 fsmonitor--daemon（不動任何檔案，git 需要時會自己再開）。
- 這個 repo 的 .git/config 設 core.fsmonitor = false（只蓋這個 repo，不動系統設定）。repo 約 3,000 個檔，監看幫不了多少。
- wt_clean.cjs `--do`：確保 repo 的 core.fsmonitor 是 false；刪 worktree 前先 `git fsmonitor--daemon stop`。
- 測試 test/tools/wt_clean.test.cjs。

## 怎麼確認的

- 結束後再數：0 個。
- wt_clean 測試過。

## 還沒做、要注意

- 新 clone 或換電腦時，.git/config 不跟著走：第壹次 ship（會跑 wt_clean --do）就會補上。

## 給下一個人

- 又看到很多 git.exe：`Get-CimInstance Win32_Process -Filter "Name='git.exe'"` 看 CommandLine，是 fsmonitor--daemon 就是這個。
