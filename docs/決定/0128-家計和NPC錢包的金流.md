# 0128 金流圖的家計、NPC 錢包有線

- 日期：2026-11-19
- 誰決定：翊文（11-19：「家計跟 NPC 錢包怎麼沒有金流阿」）
- 狀態：已決定（只改記帳的分法，不動錢）

## 決定
1. **發薪水記帳**：`nwMove`（集團 ↔ NPC 錢包）每次搬錢多記 `house.led.units`：`wageNpc|集團|u-wallets`（發薪水）、`wageBack|u-wallets|集團`（多的退回）。累計、不是每人壹筆，鍵數 ≤ 集團數 × 2。沒有單位的 NPC（學生、退休、自由業）的薪水從家計出（`wageNpc|u-household|u-wallets`）。
2. **NPC、散客花的錢記出錢的單位**（`npc_spend.js` 的 `nsLed`）：門票（`npcTicketBudget`、`npcTicketMuseum`）、店裡（`npcFood`、`npcJob`、`npcCellar`、`npcCraft`）、散客門票（`npcCrowdBudget`、`npcCrowdMuseum`）、娛樂稅 `entTax`、營業稅 `bizTax`，kind ＝ 來源代號，from ＝ 出錢的單位（家計 `u-household`、NPC 錢包 `u-wallets`，或沒有錢包時的集團），to ＝ `budget`／`museum`／`house`／`gov`。`npcBj`（餐車牌桌的牌桌那一半）還有賭場 NPC 的注（`casino_npc.js`），沒有全記，所以不記、線還是從整個已知世界出來。
3. **金流圖**：`casFlowHub` 的 `all.units` 一律用單位端點（`CAS_FLOW_GRP` 裡的來源取代同名來源整個已知世界的那條線，同壹筆錢不重複算）；端點除了 `house`、`players` 還有 `budget`、`museum`、`gov`。全景還是會合併成已知世界 → 館。標籤沒有在 `CAS_FLOW_UNIT` 的來源用 `casReportLabel`。
4. **測試**：`test/flow_wage.test.cjs`：每個來源的單位端點加起來 ＝ 這個來源在已知世界的流水（`led.world`），所以沒有漏記；金流圖有 家計→博物館資金、NPC 錢包→館、集團→NPC 錢包 的線，這些來源不再從整個已知世界出來。

## 家計要不要進往來表（建議，還沒做）
家計（`u-household`，池子的 10%，約 100 億）現在只有：（1）散客逛館付錢、（2）沒有單位的 NPC 的薪水。其他往來都沒有。建議加四種（要先用 `tools/world_trade_sim.cjs` 模擬，數字由翊文決定）：
- 家計 → 民生：日用品（最大壹筆，家計的主要消費）
- 家計 → 公共：所得稅和規費
- 家計 → 金融：保險、利息、手續費
- 集團 → 家計：薪水（各集團付，這是家計的收入；現在 NPC 薪水只算有名字的那幾位，家計沒有收入，只有成長分到的一份）
份量要名目收支平衡（現在家計只付不收，會被慢慢掏空，除非薪水收入跟日用品支出差不多）。
