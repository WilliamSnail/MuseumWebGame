## 為什麼要改

> 「有什麼辦法讓各個session不要忘記」

## 改了什麼

- 起因：維護日誌本來就有 npm run doc:new，但 AI 常常自己用 Write 手寫，標題寫錯，ship 跑完測試才擋下來。只寫進規矩，下一個 session 還是會忘。
- 新增 `.claude/settings.json`（進 repo）：Claude Code 的 PreToolUse hook，用 Write 新建 `docs/維護日誌/年份/*.md` 時擋下，告訴它改用 `npm run doc:new`。
- hook 腳本：`tools/dev/hook_log_write.cjs`。已經存在的日誌可以改；doc:new 是 node 直接寫檔，不經過 Write，不會被擋；讀不懂輸入就放行。
- `.gitignore`：`.claude/` 只收 settings.json，其他（交接、上線紀錄、launch.json）照舊不進 git。`repo_rules` 的最上層清單加 `.claude`。
- AGENTS.md 第 5 節：寫日誌一律用 doc:new。
- 這篇日誌用 doc:new 寫。

## 怎麼確認的

- test/tools/hook_log_write.test.cjs：新建要擋（Windows 和 / 兩種路徑）、已存在的不擋、別的檔和 Edit 不擋、當指令跑 exit 2／0、settings.json 有接上。
- npm test 全過。

## 還沒做、要注意

- hook 要新開的 session 才會讀到；已經在跑的 session、還沒併最新 main 的工作副本，要等下次。
- 只管 Claude Code；Antigravity 沒有這個 hook，靠 ship 跑測試前的 log:fix 和日誌檢查擋。

## 給下一個人

- 本機的 `.git/info/exclude` 有一行 `/.claude/`，所以新增 `.claude/` 底下要進 git 的檔要 `git add -f`；已經進 git 的 settings.json 之後改不受影響。
- 要再擋別的手寫（例如公告要用 npm run notice），照這支加一個 hook，測試放 test/tools/。
