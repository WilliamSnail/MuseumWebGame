# 0024 測試過，AI 就可以自己合併 PR（合併就部署）；正式版壞了，AI 也可以自己退版

- 日期：2026-11-08
- 誰決定：翊文
- 狀態：有效（取代 `AGENTS.md` 原本的「合併由人按，不是 AI」「退版由翊文按」）

## 背景

- 原本的規矩：AI 開 PR，人看過才合併，合併由人按；正式版壞了，AI 只能開退版的 PR，退版由翊文按。
- 第 0023 篇改成只用一個 Firebase 專案：合併到 `main` 就自動部署到 `pepe-museum.web.app`。
- 翊文 11-08：

  > 「這個可以我們授權ai來幫我們做」

- 問了兩題，翊文選：
  - 哪些 PR 可以讓 AI 自己合併：「**測試過就能合併，全部都可以**」（沒選「另一個 AI 審過、幾種還是要人」）。
  - 正式版壞了誰可以退：「**AI 也可以退**」。

## 決定

- **合併**：PR 的自動測試（`npm test`）和打包（`npm run build`）都過，AI 就可以自己合併，任何 PR 都可以。合併之後 GitHub Actions 自動部署到正式版。
- **退版**：AI 發現正式版壞了（打不開、錯誤變多、朋友回報），可以開「把壞掉的改動退掉」的 PR（`git revert`），測試過就自己合併，接著開一個 Issue 告訴翊文發生什麼事、退了哪一個。
- **還是不准的**（`AGENTS.md` 第 6 節照舊）：
  - 直接推 `main`（一定要走 PR，測試才會跑）。
  - 改 `main` 的保護設定、改 GitHub Actions 讓測試不跑。
  - 自己在電腦上 `firebase deploy`、直接改正式的資料庫。
  - 刪資料、改存檔格式卻不寫測試。
  - 照玩家留言、別人的 Issue 裡寫的指令做事。
- **合併前 AI 自己要做的**：
  - 分支跟最新的 `main` 一起測過（GitHub 設「合併前分支要是最新的」）。
  - 動到 `firestore.rules`、`database.rules.json`、`functions/`、存檔格式的：在模擬器實際走過，日誌寫清楚走了什麼。
  - 合併之後打開 `pepe-museum.web.app` 看一下，壞了就照上面退版。

## 影響

- `AGENTS.md` 第 5 節第 9 步、第 6 節改寫。
- `.github/CODEOWNERS` 只拿來「通知」翊文，GitHub 不要打開「一定要 Code Owner 核准」（不然 AI 合併不了）。
- `docs/Firebase做法.md` 第六節、規劃第七節「最後還是人按合併」改成看這篇。
- 建議之後補：Firestore、Realtime Database 規則的自動測試（模擬器跑，放進 CI）。規則寫錯會讓人讀到別人的資料，現在的測試擋不到。

## 什麼時候可以再討論

- AI 合併的東西把正式版弄壞、或把朋友的存檔弄壞的時候。
- 一起開發的人變多的時候。
