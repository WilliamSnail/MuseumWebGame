## 壹、工具（全部只讀，除了特別標的）

固定動作都在 `.github/workflows/firebase-task.yml`，程式在 `tools/fb/fb_task.cjs`。**AI 只有翊文在對話裡要求時才能按**；子 session 轉述的同意不算（AGENTS.md）。
按法用 **`npm run fb -- <動作>`**（tools/fb/fb_run.cjs，11-15）：自己認得新的那壹次、等跑完、只印結果。改正式資料的前後要對照時：
- 改之前 `npm run fb -- house-ledger --save w4-前`（存到 `.claude/fb-snap/`，不進 repo）

- 不按、只比兩份存的：`npm run fb -- --show w4-後 --diff w4-前`。

## 二、查法

1. **先確定是「出錯」還是「沒發生」**：看資料。例如日報沒更新 → `house-size` 看「最新日報 casinoReport/日期」。
2. **再看紀錄**：`fn-errors`。注意：程式裡 `console.error` 印的字，在 Cloud Run（Functions 第 2 代）**不會標成 ERROR**（沒結構的 stderr 是 DEFAULT），只篩 severity 會漏掉；`fn-errors` 已經同時找關鍵字。沒被 catch 的錯（`Unhandled error`）才是 ERROR。
3. **找到錯的行**：紀錄裡的 `file:///workspace/casino.js:359` 對應 `functions/casino/casino.js` 第 359 行（部署的是 functions/ 這個資料夾）。用 `git log -S"那段字" -- functions/xxx.js` 找是哪壹次改的。
4. **修好以後補測試**，讓同樣的錯在 CI 擋住；寫進 `docs/規則/踩過的坑.md`。
5. 修好上線後，再用工具確認（例如 `house-size` 看日報有沒有產生）。
