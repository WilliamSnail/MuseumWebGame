# 交代人互動：數值和存檔欄位（數值平衡出，11-21）

> 接 `交代人互動規劃.md`（決定 0151，翊文選 1A 2A 3A 4A 5B 6A 7A）。只定數字和欄位，還沒寫程式。熟識度只換文字和稱號，不給籌碼、不給靈感。

## 1. 放哪裡（重點：誰說了算）

- 玩家存檔 `P` 是瀏覽器自己存的，玩家改得動。稱號要進伺服器的錢包，所以**熟識度放伺服器的錢包 `casinoWallets/{uid}` 的 `w.npcRel`**，不放 `P`。
- 送禮要從 `P` 拿走佩佩，所以送禮、閒聊、拜託都走 `casino` 的新 act `giver`（用 `play` 的 `save` 選項，同一個交易裡改錢包和存檔，跟 `takeGift` 同壹個做法）。
- 稱號：`w.ach["npc:<id>"]`＝拿到。`casAchInfo`、`casCleanTitle` 各加壹條（id 格式 `npc:yuga|hall|postman|clerk|scale|number`，名字從 `GIVER_TITLES` 查，不存玩家端文字）。**不進 `CAS_ACH`**（它的數量會算進館友證的「基本成就 have/total」），挑稱號還是現有那壹處。

## 2. 存檔欄位

```
w.npcRel = {
  <交代人id>: {
    xp: 數字,            // 累計熟識度，只增不減
    lv: 0..3,            // 由 xp 算（GIVER_LV），存起來方便讀
    day: "YYYY-MM-DD",   // 下面 today 是哪壹天的（台灣 05:00 換日）
    today: { xp: 今天已加, tap: 今天點了幾下, chat: 今天算過熟識度的閒聊次數(≤3), visit: 0|1, gift: 0|1, ask: null | { k: 拜託的種類, at: 時間, done: 0|1 } }
  }
}
house.givers = { <id>: { recent: [ { kind, key } ]（最近收到的三隻，匿名；不寫是誰送的） } }   // 3A：他桌上顯示的
```

- 換日：`day` 不是今天就把 `today` 重設成空的（`xp`、`lv` 不動）。
- 號碼機沒有 `gift`，也不收禮；其他全部壹樣。
- 臨時拜託**不存抽籤結果**：用 `hashStr(uid + day + id)` 算，同壹天重整畫面結果壹樣。`ask` 只在玩家接下之後才寫。

## 3. 數值（`NUM.givers`，全部放 `shared/core/config.js`）

| 項目 | 數值 |
|---|---|
| 門檻（xp） | Lv1 ＝ 10、Lv2 ＝ 50、Lv3 ＝ 140 |
| 閒聊 | +1，壹天前 3 次算；點到第 4 次起不耐煩句，**壹天最多點 8 下**，之後固定「改天再聊」 |
| 來他待的地方 | +1，壹天壹次（進那個地方、不在時段也算，因為字條也是互動） |
| 做他交代的當天任務 | +4（壹天壹位只有壹個交代人，約 6 天輪到壹次） |
| 臨時拜託做完 | +3，壹天壹位最多 1 件 |
| 送禮 | 喜歡 +5、普通 +3、不太對 +1；**壹天壹位最多收 1 隻，六位合計最多 3 隻** |
| **壹位壹天的熟識度上限** | **12**（所有來源加起來）。不是給你衝的，只是防壹天送滿禮物就升級 |
| 臨時拜託出現率 | Lv0 不出現；Lv1 30%、Lv2 35%、Lv3 40%（壹位壹天），**六位合計壹天最多出 2 件**（照 `hashStr` 排序取前 2） |
| 稱號 | 熟識度到 Lv3 的那壹下發 `npc:<id>` 進 `w.ach`（只發壹次） |

### 步調（`test/sim/` 裡寫成模擬；這裡先用簡單版算過，中位數）

| 玩法 | Lv1 | Lv2 | Lv3 |
|---|---|---|---|
| 天天來、每天閒聊 3 次、拜託照接 | 3 天 | 10 天 | 26 天 |
| 天天來＋壹半的日子送禮 | 2 天 | 8 天 | 20 天 |
| 隔天來 | 4 天 | 19 天 | 50 天 |
| 只閒聊 1 次、不接拜託 | 5 天 | 19 天 | 52 天 |

延伸劇情世界的期望（3 天、1.5 週、4 週）：天天來的人剛好吻合（3／10／26）。

## 4. 送禮規則

- 能送：佩佩、失敗作（堂主對失敗作有反應）。**不能送**：修復品、抱枕、受傷的、正在地下的、擺在展台上而且只有壹隻的（照 `canGive`）。
- **另外擋**：完美作品只有壹隻時、取了名字的佩佩只有壹隻時——不退還，送出去就沒了，這兩種要先有第二隻（避免玩家手滑把最重要的送掉）。畫面送出前要有確認。
- 喜好（喜歡／不太對）在 `content/givers/<id>.json`，伺服器只認「稀有度、心情、顏色、帽子、姿勢」五類欄位；喜歡的類別要在 `GIVER_LIKES` 一份純資料，伺服器和畫面用同壹份。
- 不回籌碼、不回靈感。收到的佩佩**不進任何人的收藏**（送出去就消失，只留 `house.givers[id].recent` 的 key）。
- **接到每日任務「送佩佩」的證據（決定 0146）：送給交代人不算**（那條只認館友）。
- 號碼機：送禮鍵換成「抽號碼紙」，只當閒聊的另壹種說法，同樣算閒聊次數，不收東西。

## 5. 稱號

`GIVER_TITLES = { yuga: "牌桌的熟面孔", hall: "餐車的常客", postman: "收信人", clerk: "大夜班的幫手", scale: "秤得出的人", number: "聽得懂叫號的人" }`，id ＝ `npc:yuga` …。稱號裡不寫輸贏、不寫排名。

## 6. 伺服器動作 `casino` act `giver`

`{ op, id, ... }`：

- `info`：六位現在的樣子（lv、xp、離下壹級多少、今天還剩幾下、拜託、可不可以送、最近收到的三隻）。不動錢、不動存檔。
- `tap`：點他閒聊。回 `{ n: 今天第幾下, xp }`（句子畫面自己挑，伺服器只管算）。
- `visit`：來到他那裡（每天壹次）。
- `ask`：接下今天的臨時拜託（回 `k`）；`askDone`：伺服器看 `taskAct/{uid}` 有沒有對應的證據（接下之後做的），有才 +3。
- `gift`：`{ item: { kind, key } }`，檢查（能不能送、壹天壹隻、六位合計 3 隻）→ `takeGift(P)` → 算反應 → 加熟識度 → 記 `recent`，壹個交易。回 `{ react: "like"|"ok"|"no", xp, lv }`。
- 每壹個 op 最後呼叫 `giverLevelUp`：xp 跨門檻就更新 `lv`，到 3 就發稱號。

## 7. 要寫的測試（`test/casino/givers.test.cjs`）

- 門檻、每天上限 12、換日重設、閒聊第 4 次起不加、壹天 8 下封頂。
- 臨時拜託同壹天結果穩定、六位合計 ≤ 2、Lv0 不出。
- 送禮：壹天壹隻、六位合計 3、被擋的種類、完美／有名字只有壹隻擋住、守恆（`P` 少壹隻、錢包不動）。
- 稱號：Lv3 發壹次、`casCleanTitle` 認得 `npc:*`、亂寫的 id 被擋、`casSetTitle` 能戴。
- 熟識度**不會**動 `w.chips`、`P.insp`（資料欄位對照）。
