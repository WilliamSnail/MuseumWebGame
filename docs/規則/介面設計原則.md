# 介面設計原則

> 2026-11-20，美術統籌整理。翊文問「我們有沒有一些 Design Principle？」：以前散在翊文的回饋、`docs/` 好幾份和美術統籌的記憶裡，這份把它們放在一起，下一個 AI 看得到。
> 改任何畫面之前讀一遍；改完用最下面的「自我審查」檢查。細節在各自的文件：配色字級看 `docs/規則/介面配色.md`、整合骨架看 `docs/規劃/介面整合規劃.md`、生素材看 `docs/素材/素材生成.md`、素材放哪看 `docs/素材/素材索引.md`。

## 一、資訊

1. **一屏看完。** 電腦（約 2000×1100、1366×768）和手機直拿都盡量不用往下滑才看到全部事項。看不到全部事項，就重新安排，不要只縮間距。（翊文 11-10、11-18）
2. **分兩層。** 第一層是要做的選擇、結果、價錢、效果；第二層是說明、機率、細節，點開才看（例：餐車的「有機會抽到券」點開才看機率）。第一層最大最顯眼，第二層看得到但不搶主角。不要為了「明顯」放大到比主角還大，也不要小到看不見。
3. **不重複。** 同一件事只在一個地方畫完整；其他地方用小牌子指過去。（例：今天面板的每日任務和每週劇情用同一份任務卡零件。）
4. **文字短。** 一句一件事；說明寫在要用的地方，不寫整段。介面文字數字用「壹」，不整批取代。

## 二、版面

1. **平衡。** 每個區塊的大小要有道理，哪邊佔空間太大又沒有意義就重排。一個畫面不要左邊一顆小鈕、右邊一塊大牌：標題在上、動作在下，置中對稱；或同一排放等量的東西。（翊文 11-20 的「回書架」）
2. **空間要用在資訊上。** 不留大片沒用的空白，也不把每個角落塞滿。
3. **手機另外看。** 手機不是把電腦縮小：重新排（兩欄變一欄、按鈕換行、說明收起來點開）。直拿和橫拿都要看。
4. **能按的看得出能按。** 按鈕要像按鈕（有邊、有底色、有字）；只有小圖示 ⓘ 不夠。可以點開的區塊要有「點了會怎樣」的提示（例：下底線的虛線字、箭頭）。不能按的要變淡、說明為什麼。

## 三、顏色和字

照 `docs/規則/介面配色.md`：淺底用 `--ink` 那組字色、深底用 `--paper` 那組；字級只用四級；不好的事用酒紅加粗，不要另外發明紅色。

## 四、動態和聲音

1. 提醒用的閃爍（發光、脈動、叫你按這裡）**閃 3 下就停**，不要 infinite；氣氛動畫可以 infinite，45 秒沒操作會自己停（`web/src/core/rest.js`）。只要有一個無限循環動畫，手機就會一直重畫、發熱。
2. 動畫只演一次、短（約 0.4 秒）；領獎、買東西這類回饋要有，但不擋人。
3. 聲音要遵守靜音設定；AI 聽不到，日誌要寫「還沒人聽過」。開發時網址有 `#畫面` 會自動靜音。

## 五、素材

1. **零件拆開，不整張拉伸。** 底（可無縫拼接的材質）、邊條（橫向／直向重複接）、四角、裝飾分開生；畫面上重複排或九宮格，什麼大小都不會變形。整張的「方向圖」只當參考，不直接用在畫面上。
2. **一次生多張候選。** 每張 prompt 要求同一個東西生 3～4 種，挑最好的。不同狀態（平常、選中、不能按）用同一個形狀，只換顏色和光。
3. **光從左上來**，正面平視，沒有字（字讓程式寫），純綠底（`#00FF00`）好去背。
4. **能共用的放 `web/public/kit/`**，只有一個地方用的放自己的資料夾；放好在 `docs/素材/素材索引.md` 加一行。
5. **圖可以換檔。** 頭像、品項圖這類之後會被換掉的，用固定檔名或一份設定指到路徑；換圖不用改程式（例：`web/public/tasks/giver-<id>.webp`＋`GIVER_ART`）。圖還沒生好時，用 CSS 漸層或剪影頂著，不要等。
6. **界線：** 不畫、不收集 Pepe the Frog 的圖（決定 0005；Yuga Bot 的頭像是決定 0147 的唯一例外）；圖裡不放真人、品牌、政黨標誌；酒類不能畫品牌；風格是老博物館：深色雕花木、舊銅、酒紅、羊皮紙。

## 六、做法

1. **整體重新設計，不是只修被點名的那一處。** 翊文指出一個問題，通常代表整個畫面都要重新安排；修完後用下面的自我審查檢查其他區塊，一起修或明確列出沒修的。
2. **先做會動的，再換圖。** 版面骨架先用 CSS 做好、用假資料看；圖回來再換上去。
3. **只測兩種寬度：** 電腦 2140×1440、手機直拿 375×740；測完停開發伺服器。
4. **共用零件。** 同一種東西（任務卡、名牌、積分條）只寫一份，所有出現的地方都用它（例：`web/src/panels/ui_tasks.js`、`ui_pepename.js`）。

## 自我審查（每次改畫面都做）

1. 資訊明顯度：要做的選擇和結果是不是最顯眼？有沒有看不到的事項？
2. 空間：有沒有浪費、有沒有擠？
3. 區塊平衡：各塊大小有沒有道理、左右上下有沒有不平衡？
4. 主次層級：主要資訊最大，次要的看得到但不搶。
5. 一屏看完（電腦、手機）。
6. 能按的看得出能按？不能按的有說為什麼？
7. 電腦 2140×1440、手機 375×740 都照過圖。

回報時寫「我檢查了哪幾點、發現什麼」。
