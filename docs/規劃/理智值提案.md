# 理智值提案：有名字的 NPC、集團、散客各一種（草稿，等翊文定）

- 日期：2026-11-15
- 誰寫：數值平衡
- 狀態：**只有提案**。翊文定了才做；定案後另寫決定紀錄。第 6 節的 `statView`（公用的讀法）是例外：它先做，只放「已經有的值」（集團的健康值、狀態、預算倍率），新的理智值定案後才加進去。
- 起因：翊文「再給他們理智值」「三個都要，但計算方式不同」「這些數值要在哪裡可以看得到也想一下，寫個公用的方式，這樣以後哪邊都好呼叫」。

## 0. 先講結論

| | 有名字的 NPC | 集團 | 散客 |
| --- | --- | --- | --- |
| 叫什麼 | **理智**（0～100，高＝穩） | **集體不安**（0～100，**高＝不安**；跟健康值 h 分開） | **展廳氣氛**（0～100，高＝熱絡） |
| 算法 | **累積型**：每位自己存，事件加減、休息回復 | **慣性型**：事件推一下、每天慢慢回到平常 | **無狀態**：每天由別的值算出來，不存 |

| 劇情 | `san` 的事件由排程在 `week.json` 的 `sanEvents` 填（**劇情決定的欄位**） | 劇情事件由排程填；文化部**不放**（劇情決定） | 沒有 |

## 1. 有名字的 NPC：累積型

**範圍**：旅客（v-）和委託人（c-）共 47 位；劇情角色（t-）不放。自由業、學生、退休也有。

**存在哪**：`house.npcw.san[NPC id] ＝ 整數 0～100`，沒有紀錄的人當成初始值（預設 70，名單的 `job` 旁可選填 `sanStart`，只放明面欄位）。`tools/check/npc_check.cjs` 檢查範圍。之後 W 後的「每位一份文件」（規劃 5.2）再搬。

**每天怎麼變**（換日時算一次，`nwPayday` 同一個位置）：

| 事件 | 變化 | 資料來源（都是現有的） |
| --- | --- | --- |
| 今天去了地下收藏庫（行程有 `cellar`） | −2／次，一天最多 −4 | `npcVisitsToday` |
| 去了餐車點了餐 | +1（點的有啤酒或葡萄酒再 +1） | W 的點餐紀錄 `house.npcs.menu`（只看有名字的那位點了什麼） |
| 去了展廳／手作坊／委託櫃台 | 0 | |
| 沒來館的一天（休息） | +3 | 行程裡沒有 |
| 劇情日、突發事件、排程標的 `sanEvents` | 排程填的數字（−10～＋10） | `week.json` 新欄位，**劇情決定的欄位** |
| 所屬集團「裁員」那週被裁 | −8（一次） | W6 `npcw.ev` |
| 找到新工作 | +5（一次） | W6 |
| 自然回復 | 往 70 靠近，每天 1 點 | |

**上下限**：夾在 0～100；一天最多變 ±10（劇情事件不算進去，但加起來也夾在 0～100）。

**影響什麼**（都只放小的，不讓一位 NPC 的狀態變成賺錢門路）：
- **來館路線**：理智 < 30 的 NPC，當天行程裡的「地下收藏庫」換成別的地點（`npcTrips` 加權重 0）。只影響**去哪**，不影響人數，所以館內股的「不同的人」數不變。
- **評價語氣**：展廳留的評價，理智 < 50 時加星少一顆（`stars −1`，下限 1），文字不變。
- **預算**：理智 < 30 時預算倍率 ×0.9（乘在 W5 的倍率上，一樣有下限 0.3）。這是唯一動到錢的地方，上限已經被 `dayCap` 和 W5 的下限擋住。
- **不做**：不讓理智決定買不買畫、去不去賭場（NPC 步驟 5 才接）。

**錢的守恆**：理智本身不是錢。預算 ×0.9 只讓花的更少，不新增來源；`econ:check` 要多一項「理智倍率 ≥ 0.9、乘上 W5 後仍 ≥ 下限」。

**劇情**：名單裡**不放**劇情角色的理智；`sanEvents` 是排程的欄位，數字和理由都在 `content/story/帳本.json`，程式碼和名單不寫為什麼。

## 2. 集團：慣性型的「集體不安」

**為什麼分開**：健康值 h 是「景氣」（錢）；不安是「氣氛」（劇情、文化部、市場新聞）。兩個可以不同：景氣好但不安高（有人在傳怪事）。

**存在哪**：`house.wh.unrest[集團 id] ＝ 整數 0～100`（0＝安穩，預設 20）。**文化部不放**（劇情決定的欄位）；家計沒有。

**每天怎麼變**：

| 事件 | 變化 |
| --- | --- |
| 集團減薪／緊縮／裁員（W5 換狀態那天） | +3／+5／+8 |
| 恢復正常 | −5 |
| 世界市場新聞提到這個集團的股票，tone 是 `down` | +2（一天最多 +4） |
| 排程填的 `unrest`（劇情事件、文化部的事） | 排程填的數字（−15～＋15），**劇情決定的欄位** |
| 自然回落 | 往 20 靠近，每天 2 點（**慣性**：所以事件的影響會拖幾天，不是當天就沒） |

**上下限**：0～100。

**影響什麼**：
- 旗下 NPC 的理智**每天的自然回復**變慢（不安 > 60 時，自然回復 +1 變 0；> 80 時 −1／天）。**這是唯一的影響**，不直接動錢，也不影響人數。
- 財報「已知世界」卡多一條分級（安穩／有點躁動／不安／動盪），**不列每家**。

**錢**：不動錢；不需要新的守恆項。

**劇情**：事件由排程填；名單和程式只放數字。

## 3. 散客：無狀態的「展廳氣氛」

**為什麼不存**：散客不具名、一天一批。每天用別的值算一次就好，不用記。

**算法**（換日或第一次需要時算，只留今天和昨天兩個數字）：

```text
氣氛 ＝ 50 ＋ 20 × 景氣 b ＋ 0.3 × (今天來館的有名字 NPC 的平均理智 − 70) − 5 × 今天減薪／緊縮／裁員的集團數 ＋ 排程填的 moodEvent
夾在 0～100；週末 ＋5
```

**影響什麼**（預設都不動錢）：
- 展廳的一句氣氛文字（熱絡／平常／冷清），日報一句。
- 散客組的類型權重（氣氛高時「旅行團」「家庭」多一點；低時「獨自看展的人」多一點）。**只影響看到誰，不影響人數**。
- **選項（要翊文定）**：散客門票 ×（0.9～1.1，隨氣氛）。會動到錢：從已知世界付，仍受 `crowd.dayCap` 擋住，`econ:check` 要新增「±10% 後仍 ≤ dayCap」。

**劇情**：`moodEvent` 是排程欄位。

## 4. 三種的比較（為什麼算法不同）

| | 變的快慢 | 誰影響 | 為什麼這樣 |
| --- | --- | --- | --- |
| NPC 理智 | 每天，累積 | 這位自己的行程和遭遇 | 每位有自己的故事線，會「記得」昨天發生的事 |
| 集團不安 | 事件推一下，慢慢回落 | 集團整體的事 | 氣氛有慣性，一件事影響好幾天 |
| 散客氣氛 | 每天重算，不記 | 景氣、NPC 狀態、集團事件加總 | 散客沒有名字，不需要記憶；就是「今天館裡的感覺」 |

## 5. 在哪裡看得到

| 值 | 玩家看得到 | 只給 AI／排程 |
| --- | --- | --- |
| NPC 理智 | NPC 卡片（展廳留言旁、NPC 簡介）：**分級＋一句提示**；Discord 的 NPC 指令（若有）只給分級 | 數字、`sanEvents` 的來源 |
| 集團不安 | 財報「已知世界」卡：分布（幾個安穩、幾個躁動…），不列每家；日報一句（只有「不安」以上才寫） | 每個集團的數字 |
| 集團健康度 h、狀態、預算倍率（已經有） | 財報卡：分布；日報：換狀態那句 | 每個集團的 h、倍率（`world-status`、`world:health`） |
| 散客氣氛 | 展廳畫面一句、日報一句 | 數字 |
| 錢包（已經有） | 不給玩家看 | `world-status` |

**（翊文 11-15 改了：玩家看得到數字，分級和一句話也照給。）原本的建議是玩家不看到數字，只看分級和一句話**：避免當成可以算的指標（理智低的 NPC 一定去不了地下）；排程和 AI 要用數字時走腳本。

## 6. 公用的讀法：`statView`

**資料層**：`shared/world/stat_view.js`（新），**分級的門檻和名字只寫在這一處**（`NUM.stat` 或這個檔的常數）；畫面、日報、Discord、腳本、伺服器回傳給畫面都叫它，不各自算。

```js
statView(kind, id, data) → { value, band, label, tone, hint, pub }
```

- `kind`：`npcSan`、`unitUnrest`、`crowdMood`、`unitHealth`、`unitState`、`budgetMult`。
- `data`：那個 kind 要的資料（例如 `unitHealth` 給 `house.wh`，`npcSan` 給 `house.npcw`）。
- 回傳：
  - `value`：數字（只有 `pub` 為 false 時才給玩家以外的地方用）；
  - `band`：分級代碼（例如 `calm／tired／uneasy／edge`）；
  - `label`：中文分級名；
  - `tone`：`good／neutral／warn／bad`（畫面配色、日報語氣用）；
  - `hint`：一句提示（20 字內）；
  - `pub`：是不是可以給玩家看（false ＝ 只給腳本）。

**第一版先做的**（不等翊文，只放已經有的值）：`unitHealth`（h 分 4 級：吃緊／偏弱／普通／很好，現在 W5 的 `bands` 門檻搬進來）、`unitState`（一般／減薪／緊縮／裁員）、`budgetMult`。`world:health`、日報、財報卡的 `whCard` 改成叫它。**新的三個理智值（`npcSan`、`unitUnrest`、`crowdMood`）的分級先寫成資料表放著，定案後才接上資料**。

### 分級建議（草稿）

| kind | 分級（由低到高） | 門檻 |
| --- | --- | --- |
| `npcSan` | 崩潰邊緣／不安／有點累／穩定 | 0～19／20～39／40～59／60～100 |
| `unitUnrest`（高＝不安，所以反過來看） | 安穩／有點躁動／不安／動盪 | 0～29／30～49／50～74／75～100 |
| `crowdMood` | 冷清／平常／熱絡／沸騰 | 0～29／30～59／60～84／85～100 |
| `unitHealth` | 吃緊／偏弱／普通／很好 | ＜0.75／0.75～0.9／0.9～1.1／≥ 1.1（跟 W5 一致） |

### 畫面層（交給美術統籌）

公用元件（例如 `web/src/core/ui_stat.js` 的 `statBadge`、`statBar`）要吃的欄位就是 `statView` 的回傳：`{ band, label, tone, hint }`；`value` 只有管理者畫面才用。同一個元件用在 NPC 卡片、財報卡、展廳畫面。

## 8. 要翊文定的事

1. **要不要做這三種？** 三種都做、只做 NPC 理智（最小）、還是 NPC 加集團（不做散客）？建議**三種都做**，但分兩步：先 NPC 理智（W 後第一步），再集團不安和散客氣氛。
2. **NPC 理智低時的影響**：路線（不去地下）、評價星數、預算 ×0.9——三項都要嗎？建議三項都要，但預算 ×0.9 是唯一動錢的，翊文可以說不要。
3. **玩家看得到數字嗎？** 建議只看分級＋一句話，不看數字。（**翊文 11-15：玩家看得到數字**——statView 的 value 要給畫面。）
4. **散客門票要不要隨氣氛 ±10%？** 建議第一版**不要**（只影響看到誰），日後再說。
5. **文化部要不要有集體不安？** 建議**不放**，由劇情決定（欄位預留）。
6. **「劇情決定的欄位」誰來填**：排程在 `week.json` 填 `sanEvents`、`unrest`、`moodEvent`，還是由 Yuga 手寫在帳本？建議排程填、Yuga 審。
7. **NPC 理智的初始值**：全部 70，還是照個性（愛哭的高中生低一點、警衛高一點）？建議全部 70，個性之後再說。
8. **statView 的分級名字**：上面是草稿，Yuga 可以改（只改一處）。

## 9. 風險

- **玩家用理智推算 NPC 行程**：路線只在「理智 < 30」才變，而且玩家看不到數字，只看分級；行程本來就用祕密種子，不會洩漏館內股的人數（人數不變）。
- **NPC 理智一直掉到 0**：自然回復每天 +1、休息 +3，加上上下限；`world:sim` 90 天要看分布，不能全部卡在 0 或 100。
- **劇情不能破梗**：事件的理由只在帳本；名單、程式、日報只放明面的字（「某某看起來有點累」這種）。
