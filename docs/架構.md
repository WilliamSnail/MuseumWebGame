## 1. 這是什麼遊戲

- **主旨是「客製化自己的佩佩」**。核心是「各種可能性的各種可能性組合的可能性」：選項彼此組合出來的可能性空間。畫廊、起源只是包裝。
- 玩家是博物館的「參觀者」，規則借用 CoC（克蘇魯的呼喚）第 7 版：
  - d100 擲出 ≤ 數值就成功。
  - 理智檢定寫成「成功掉多少/失敗掉多少」，例如 `1/1D6`。
  - 一次掉 5 點以上會暫時瘋狂（要先過「看懂檢定」），一天掉超過五分之一會有長期怪癖。
  - 佩佩神話點數會壓低理智上限（99 − 神話）。
  - 心情就是 CoC 的幸運值，可以花掉把骰子壓低。
- 理智歸零就進「俄國8+9 的房間」，換下一位參觀者。翊文要求這件事要「算容易出現」。
- **一天＝台灣時間 05:00 到隔天 05:00，週一 05:00 換週**（`docs/決定/0019-一天台灣時間05點換日.md`，11-09 做了；以前是「玩 15 分鐘一天」，決定 0003 被取代）。大家的一天都一樣。委託、每天的次數、心情恢復、技能成長、受傷、每週特展、每週公告都照這個走。狀態列最左邊寫「第 001 天」（從第一次進館那天算）和「還有 N 小時換日」。怪癖不照天數：做完一件事就好，不然 20 分鐘（真的時鐘）後自己消失（`docs/決定/0027-怪癖做完一件事或二十分鐘消失.md`）。狀態列最左邊寫「第 001 天」和幾分鐘後換天。
- 兩種模式：
  - **挑戰模式**：要解鎖、會擲骰、會瘋。
  - **自由模式**：全部選項打開，只管捏佩佩。
- 第 3 版在進階版上面加了 4 個系統：J 融合室、K 工坊升級、L 職業與技能、M 地下收藏庫。另外還有老主顧故事線、每週特展、交換碼、修復台、會動的珍品、整套音效。
- 第 4 版之後要加的多人玩法（交誼廳、參觀展廳、送佩佩、一起融合、合作地下收藏庫、比賽）在 `規劃.md` 第二、三節。

## 3. 怎麼跑、測試、在瀏覽器看

需要 **Node.js 22.13 以上**：伺服器用 `node:sqlite`（Node 22.13 才有）；只跑網頁的話 20.19 就可以（Vite 8 要的）。都在專案資料夾裡執行。

```bash
npm install            # 第一次，或 package.json 改了之後
npm run dev            # 開發用：http://localhost:5173（port 固定，被占用就不會開）
npm test               # 規則測試、兩支內容檢查、fx 檢查、ES 模組檢查、維護日誌的格式（test/run_all.cjs；不含模擬）
npm run build          # 打包到 dist/
npm run preview        # 看打包後的樣子
npm run version:bump   # 換版本號（version.json）
npm run log:index      # 重新產生 維護日誌/README.md（總表）
```

單獨跑某一支：

```bash
node test/logic.test.cjs               # 每一項都要過
node test/content/check.cjs            # 預設檢查 shared/content.js
node test/content/check3.cjs           # 預設檢查 shared/ 的 content3.js
node test/fx/node-check.cjs
node test/esm_smoke.mjs
node test/sim.cjs 1000                 # 節奏：每天玩 20 分鐘（預設，設計基準）：10 分鐘解鎖 4 個；全部解鎖中位數 1.0 小時（約 3–4 天）
DAY_MIN=60 node test/sim.cjs 1000      # 每天玩 60 分鐘：全部解鎖 2.2 小時；DAY_MIN=15 是以前「15 分鐘一天」的算法（0.8 小時）
node test/sim_san.cjs 1000             # 理智：每天玩 20 分鐘（預設），好奇的玩家第一次歸零中位數 0.7 小時（1 小時內 96%）；DAY_MIN=60 時 1.3 小時（10%）
node test/sim_cellar.cjs 100           # 地下收藏庫的難度表（約 3 分鐘）
```

- PowerShell 裡設 `DAY_MIN` 要寫成 `$env:DAY_MIN=45; node test/sim.cjs 1000`。

**在瀏覽器裡看**：

- `npm run dev`，打開 `http://localhost:5173/#lobby`。`#` 後面接畫面名稱，就直接開那個畫面，並放好 150 隻假收藏（`web/src/debug_boot.js`）。
- 可以用的寫法：`#title`、`#titlehover`、`#reveal`、`#roll`、`#focus::strange`（看某件展品）、`#ending:russia8`、`#book`、`#cellarrun`（直接在 B1）、`#fusion2`（融合台放好兩隻）、`#jobpick`、`#office:upgrades`（`畫面:頁籤`），以及 `#gallery:lowsan`、`#lobby:bout`、`#workshop:quirk`（放兩個怪癖：整類帽子恐懼症、綠色狂）這類（改理智、狀態）。`#signin`、`#calendar` 直接打開簽到卡、簽到日曆（11-09）；要看節日，在主控台 `import` `shared/logic.js` 再 `setNowClock(() => Date.parse("2026-09-25T10:00:00+08:00"))`（網址用 `performance.getEntriesByType("resource")` 找）。開發用的 `#畫面` 不會自己跳簽到卡。
- **網址加 `#畫面` 會清掉這個瀏覽器在 `localhost:5173` 的存檔**（`pepeMuseum3`）。不要拿玩家正在玩的瀏覽器測。
- `debug_boot.js` 只在 `npm run dev`、網址有 `#` 時才載入，不會進 `dist/`。
- 要看的寬度：電腦約 1366、平板約 800、手機 375。手機版很多排版是另外寫的。

**聲音（AI 聽不到，用量的）**：

- 第 4 版的 `FX` 不是全域變數了。`npm run dev` 時，在瀏覽器的開發者主控台先把它拿出來（寫這份時還沒實際試過這個寫法）：

  ```js
  const { FX } = await import("/src/fx.js");
  await FX.sound.analyze("bell");                  // { peak, rms }，一次性的聲音
  await FX.sound.analyze("gallery", null, 6, true); // 會一直響的環境音（第 4 個參數 true）
  ```

- 大小的參考：鐘聲（bell）rms ≈ 0.020、peak ≈ 0.18，這是翊文實際聽過、覺得可以的。會一直響的環境音要比它小，現在大約 rms 0.005–0.018（有旋律的房間音樂 0.013–0.018，只有聲響的房間比較小）。peak 不可以接近 1。
- `analyze` 回傳 `{ peak, rms, rmsHi, centroid, bands }`：`rmsHi` 是 150 Hz 以上的大小（筆電喇叭聽得到的部分），`centroid` 是平均頻率（越高越尖），`bands` 是 <500、500–2k、2k–5k、>5k 四段的能量比例。

## 4. 架構

### 4.1 模組結構（第 4 版）

**載入順序**（`web/src/main.js`）：

```
CSS：ui.css → fx.css → theme.css → theme3.css → board.css → net.css → visitors.css → signin.css（後面的蓋前面的，跟第 3 版一樣；board.css 是 11-08 加的公佈欄、信箱、選單；signin.css 是 11-09 的簽到、日曆、節日外觀）
JS ：art.js → fx.js → ui_core.js → ui_screens1.js → ui_screens2.js → ui_screens3.js → ui_curio.js → ui_odd.js → ui_board.js → ui_login.js → ui_signin.js
     → 最後 import("./boot.js")（動態 import）開館
     → npm run dev 而且網址有 #畫面：再 import("./debug_boot.js")
```

- 每個畫面檔一載入，就把自己的房間登記進 `SCREENS`（例如 `SCREENS.lobby = root => {…}`，`SCREENS` 在 `ui_core.js`）。所以畫面檔全部先載入。
- `boot.js` 一載入就開館（`boot()`），所以放在最後，而且用動態 import，確定前面都準備好了。
- `shared/` 的檔由畫面檔 import 進來，不用寫在 `main.js`。
- 新的畫面檔要在 `main.js` 裡 import，放在 `boot.js` 前面。

**誰 import 誰**：

```
shared/config.js、content.js、content3.js    不 import 任何檔
shared/logic.js ⇄ logic3.js                  互相 import（都在函式裡用到對方）
web/src/art.js、fx.js                        不 import 任何檔
web/src/ui_core.js       ← shared/、art、fx   （不 import 比它後面的檔）
web/src/ui_screens1/2/3、ui_curio、ui_odd ← ui_core、shared/、art、fx，彼此也會互相 import
web/src/boot.js          ← ui_core、ui_screens1、ui_screens2、shared/、art、fx
web/src/debug_boot.js    ← ui_core、ui_screens1、ui_screens3、shared/
```

**檔頭的 import**：

- 每個檔頂層的宣告都 export（`export function`、`export const`）。
- 檔頭那一段「第 4 版：從別的檔拿的」是從第 3 版轉成模組時自動產生的。之後用到別的檔的新名字，手動加進去。
- 忘了 import：模組是嚴格模式，不會變成全域變數。跑到那一行才壞（`ReferenceError: … is not defined`），所以要在瀏覽器實際走過改到的畫面。
- import 了對方沒有 export 的名字：整個遊戲打不開，瀏覽器主控台會寫 `does not provide an export named …`。

**`ui_core.js` 不 import 比它後面的檔**：

- 為什麼：畫面檔一載入就執行 `SCREENS.lobby = …`。如果 `ui_core.js` import 了 `ui_screens1.js`，就變成循環引用，瀏覽器會先跑 `ui_screens1.js`。這時 `ui_core.js` 還沒跑完、`SCREENS` 還沒建好，就會出現 `Cannot access 'SCREENS' before initialization`，整個遊戲打不開。
- 所以 `ui_core.js` 只 import `shared/`、`art.js`、`fx.js`。
- 轉換時從後面搬進 `ui_core.js` 的：`dayMins`（原本在 `boot.js`；11-09 起永遠回 0）、`miniLayer`（原本在 `ui_screens2.js`）。
- 之後 `ui_core.js` 需要後面某個檔的東西：把它搬進 `ui_core.js`，或讓後面的檔把東西登記進 `ui_core.js` 的表（像 `SCREENS` 那樣）。

**畫面檔之間**：

- `ui_screens1/2/3`、`ui_curio` 彼此 import，是循環引用。
- 所以檔案最外層（載入時就執行、不在函式裡）的程式，只用 `ui_core`、`shared/`、`art`、`fx` 的東西。別的畫面檔的名字放在函式裡、用到時才讀就沒問題。

**共用狀態用 setter**：

- `SAVE`（整份存檔）、`P`（現在的參觀者）、`IMG`（圖庫的圖）、`FIT`（自己的圖怎麼對位）宣告在 `ui_core.js`：`export let SAVE = null, P = null, IMG = {}, FIT = {…}`。
- 為什麼：ES 模組 import 進來的名字是唯讀的，別的檔寫 `SAVE = x` 會出錯（`TypeError: Assignment to constant variable`）。第 3 版共用同一個全域範圍才能直接賦值。
- 所以要整個換掉時，用 `setSave(x)`、`setP(x)`、`setImg(x)`、`setFit(x)`。
- 改裡面的欄位可以直接改（`P.insp += 2`、`SAVE.settings.muted = true`），因為沒有換掉整個物件。
- 讀的時候直接用 `P`、`SAVE`：import 進來的名字會跟著變，`setP()` 之後別的檔讀到的就是新的。

**測試怎麼載入 `shared/`**：

- `test/load_shared.cjs`：把 `shared/` 的五個檔（config → content → content3 → logic → logic3）拿掉 import 那一行、拿掉行首的 `export`，照順序接成一段，放進 Node 的 `vm` 跑。每一項測試都 `load()` 一份全新的（跟第 3 版的測試一樣）。所以：
  - `shared/` 的 import 要寫成**一行**（它一行一行拿掉）。
  - `export` 寫在宣告前面，**一個 export 只宣告一個名字**（`export const A = 1, B = 2` 只認得 A）。不要用 `export { … }`、`export default`。
  - 五個檔接成一段，**頂層的名字不能重複**，重複的話測試整個跑不起來。
- `test/esm_smoke.mjs`：用真正的 ES 模組 import `shared/`，確定 import／export 接得上、logic 和 logic3 互相叫得到。伺服器之後就是這樣用。
- `test/content/check.cjs`、`check3.cjs`：拿掉 `export` 再檢查。內容檔不准 import，只准 `export const`。`check3.cjs` 把 config、content、content3 放在同一個 `vm` 裡，名字撞到也會失敗。
- `test/fx/node-check.cjs`：拿掉 `export`，確定 `fx.js` 在 Node 裡載得起來（載入時不碰 DOM）、API 都在。
- 第 3 版 `boot.js` 最後的 `module.exports` 拿掉了，測試不讀畫面的程式。
- 轉換時用同樣的種子跑過，模擬結果跟第 3 版一字不差。

**版本號**：

- `version.json` → `vite.config.js` 用 `define` 帶成 `__APP_VERSION__` → 設定頁的「版本」（`ui_screens2.js`）。
- 格式是 `日期-當天第幾次`，例如 `2026.11.08-1`（規劃.md 第五節「版本號」）。用 `npm run version:bump` 換。

**跟第 3 版不一樣的地方**：

- 不再共用同一個全域範圍：每個檔用 import／export 說清楚要什麼、給什麼。但 `shared/` 五個檔的頂層名字還是不能重複（上面的測試）。
- `ART`、`FX` 還是包在自己的 IIFE 裡，用 `export const ART = (() => {…})()` 給出去；裡面的小工具不是 export 的。
- 沒有 `build.js`、`serve.js`；第 3 版「script 裡不能出現 `</script`」的限制沒了。
- CSS 搬到 `web/src/css/`。
- `boot.js` 不再 `module.exports`。
- 開場大標題、分頁標題是「佩佩博物館 4」（`docs/決定/0015-名字佩佩博物館4.md`）。

### 4.6 聲音引擎（`web/src/fx.js` 的 `FX.sound`）

- **全部即時合成**（Web Audio），沒有音效檔。音樂、節奏都是 Claude 自己寫的，不放現成的歌（`docs/決定/0008-音樂原創.md`）。
- 三條音軌接到總音量，再經過低通和壓縮器：
  - `sfx`：效果音。
  - `amb`：環境音。
  - `heart`：心跳與低鳴。
  - 音量在設定頁調，存在 `SAVE.settings.vol`，預設都是 100。
- 一次性的聲音寫在 `R` 物件裡，`snd(名字, 參數)` 播放：
  - 舊的：click、flip、unlock、submit、stamp、bell、dice、hug、error、whoosh、coin、heartbeat。
  - 理智：sanPre、sanOk、sanBad、sanDrop（參數是扣幾點）、sanUp、lightsOut。
  - 心情：moodUp、moodDown。
  - 揭曉：revCommon、revRare、revSuper、revLegend、revFailed、crit01、fumble100。
  - 地下收藏庫：drum、hurt、block、fanfare。
  - 融合：fuse、mutate。
  - 換房間：steps。
  - 看到奇怪的東西：eerie（5 種，參數 0–4，不給就隨機）。
  - 珍品：whisper、eyeOpen、squelch、hic、choir、shimmer、sparkle、puff、tip、hey、whoop、twinkle、snow、crack、gopnik。
- 會一直響的聲音由狀態決定，不要自己去開關：
  - `ui_core.js` 的 `audioState()` 在每次 `go()` 和 `updateStatus()` 時呼叫：
    - `FX.sound.ambient(房間)`：每個房間各有一段，對應寫在 `ui_core.js` 的 `AMB_OF`。
      - 大廳 `lobby`：優雅、慢慢走的門廳音樂（D 大調 D→G→Em→A｜D→F#m→G→A，豎琴分解和弦＋長笛般的旋律＋很輕的弦樂墊底，一圈約 19 秒，沒有鼓，因為大廳待最久），遠處的人聲、腳步改小留著（11-08 翊文：「大廳也可以有音樂嗎」；Claude 自己寫的）。
      - 手作坊 `workshop`：輕快的木琴旋律＋撥弦低音＋反拍小和弦，F 大調 F→Dm→B♭→C，旋律 A、B 兩段輪流，偶爾剪刀喀擦（11-08 翊文說原本的剪刀、鉛筆聲聽不太到，換成真的音樂；Claude 自己寫的）。
      - 抱枕 `pillow`：軟綿綿的搖籃曲小圓舞曲（3/4 拍，G 大調 G→Em→C→D，鋼片琴旋律＋「嗯—啪—啪」伴奏，A、B 兩段輪流，一圈 12 秒），布料聲、縫紉機留著當點綴（11-08 翊文：「抱枕區音樂也要」；Claude 自己寫的）。
      - 委託 `commission`：翻紙、蓋章、櫃台鈴。
      - 圖鑑 `codex`：時鐘、翻頁。
      - 起源室 `origin`：古老、神秘的慢歌（D 小調 Dm→C→B♭→A，風琴般的和弦＋豎琴般的旋律、長回音，一圈約 26 秒），老時鐘跟著拍子滴答，木頭嘎吱、翻頁留著（11-08 翊文：「還有他的音樂呢」；Claude 自己寫的）。
      - 展廳 `hall`：明亮的弦樂、人聲。
      - 圖庫 `library`：音樂盒。
      - 館長室 `office`：落地鐘、羽毛筆、壁爐。
      - 畫廊 `gallery`：弦樂和聲、遠處的腳步。
      - 融合室 `fusion`：神秘的低鳴、玻璃音。
      - 地下 `cellar`：風、滴水。
      - 開場 `title`：音樂盒旋律。
      - 設定：`room`。
      - 理智歸零時是 `zero`。
    - `FX.sound.heart(理智)`：30 以下才跳，越低越快。
    - `FX.sound.tinnitus(是否發作)`：發作時的聲音。名字沿用 tinnitus，11-08 起是深沉、神秘的低鳴，不是高頻耳鳴：D2＋A2 鋸齒波，共鳴在 250–950 Hz 慢慢張合，加上氣息。
    - **低音要讓泛音落在 150 Hz 以上**：筆電喇叭、一般耳機放不出 100 Hz 以下。11-08 第一版低鳴只有 37–57 Hz，翊文說聽不到。`FX.sound.analyze` 會回傳 `rmsHi`（150 Hz 以上的大小），調低音時看這個。
    - `FX.sound.unease(0–1)`：理智 40 以下開始有低鳴。
  - `audioTrack()` 比對上一次的數字：理智變高響 sanUp，心情變化響 moodUp/moodDown。
- 瀏覽器規定玩家先點一下才能出聲，所以點之前只記下「想要的狀態」（`unlocked` 旗標），點了才真的開始。
  - 標題畫面的第一下多半是登入或「繼續參觀」（第 3 版是「進館」），一按就離開，標題音樂幾乎沒機會響。所以右下角有一顆「♪ 點壹下開啟音樂」（`titleMusicBtn`），點畫面任何地方也會開。
  - **開聲音要很多種動作都試**（11-08 翊文：開場的音樂和聲音不一定聽得到）：
    - 手機上觸控「按下去」（pointerdown、touchstart）瀏覽器不算使用者動作，「放開」（touchend）和 click 才算。所以 pointerdown、mousedown、touchend、click、keydown 都會試著開。
    - 每一次都檢查：聲音沒在播（瀏覽器暫停了、手機切出去又回來）就 `resume()`，切分頁回來也補開一次。
    - 開場音樂 0.3 秒就淡入完，第一個音 0.05 秒就出來（其他房間還是 1.5 秒淡入）。
    - **開館布幕**（`boot.js` 的 `museumDoor`，翊文 11-08：「音樂一開始要自動撥放」）：開檔先 `FX.sound.tryAutoplay()`（最多等 0.45 秒）。瀏覽器放行就直接響，布幕自己拉開；不放行就停在酒紅絨布幕「點壹下　推開館門」，點一下或按任何鍵，布幕往兩邊拉開、開場音樂和標題動畫一起開始。這樣第一下就不會被「進館」用掉。靜音的人不放布幕；開發時網址有 `#畫面` 會設 `window.__PM_NODOOR__` 跳過布幕。
    - 網頁沒辦法強迫瀏覽器在玩家點之前出聲，這是瀏覽器的規定。Chrome、Edge 常玩的網站會自己放行（Claude 的瀏覽器測試時是放行的）。
    - `FX.sound.state()` 的 `running` 才是「聲音真的在播」；`unlocked` 只代表玩家點過。標題右下角的按鈕看 `running` 和 `amb === "title"`，每 0.7 秒更新一次。
- **低語 `whisper`**（11-08 照翊文的意見改了十幾次，下面先寫現在的做法，再寫踩過的坑）：
  - **現在的做法**：
    - 一句話＝`makePlan(開始, 快慢, 音節數…)` 排好音節，再用 `speak(t0, 共鳴, 音高, 人聲比例, 音量, 去哪, 計畫, bright, 調子)` 唸出來。
    - 聲源是「氣聲（低通 3.8 kHz）＋一點點人聲（鋸齒波，女聲約 210 Hz、另一側 180 Hz，句尾往下掉）」。經過三個女聲的嘴型共鳴（帶通 Q 4、7、9，比男聲高約兩成），母音之間用 `setTargetAtTime` 滑過去，整體再低通 4.2 kHz。
    - 人聲只有一點點：比例 0.035（背後那個）、0.05（另一側）。
    - 開口前吸一口氣、講完吐一口氣；每個音節的氣音 0.26–0.42 秒、慢慢出氣（時間常數 0.07 秒），每句 4–6 或 2–4 個音節。
    - 位置在背後：`PannerNode` 的 HRTF，放在左後方或右後方（z > 0 是背後），說話時慢慢繞到正後方，戴耳機最明顯。另一個更低沉、慢半拍、更小聲的聲音在另一側後方跟著說，底下一層極輕的低音。
  - **理智越低，聲音越多**：理智 50 以上 2 個，40–49 是 3 個，30–39 是 4，20–29 是 5，10–19 是 6，1–9 是 7，0 是 8。
    - 多出來的聲音寫在 `MORE` 表，照順序加進來。每個都是「另一個人」：說自己的話（自己的 `makePlan`、自己的快慢），一個接一個進來（間隔 0.35–1.3 秒），進來前先吸一口氣，氣聲亮暗不同（`bright`）。
    - 第 1 個（理智 50 以下就有）是哼歌的女聲：很近、就在腦後，邊說邊用 `hum()` 哼一段小調搖籃曲（Claude 自己寫的）。哼法是閉嘴的「嗯——」：三角波＋高八度、5.2 Hz 顫音、每個音 0.55 秒滑過去，音量峰值 0.021。
    - 接著依序是：沙啞低沉的男聲貼左耳、細細的高音貼右耳說得快、很低的喃喃在遠遠的正後方說得慢、說得很急的中性聲音、像小孩的聲音。
    - 幾個聲音由 `ui_core.js` 的 `whisperLayers()` 算，`audioState()` 每次呼叫 `FX.sound.setWhisperLayers`。`R.whisper(t, 幾個)` 可以直接指定，設定頁的試聽有理智 60、25、5 三種。所有會播低語的地方（珍品、怪事、起源室、奇怪的聲音）都自動照當下的理智。
  - **量出來的數字**（離線 6 秒）：
    - rms：2 個約 0.013，3 個（有哼歌）0.016–0.020，8 個約 0.021。鈴聲是 0.020，所以疊越多是方向越多，不是越大聲。
    - 平均頻率（`centroid`）約 890–1010 Hz，5 kHz 以上 0%。
  - **踩過的坑**（括號是翊文的話）：
    - 窄共鳴（Q 10–14）＋5 kHz 的嘶聲聽起來像高高的口哨（「還是高音的音效」）。那時平均頻率約 1300–1600 Hz、5 kHz 以上約 10%。
    - 人聲比例 0.16 像吼叫（「變得有點像吼叫」）。
    - 音節 0.11–0.2 秒太短（「每壹段的氣音還是太短了」）。
    - 多出來的聲音說一樣的話、只晚 0.05–0.33 秒，會黏成一個聲音（「聽起來還是壹種聲音」）。
    - 只把共鳴調高一點、或在低語裡帶音高，女聲聽不出來（「另壹個女聲聽不出來」「還是聽不太到」），要真的哼歌。但哼歌音量 0.05 時整個低語大了一倍（rms 0.013 → 0.031），蓋過其他聲音，所以降到 0.021。
- **加新聲音**：
  1. 在 `R` 裡加一個函式，用 `tone`/`tonef`/`noise`/`warble`。
  2. 用 `FX.sound.analyze` 量大小，跟 bell 比（第 3 節）。
  3. 在設定頁的 `SOUND_DEMOS` 加一個試聽按鈕。
  4. 在對的地方呼叫 `snd()`。
- **加新環境音**：在 `AMB` 加一個 `(c, g) => ({ nodes, timers })`，再在 `AMB_OF` 對應畫面。
- 節奏的部分（gopnik、zero 的低音鼓）是 Claude 自己寫的，沒有抄任何現成的歌，以後也不要放現成的歌。

## 6. 改的時候會踩到的坑

**Firebase（決定 0021，11-08）**：

- **不要在原始碼裡寫反斜線 u 加 2028、2029 那種跳脫**（換行用的特殊字元）。11-08 用 AI 的工具寫檔時，連註解裡的都被換成真的換行字元，`functions/index.js` 整個載不起來。看不見的字一律用字碼判斷（`codePointAt`），寫法看 `functions/index.js` 的 `invisible()`。
- **模擬器的 Realtime Database 名字是 `demo-pepe4`**：`web/src/firebase_config.js` 的 `databaseURL` 寫成 `…-default-rtdb` 的話，畫面和 Functions 會寫到兩個不同的資料庫，在線名單會說沒有權限。
- **連接埠**：翊文的電腦 8080、9000、4000 被別的程式用了，`firebase.json` 改用 Firestore 8180、Database 9100、管理畫面 4400。
- **規則**：Realtime Database 的規則讀不到 Firestore，所以「是不是館友」兩邊都要記（Functions 的 `join` 兩邊一起寫）。
- **畫面用 `web/src/net_firebase.js` 的 `NET`**；`web/src/net.js` 是舊的 Node 伺服器版，只剩 `test/server.test.mjs` 在用。

**第 4 版的模組**（4.1 節有完整的原因）：

- **`ui_core.js` 不准 import 比它後面的檔**（ui_screens1/2/3、ui_curio、ui_odd、ui_board、boot、debug_boot），不然 `SCREENS` 還沒建好，整個遊戲打不開。
- **別的檔不能直接賦值 `SAVE`、`P`、`IMG`、`FIT`**，要用 `setSave()`、`setP()`、`setImg()`、`setFit()`。改裡面的欄位可以直接改。
- **新的頂層名字要 export；用到別的檔的名字，要在檔頭 import**。忘了 import 不一定在打包時被擋，要在瀏覽器實際走過。
- **`shared/` 的 import 寫成一行、一個 export 只宣告一個名字、五個檔的頂層名字不能重複**（`test/load_shared.cjs` 靠這些）。
- 畫面檔之間互相 import：檔案最外層的程式，不要用別的畫面檔的東西。
- `vite.config.js` 的 root 是 `web/`，`shared/` 在外面，所以 `server.fs.allow` 要包含整個專案資料夾。不要拿掉。
- `import.meta.env.DEV` 只有 `npm run dev` 是 true。開發用的程式（`debug_boot.js`）要用它擋住，不要進 `dist/`。

**從第 3 版帶過來的**：

- **不要用 `String.prototype.replace(字串, 字串)` 改程式碼**：取代字串裡的 `$$` 會變成 `$`，曾經把 `$$(".insp-have")` 改成 `$(...)` 讓遊戲一打開就壞。改程式請用 `split(a).join(b)`，或直接用編輯工具。
- **不要整批取代文字**（例如「一」→「壹」）：會改到第 1 代的原文和有檢查比對的委託文字（`docs/決定/0001-用壹不用一.md`）。
- `h()` 和 `append`/`replaceChildren` 已經墊過，`null`、`false` 會被略過，不會印出 "null"。`h()` 的 `style` 物件可以寫 CSS 變數（`{ "--i": 2 }`），會用 `setProperty` 設；以前不行的時候，地下收藏庫的三隻隊員因此疊在一起。
- 提示 `note()` 一律至少 6.5 秒（字多留更久），畫面上最多同時 5 則。不要再把它調短，翊文說過兩次「至少 6 秒」（`docs/決定/0002-提示至少6秒半.md`）。

- 有 `transform` 的父元素會困住 `position: fixed` 的子元素。所以畫面進場動畫結束就拿掉 `.enter`，看展的圖層掛在 `#room` 上。
- SVG 元素沒有 `offsetWidth`，要重播動畫時用 `getBoundingClientRect()` 逼它重算（見 `ui_curio.js` 的 `replay()`）。
- 瀏覽器要玩家先點一下才准出聲；自動化測試要先送一次點擊。
- **存檔跟網址綁在一起**：`localhost:5173`、`npm run preview` 的 port、用檔案打開的第 3 版，各是各的存檔。`vite.config.js` 把 port 固定在 5173（`strictPort`），不要改，不然開發時的存檔會不見。
- `debug_boot.js` 會清存檔，只能在開發時載入。
- 原本的美術是用零件組起來的，第 3 版之後直接改 `art.js`。舊的零件和組裝程式沒有帶過來，**不要再從零件重組 art.js**，會蓋掉後來的修改。
- 改了選項名字，要同步改 `RENAMED`、`content.js` 的委託條件、`test/content/check.cjs` 的 `PEPE` 清單，還有測試。
- 手機版要另外看，很多 grid 要用 `minmax(0, 1fr)`，不然會被撐爆。
- `body.reduce-motion` 是「動畫減量」設定，新動畫要尊重它。
- 設定頁的「怎麼玩」（`ui_screens2.js` 的 `howToPlay`）**不要破梗**：理智 0 會發生什麼、隱藏展品、禁書續集、結局，都不要寫出來（`docs/決定/0007-說明不破梗.md`）。
- 兩支內容檢查有白名單：`check.cjs` 只准 `{x}`、`{圖鑑格數}` 這兩種大括號；`check3.cjs` 的 `NAMES` 列出 `content3.js` 可以有的頂層名字。加新的要一起加。
- **「今天」一律用 `todayStr()`，不要自己 `new Date()`**：一天是台灣時間 05:00 換日（決定 0019），`todayStr()` 不帶參數＝現在是台灣的哪一天（照 `nowMs()`；`setDayClock` 可以蓋掉）。新的「每天」規則（次數、恢復、連續幾天）只要用它就會自動跟著走。
- **「現在」一律用 `nowMs()`，不要直接 `Date.now()`**（決定 0026，翊文 11-09：「遊戲裡的內容也是跟著那網路抓取的真實時間時間」）：登入連上之後，`net_firebase.js` 讀 Firebase 的 `.info/serverTimeOffset`，用 `setNowClock` 換成網路的時間；還沒連上之前照電腦的時間。畫面上量「過了多久」的（`setTimeout`、多久沒動、動畫）照舊用 `Date.now()`，不要兩種混著減。
  - 規則和測試不碰真的時鐘：要算哪一天就傳時間進去（`todayStr(毫秒)`、`taipeiDay(毫秒)`、`secToNextDay(毫秒)`），或直接把日期字串傳給 `ensureDay`、`dailyCommissions` 這些。測試裡的台灣時間可以寫 `Date.parse("2026-11-09T05:00:00+08:00")`。
  - 測試用 `G.setNowClock(() => 毫秒)` 換時鐘，用完 `G.setNowClock(null)`；模擬（`sim*.cjs`）設成照模擬的秒數走，怪癖 20 分鐘才會消失（決定 0027）。
  - 伺服器、Functions 用 `taipeiDay(Date.now())`（伺服器的時間；在那裡 `nowMs()` 也是一樣的），不要靠 `setDayClock`。
  - 日期字串要加減天數用 `addDays`（UTC 算，不受時區影響）；不要 `new Date(y, m, d)` 再轉回字串，那會照電腦的時區。
- 日期往回走（改電腦時間、11-09 以前 15 分鐘一天的舊存檔）：`ensureDay` 叫 `rewindDays` 處理，受傷剩幾天照樣、今天的委託重抽。存日期的新欄位如果會拿來比先後，要一起加進 `rewindDays`。
- 開發時在主控台 `import("/src/ui_core.js")` 拿 `P`：改過 `ui_core.js` 之後網址會變成 `/src/ui_core.js?t=數字`，要用 `performance.getEntriesByType("resource")` 找到真正的網址，不然 import 到的是另一份（`SCREENS` 是空的）。
- **深色牆上和羊皮紙上的字顏色相反**：`--ink`/`--sub` 在牆上是淺色、在羊皮紙裡是深色。不要用「跟在哪個元素後面」（例如 `.placard + .x`）來猜它在哪一種底上，11-08 融合室的上限提示就是這樣變成深棕字配暗紅底。要依「包在哪個框裡」（例如 `.mini-card .day-limit`）。
- 測試用 `vm` 跑規則（`load_shared.cjs`），裡面做出來的陣列、物件跟測試檔不是同一個「世界」的，`assert.deepStrictEqual` 會說不一樣。比內容時用 `JSON.stringify` 兩邊再比。
- `ART`、`FX` 裡面的小工具沒有 export：例如 `focusNoScroll` 包在 `fx.js` 的 IIFE 裡，畫面檔要寫 `el.focus({ preventScroll: true })`。借用別的檔的函式之前，先確認它有 export。
- 低語、環境音加新的層之前先量整體 rms：多一層哼歌（0.05）就讓整個低語大了一倍。
- `FX.sound.analyze(房間, null, 秒, true)` 只畫得到「第一下」：會一直隨機出現的聲音（例如圖庫的音樂盒），第一個音又剛好落在 1.5 秒的淡入裡，量出來會接近 0。這是量法的限制，要看單一個音的大小。
