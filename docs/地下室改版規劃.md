## 一、現在的地下室哪裡不夠好玩

- 5 層、每層 4 間，照固定順序走，沒有路可以選（`shared/content3.js` 的 `CELLAR`）。
- 每間是三個選項挑一個、擲一次骰，結果馬上出來（`cellarResolve`、`cellarApply`）。
- 隊伍的佩佩只是一個「強度」數字，沒有各自出手的感覺。
- 沒有敵人。房間只有「心情」「顏色」當相剋的對象。
- 走過的房間再走只給 1 靈感。走完 B5 就沒有理由再下去。
- 單人和合作是兩套流程：單人在瀏覽器跑 `logic3.js`，合作在伺服器跑 `coop_flow.js`。新東西要寫兩次。

## 二、最重要的一條：預設都能合作

翊文 11-12：「預設都要能合作」。

- **每一種點、每一個機制，設計的時候就是 1～4 個人的版本。** 一個人下去＝一個人的隊伍，不是另一套玩法。
- 規則只寫一份（`shared/`，純函式），吃「一隊人」。不再有「單人版的規則」和「合作版的規則」。
- 沿用現在的隊伍：一隊 1～4 人、每人帶 1～2 隻、不滿 3 隻由館方助手補（`COOP`、`PARTY`，決定 0020、0036）。
- 獎勵每個人各拿一份，不互搶（決定 0020）。
- 合作現有的九個機制都留著，接法在第七節。
- 人多的好處是「分工」，不是單純比較強：怪物的壓力照人數放大（沿用 `COOP` 放大門檻的算法）。

## 三、每層變成一張小地圖

- **房間探索是重點，要保留**（翊文 11-12：「房間探索還是要保留喔，是個重點」）：
  - 現在的 20 間房文字、選項都不變，每一層的房間每一間都在地圖上。
  - 每一排一定有一間探索房，而且探索房一路連到下一排的探索房：**一趟可以把這一層的房間全部走完**，跟改版前一樣。
  - 打怪物、寶箱是「這一排不想探索時的另一條路」，不是取代探索。
- 每層 5 排（`NUM.cellarMap.rows`），一排 2～3 個點，從上往下走，最底是這層的守門怪物。最後一排一定有休息。
- 點有五種：

| 點 | 內容 | 幾個人的時候 |
|---|---|---|
| 探索 | 現在的 20 間房直接搬來用，選項和文字不變 | 投票（現在的做法） |
| 遭遇 | 打一隻怪物（第四節） | 每個人各出一招 |
| 休息 | 回一點理智，或治好一隻受傷的佩佩，只能選一個 | 每個人各選各的 |
| 寶箱、怪事 | 小事件，有好有壞；理智低的時候內容不一樣 | 投票；「兩人一起搬」放這裡 |
| 守門 | 這層的大怪物，兩個階段 | 每個人各出一招 |

- **選路**：全隊投票選下一個點，平手領隊決定（沿用投票 30 秒）。一個人就自己選。
- 地圖每天用 `RNG()` 重排一次（種子＝日期＋層數），同一天大家看到的地圖一樣，可以互相報路。
- 下一個點是什麼看得到；再下面的只看得到種類的剪影。留守的人看得到整張（第七節）。
- **遭遇的點看得到怪物大概多強**（翊文 11-12）：等級 1～3、心情、顏色。是哪一隻不說，登記過的才看得到名字。越下面的排越容易遇到強的。

## 四、打怪物：回合制，看得到對方下一招

### 怪物是什麼

- 收藏庫裡放太久的東西成精：發抖的紙箱、從海報走下來的影子、自己坐著的椅子。跟現有房間的文字接得上。
- **全部原創，不畫青蛙，不像 Pepe**（界線第一條）。名字和來歷是草稿，給 Yuga 寫。
- 每隻怪物有：一條「壓力」（打到零就過）、心情、顏色（沿用現在的相剋）、2～4 招、一個弱點。

### 一回合怎麼走

1. **怪物先亮出下一招**。例如「要撲向小明的佩佩」「要讓大家看到不該看的」。
2. **每個人各選一個行動**（25 秒，時間到當「擋」）：

| 行動 | 用什麼 | 效果 |
|---|---|---|
| 推 | 自己帶的佩佩的強度＋骰子 | 扣怪物的壓力 |
| 看穿 | 偵查或神秘學 | 找到弱點：接下來的「推」算兩倍 |
| 安撫 | 說服 | 怪物這回合的招變弱，夠多人安撫就取消 |
| 擋 | 不用擲 | 這回合受傷、扣理智減半；可以指定幫隊友擋 |
| 招式 | 帽子、姿勢 | 見下面 |
| 逃跑 | 擲一次 | 離開這一場（要一半以上的人一起選）；沒成功怪物照打 |
| 撤 | — | 自己回地面，見第五節 |

3. **一起結算**，順序固定：看穿 → 安撫 → 擋 → 推 → 怪物出招。所以同一回合一個人看穿、另一個人推，當回合就兩倍。這是合作的甜頭。
4. 怪物的招打中：被點到的人扣理智，或他的一隻佩佩受傷退場。

- 一個人的時候：自己每回合選一個行動，館方助手自動「推」。
- 心情照舊可以花掉把骰子壓低。
- 技能檢定由出手的那個人擲，所以不同職業各有用處（規劃.md 第三節的「分工」）。

### 帽子和姿勢變成招式

現在這些能力是自動觸發，改成自己決定什麼時候用，一場一次：

- 棒球帽：擋下一次。
- 皇冠：重擲一次。
- 觸手帽：大傷害，帶牠的人扣理智。
- 巫師帽：這回合全隊的「推」加成。
- 躺平、毛帽：回理智（每層第一次才算，不能刷，界線「不要改回去」）。
- 斯拉夫蹲：這回合不會被推倒。
- 比讚：鼓舞，下一回合全隊加成。

改了要同步改 `HAT_AB`、`POSE_AB` 和「隊伍規則」牌子（`docs/架構.md` 4.7.1）。

### 守門怪物

- 壓力比較多，打到一半進第二階段，換一組招。
- 第二階段會讓全隊擲理智。
- 第一次打倒，給現在每層的過關獎勵（`CELLAR_REWARDS`：毛帽、書、鑰匙、倒立、結局都不變）。

### 為什麼是回合制，不做按時機

- 規則可以是純函式，伺服器跑同一份。
- 合作時不怕網路延遲，不會有人因為網路慢吃虧。
- 手機好按，不用另外照顧 `body.reduce-motion`。
- 要「手感」之後可以加演出（動作、震動、音效），不改規則。

## 五、帶著東西往下走

- 這一趟拿到的東西先放「背包」，每個人一個。回到地面才真的入帳。
- **撤退**：全隊投票一起撤，全拿。也可以自己先走，拿自己的背包，隊友繼續。
- **倒下**：自己帶的佩佩都退場，變成幽靈（沿用現在的幽靈）。背包先留著。
- **全隊都是幽靈**：這一趟失敗（決定 0036），每個人的背包剩一半。理智歸零的人照舊回黑房間。
- 這樣「要不要再走一個點」每次都要商量。也符合界線的「理智歸零要算容易出現」。

## 六、獎勵：靈感總量不加

節奏本來就太快（`docs/現況.md` 已知問題），所以：

- **靈感總量照現在的**，只是重新分到各個點。調之前先跑模擬。
- 新的獎勵：
  - **怪物圖鑑**：打過的怪物收進典藏冊，寫弱點和一小段來歷。
  - 怪物掉的材料、證據（接現有的「湊證據」）。
  - 少量籌碼：接現有的撿籌碼（決定 0047），一天幾次照舊。
- 每天前 3 趟有獎勵照舊（`P.coopDay`）。

## 七、跟現有的東西怎麼接

**合作的九個機制**（決定 0036）：

| 機制 | 改版後 |
|---|---|
| 全隊理智壓力 | 平均理智越低，怪物壓力越多、招越兇 |
| 每個人看到的不一樣 | 怪物的弱點每個人看到一部分，要拼起來 |
| 幻覺 | 理智低的人看到的「下一招」可能是假的 |
| 湊證據猜真相 | 照舊；怪物也會掉證據 |
| 短句、叫聲、打字 | 照舊；多幾句打怪用的短句（「我來擋」「先看穿」） |
| 一人留守 | 看得到整張地圖、怪物下一招是真是假 |
| 幽靈 | 照舊敲一下；打怪時可以指出怪物的弱點一次 |
| 留下痕跡 | 照舊；留言牌可以留在地圖的點上 |
| 兩人一起搬 | 放進「寶箱、怪事」的點 |
| 探險報告 | 多寫打倒了什麼、誰補了最後一下 |

**其他**：

- **存檔**：`P.cellar` 的 `best`、`won`、`cleared`、`floorsDone` 都保留，只加欄位。舊存檔走過的層照算。改存檔欄位要寫測試。
- **每週劇情**：`week.json` 的房間格式不變，多一個可以不寫的「本週怪物」。`tools/week_check.cjs` 要跟著認。
- **試煉房間、限時活動**（`trialBoost`、`coopBoost`、`cellarChips`）：照舊，當成地圖上的特別點。
- **伺服器**：怪物的壓力、下一招、骰子都放 `coopRuns/{pid}`（只有 Functions 碰得到）；每個人看到的放 `coopView`。開主控台看不到弱點和假招。
- **回滾**：比照大廳改版（決定 0066）。舊的地下室程式不刪，`NUM.ui.newCellar` 切換。
- **手機**：打怪的畫面一開始就排 375 寬和橫拿，不要做完再補。

## 八、介面：一眼看得出要怎麼做

翊文 11-12：「然後介面也要看，是不是很直觀，玩家能一眼看出要怎麼做」。

這一節跟規則一樣重要。每一步有畫面的 PR 都要照這裡檢查，沒過不算做完。

### 每個畫面都要守的

1. **一個畫面只問一件事。** 畫面最上面一行大字寫「現在要你做什麼」：「選下一個點」「選你這回合的行動」「等隊友」。
2. **可以按的東西都有框、有字**，不能只有小圖示（翊文的習慣，`docs/現況.md`）。現在不能按的要變灰，並寫為什麼（「這場用過了」「偵查太低」）。
3. **按之前就看得到會發生什麼。** 行動按鈕上直接寫結果：「推：扣怪物約 6～10」「擋：這回合傷害減半」。要擲骰的寫成功率，用白話（「大概七成」），不寫「1D10」。
4. **怪物下一招用一句白話加一個大圖示**，放在怪物頭上，並指到會被打的那個人或那隻佩佩。
5. **數字用條，不用背。** 怪物的壓力、自己的理智都是一條，旁邊才是數字。這一招打下來會扣多少，直接在條上用淡色預告。
6. **輪到誰、還剩幾秒一直看得到。** 選好的人頭上打勾；隊友選了什麼在結算前只顯示「選好了」，結算時一個一個演出來。
7. **第一次遇到才教，教在現場。** 第一場打怪一步一步帶（先指怪物的下一招，再指行動按鈕），不另外開說明頁。說明不破梗（決定 0007）。
8. **花東西的按鈕寫清楚花多少**、旁邊寫現在有多少（界線「不要改回去」）。
9. **結果要看得懂為什麼。** 結算時寫「看穿＋推＝兩倍」「被棒球帽擋下」，不是只跳一個數字。
10. **手機一開始就排。** 行動按鈕在拇指按得到的下半部，每顆至少 44px 高；375 寬直拿和橫拿都要能一手按完一回合。

### 選路的畫面（草稿）

- 地圖從上往下，現在站的點發亮，**能走的下一個點會跳、有框、寫名字**（「休息」「遭遇」「寶箱」），不能走的是淡的。
- 點一個先看到一張小卡：這是什麼、大概會遇到什麼、誰投了這裡；再按「走這裡」才算投票。
- 最下面一直有背包（拿了什麼）和「撤退」。

### 怎麼確認

每個有畫面的 PR：

- 截圖電腦 1366、平板 800、手機 375 直拿和橫拿（`npm run shot`、`tools/shot_phone.cjs`），放進 PR。
- 照上面 10 條逐條寫過或沒過，寫進維護日誌。
- **「第一次看到的人」檢查**：只看截圖，回答三題：現在要做什麼、可以按哪裡、按了會怎樣。有一題要想超過幾秒就改。
- 兩個分頁實際走完一場，看「等隊友」的時候畫面有沒有告訴你在等誰。
- 最後一關是翊文自己玩 B1。AI 覺得直觀不算數。

## 九、分幾步做

每一步一個 PR。

1. **規劃文件和決定紀錄**（這一份）。
2. **打怪的規則**：新檔 `shared/cellar_fight.js`，純函式，一開始就吃 1～4 人。加測試、加模擬（1～4 人的勝率、平均幾回合、扣多少理智）。
3. **接進合作流程**：`coop_flow.js` 多一個「打怪」的階段，Functions 跟著接。在模擬器用 `emu:call` 走完一場。
4. **B1 一隻怪物的畫面**：放在開關後面。一個人、兩個分頁合作都實際走過；電腦和手機寬度都看，照第八節的 10 條檢查。**這一步做完翊文就能玩到。**
5. **地圖、選路投票、休息、寶箱**。
6. **五層的怪物**：一般怪物約 10 隻、守門 5 隻。文字草稿給 Yuga。
7. **背包、撤退、失敗的代價**。
8. **每週怪物、怪物圖鑑進典藏冊**。

## 十、翊文回答的八題（11-12，決定 0068）

| 題 | 翊文的回答 | 做到哪 |
|---|---|---|
| 1 互動方式 | 回合制，**有時候**加按時機 | 規則有了：有些回合可以按（`fight.tap`），按得好「推」多一點點；只加不扣、不按也沒事。畫面還沒做 |
| 2 一個人下去在哪裡算 | 登入的人也走伺服器的合作流程 | 還沒接 |
| 3 走到一半叫人加入 | 先不做 | — |
| 4 取代還是並存 | 新的取代舊的，留開關可以切回去 | 還沒接 |
| 5 失敗的代價 | 背包剩一半；**倒下的佩佩是真的受傷** | `NUM.fight.injure = 1` |
| 6 留守算不算走過這一層 | 不算（照現在） | — |
| 7 怪物的題材 | 「沒被記在帳上的東西」，**並且跟著逐漸擴展的世界觀主線走** | 第十一、十二節 |
| 8 靈感 | 總量照現在；合作人越多**稍微**多給一點；每多一個合作的玩家理智高 5 點（壯膽） | `fightWinInsp`、`fightCourage` |

翊文同一天另外說的：

- **怪物有不同的等級**：1～3 級（`fight.rank`）。等級越高壓力越多、理智扣越多，打贏多給一點靈感。守門不分等級。
- **在地圖上就看得到大概多強**：遭遇的點看得到等級、心情、顏色（`cmapPeek`），決定要帶誰、要不要接戰。**是哪一隻不說**，登記過的才看得到。
- **有逃跑**：打到一半可以逃（`flee`）。要一半以上的人一起選才擲，一般 60%、守門 40%。成功就離開這一場，沒有獎勵；沒成功怪物照打。跟「撤退」（自己回地面）是兩件事。
- **主線要保持神祕感**：沒登記過的只給剪影；B5 的怪物故意不清楚；不揭曉多出來的那一隻。
- **動畫要夠精美**，素材的 Prompt 在 `docs/地下室素材清單.md`。

**做的時候 Claude 先定的，等翊文看**：

- 壯膽不是直接加理智，是「膽量」：每多一個真人隊友每個人多 5 點，扣理智時先扣它，這一趟用完就沒了，不寫進存檔。原因：直接加理智的話，一直開隊伍就能把理智刷回來，跟界線的「理智歸零要算容易出現」衝突。**如果翊文要的是直接加，說一聲就改。**
- 合作多給的靈感：每多一個真人隊友，每打贏一隻多 1 靈感（`NUM.fight.coopInsp`）。
- 按時機是每個人在自己的畫面上按，不經過網路，所以網路慢不吃虧。按得好只多 1～2 點。
- 等級 3 的怪物很兇（模擬：一個人贏 23～51%），是給多人或想冒險的人挑的。

## 十一、故事線：怪物是「沒被記在帳上的東西」

翊文 11-12：「有你說的隨機地圖那一些嗎，以及這些的故事線嗎」。

這一節是草稿。主軸 `content/story/帳本.json` 的 `main.theme` 已經定案，**不改**；這裡只是讓新玩法接上它。文字、名字問 Yuga。不破梗：遊戲裡不直接說出下面的解釋，藏在登記卡、帳本的字跡裡。

### 一句話

館裡的帳一直對不上。帳本漏掉的東西在地下放久了會「鬧」。你下去不是去打死牠，是把牠安撫下來、**補登記**。可是每補一筆，帳還是差一隻。

### 玩法的每一塊都有說法

| 玩法 | 故事裡是什麼 |
|---|---|
| 怪物 | 沒被記在帳上的東西：沒登記的紙箱、沒名牌的雕像、沒簽名的畫 |
| 怪物的「壓力」 | 牠的不安。壓到零＝牠安靜下來，肯讓你登記 |
| 推、看穿、安撫 | 把牠按住、看出牠原本是什麼、跟牠說話 |
| 打贏 | 寫一張登記卡，掛上去。牠不會消失，隔天還在，只是不鬧了（所以每天可以再遇到） |
| 怪物圖鑑 | 一本《補登的帳》。每隻一張登記卡 |
| 地圖每天不一樣 | 晚上有人在搬東西（接 B2 走完的那句「每一尊雕像都換了位置」）。是誰搬的不說 |
| 背包、撤退 | 還沒上樓登記的東西不算數。倒在下面，東西有一半會自己走回去 |
| 理智低看到假的下一招 | 你開始分不清哪些是帳上有的 |
| 守門怪物 | 那一層「數不清」的原因 |

### 五層各一段（接已經有的《看懂的事》，不新增謎底）

| 層 | 一般怪物 | 守門 | 這一層問什麼 |
|---|---|---|---|
| B1 積灰的儲藏室 | 發抖的紙箱、沒人領的失物 | 一直多出一箱的那疊紙箱 | 沒被記下來的東西，還算存在嗎 |
| B2 蓋著白布的雕像廳 | 白布底下會換位置的、空白的名牌 | 沒有名牌的那一尊 | 名字是誰給的 |
| B3 空畫框的走廊 | 從畫裡走下來的影子、沒簽名的畫 | 不肯回框的那一幅 | 數的人會不會改變被數的東西 |
| B4 淹水的檔案室 | 泡爛的帳頁、浮上來的算盤珠 | 水面上那本一直在寫的帳本 | 記帳的人有沒有被記在帳上 |
| B5 | 排隊的、還沒有樣子的 | 不寫（不破梗；結局「地下館長」不改） | 誰來替牠寫上名字 |

### 登記卡怎麼露出故事

- 每隻怪物的登記卡有三段字：第一次登記露第一段，之後再遇到幾次露第二、第三段。
- 第一段寫牠是什麼；第二段寫牠為什麼沒被記下來；第三段是帳本上一行別人的字（會計、警衛的筆跡，不說是誰）。
- 五隻守門的登記卡湊齊，劇情線多一條「補登的帳」，最後一行還是「收支：差壹隻」。**不揭曉多出來的那一隻是誰。**
- 合作時：誰補最後一下，登記卡上的「登記人」寫他的名字。大家各自的《補登的帳》都會有這張。

### 每週劇情怎麼用

- `week.json` 的「本週怪物」：這週新聞的氣氛變成一隻只出現一週的東西（例如換季 → 沒人領的冬衣）。照決定 0037、0048 的規矩，不寫真人。
- 登記了本週怪物可以當每週任務、可以帶線索（`clue`）。
- 第 1 季「帳對不上」（W47～W50）本來就是一層一層往下數，守門怪物可以照週次一層一層開。

### 要小心的

- 第 1 代的文字不改（決定 0006）；現在 20 間房的文字照搬，不重寫。
- 「打」這個字在介面上要不要用，問 Yuga：故事裡是安撫和登記，按鈕叫「推」「安撫」比較合，但翊文說的是「打怪物」。
- 等翊文、Yuga：這個說法可不可以；B5 守門要不要做成特別的一場。

## 十二、每天的排程：好改、好玩、接得起來

翊文 11-12：「補故事規劃，讓每天排程能方便更改又好玩且有連續性的故事」「要設計讓每日的更新方便設計新關卡」。

### 原則：新關卡是「寫資料」，不是「改程式」

每天 04:30 的排程只要在當天的 `content/weeks/週/dN.json` 多寫一塊，就多一個關卡。不用動 `shared/`、不用部署新程式。

**已經做好的**（11-12）：

- `fightStart` 的第一個參數可以是「整份怪物」，不一定要是內建的 id。
- `fightFoeCheck(怪物)` 會擋壞的：壓力 10～90、理智一招最多扣 6、回壓力最多 10、2～4 招、名字 12 個字內、預告要寫點到誰、不能像青蛙、id 不能跟內建的撞（`FIGHT_CUSTOM`）。排程寫壞了進不了遊戲。

- **工具** `npm run level:new`（`tools/new_level.cjs`）：排程寫名字、打法、心情顏色、預告和登記卡的字，數字由工具照樓層填、自動調到目標難度、模擬 1～4 人、印出玩家在地圖上會看到什麼，`--write` 寫進當天的檔。五種打法：嚇人、撲人、越來越多、混合、守門。
- `tools/week_check.cjs` 會檢查 `cellar` 那一塊（`fightDailyCheck`＋字數、禁用字、劇情線）。
- `cmapAddDaily`：今天的怪物放進地圖中間那一排，上一排都走得到。
- 排程的步驟寫在 `content/排程說明.md` 一之八；格式在 `content/README.md`。

**還沒做的**：遊戲把 `cellar` 讀進來（要等畫面）；帳本的 `cellarArc`（先沿用現有的 `weeks.<週>.hooks`）。下面的草稿格式以 `content/README.md` 的為準。

### 每天可以寫的那一塊（草稿）

```json
"cellar": {
  "floor": 1,
  "node": "foe",
  "foe": {
    "id": "w47-d2-coat", "name": "沒人領的冬衣", "intro": "袖子自己舉了起來。",
    "hp": 30, "mood": "傷心", "color": "紅",
    "moves": [
      { "id": "wrap", "kind": "scare", "san": "1D3", "text": "要把{x}包起來" },
      { "id": "pile", "kind": "grow", "n": 3, "text": "箱子裡還有壹件" }
    ]
  },
  "card": ["登記卡的第一段。", "第二段。"],
  "picks": "h-w47-d1",
  "hook": { "id": "h-w47-d2", "text": "口袋裡有壹張寫了壹半的招領單。" }
}
```

- `floor`、`node`：今天在哪一層多一個點。`node` 可以是 `foe`（一隻新怪物）、`explore`（一間新房間，用現在 `week.json` 房間的格式）、`chest`（一件怪事）。
- 這個點放在當天地圖的中間那幾排，標「今天」。只有今天有；沒走到不懲罰。
- `card`：登記之後寫進《補登的帳》的字。
- `picks`、`hook`：連續性靠這兩個，見下面。

### 排程可以轉的三個旋鈕

寫新怪物不用想數字，轉這三個就有變化：

1. **心情和顏色**：決定今天帶哪種佩佩最好打（心情相剋兩倍、顏色 +1）。每天不一樣，玩家就要換隊伍、去做新的佩佩。
2. **招的組合**：撲（倒下一隻）、嚇（一個人扣理智）、全體、回壓力，四種挑 2～4 招。全是「嚇」的怪物考驗理智；會「回壓力」的要趕快打。
3. **在哪一層**：B1 新手也打得到；放深一點的層是給走得遠的人。

壓力和理智的範圍被 `FIGHT_CUSTOM` 框住，排程怎麼寫都不會寫出打不贏的。

### 故事怎麼接得起來

- **每天接一個鉤子、留一個鉤子**：今天的 `picks` 要寫昨天 `hook` 的 id；今天自己再留一個 `hook`。檢查程式擋「沒接昨天的鉤子」。這樣排程不用記得整季的故事，只要讀昨天那一句。
- **帳本記進度**：`content/story/帳本.json` 多一條 `cellarArc`：這週的怪物是誰、補登了幾筆、還開著的鉤子。每天的排程先讀它、寫完更新它。換一個 AI 來寫也接得上。
- **一週七天的節奏**（可以不照，但照這個比較穩）：

| 天 | 做什麼 | 玩法 |
|---|---|---|
| 一 | 出現異狀：某一層多了一樣東西 | 一間新的探索房 |
| 二 | 第一隻小的出來 | 一隻新怪物 |
| 三 | 線索：登記卡上有別人的字 | 一件怪事（寶箱） |
| 四 | 第二隻，跟第一隻有關 | 一隻新怪物，心情顏色跟週二相反 |
| 五 | 本週怪物現身（限時活動可以排這天晚上） | 守門等級的一隻，兩個階段 |
| 六 | 全館一起：大家補登的筆數加起來 | 沒打過週五那隻的還可以打 |
| 日 | 收尾：這週的帳，最後一行還是差一隻；留下週的鉤子 | 一間新的探索房，只有字 |

- **好改**：每天的檔自己一份。翊文或 Yuga 想改明天的，改那一個 json 就好；想換掉整週的方向，改帳本的 `cellarArc`，後面幾天的排程會照新的接。
- **排程沒跑**：那天就沒有「今天」的點，地圖照常，鉤子順延到隔天（`picks` 接最後一個開著的鉤子）。不會斷。
- **主軸不變**：每週的事件來自新聞的氣氛（決定 0037、0048 的規矩照舊），但都要落在「帳對不上、多出來的那一隻」。不揭曉謎底。
- **合作**：週五那一隻適合揪人；登記卡寫「登記人」；週六的全館筆數每個人都算。

### 要翊文、Yuga 決定的

- 「今天」的點沒走到，隔天還能不能補（每日任務現在可以補做，決定 0060）。
- 每天的新怪物要不要也進《補登的帳》（會越來越厚），還是只有每週那一隻進。
- 一週七天的節奏可不可以。
