## 為什麼要改

Yuga 檢視每日排程（08:23 雲端照 content/排程說明.md 寫劇情）能不能快速、準確，把腳本的五項交給我（翊文要求）。

## 改了什麼

1. **strict 查延伸世界**（`day_check.cjs` 的 `extendIssues`）：帳本 `extend.weeks.<週>` 的恐懼／代價／佩佩／嚇人的展品各有 `day`、`where`；今天剛好是那天，今天的 dN.json 就要真的有對應的東西（房間 adds、今日特展 show.works、公佈欄 board、每週任務旁白、書、賭場），cost 的 `san` 要在今天的檔裡找得到；`closes` 的謎在週日收，那天要有 clue。`where` 裡「dN …」開頭的段落是別天的不算；不認得的（NPC 日報）略過。人物線放了要在 `ties` 有記：strict 本來就要求每天 ties 有「dN：」那一行，沒另外加。
2. **`ledger -- today`**：延伸世界排最前（四問、人物線、這週的掉落和附頁、collect 的線，「見 extend.weeks…」直接換成內容）；mysteries／newsThreads／revealBeats 預設只印標題（`--full` 才全文，也不再預設印出謎底）。W48 從 72KB 降到 27KB。
3. **`day:plan`**：底下多印這週 extend.items、今天排到的四問、collect 的四問摘要（`tools/content/extend_view.cjs`，只在 day_plan 的 main 加壹行，沒動延伸週那段）；`--week --next` 看下壹週。
4. **署名**：`ship.cjs` 本來就讀 `SHIP_AI`（沒設才是 Claude Opus 5.5），只是檔頭註解和預設值容易讓人誤會；加了測試鎖住。
5. **失敗偵測**：ship 停下來時印壹段可以貼進 issue 的失敗報告（標題、時間、分支、停在哪壹步、原因）；新的 `schedule_health.cjs` 加 `.github/workflows/schedule-health.yml`（台灣每天 09:30）：今天的 dN.json 既不在 main 也沒有開著的 PR 帶它就開 issue「自動流程失敗通報」（暫停中不檢查，週一另看 week.json）。

## 還沒做、要注意

- 09:30 的 workflow 第一次跑要等明天；GitHub 的排程可能延遲幾分鐘。
- 排程 PR 如果 09:30 已經合併，檔在 main 上；還沒合併就看開著的 PR（用 `gh pr list`，需要 workflow 的 `pull-requests: read`，已加）。
- 帳本 where 的詞（房間、今日特展…）是照現在的寫法對的，之後帳本換寫法要同步 `WHERE_KEYS`。
