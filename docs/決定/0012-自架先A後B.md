# 0012 伺服器自架在 homelab：先 A（ASUS DDNS），之後換 B（買網域＋Tunnel＋Access）

- 日期：2026-11-08
- 誰決定：翊文
- 狀態：被第 0021 篇取代（11-08 改用 Firebase）

## 背景

- 規劃比較過 Cloudflare Workers、Firebase、自架（規劃.md 第五節）。
- 翊文 11-08：

  > 「我有一個homelab,proxmox然後可以開debian CT，適合的話你也可以參考看看」
  >
  > 「我有Asus路由器可以把動態ip變成asus.com的」
  >
  > 「DDNS來port forwarding 這樣只會在我的Homelab裡的一個CT跑對不對，不會影響到其他家裡的服務」
  >
  > 「兩個都規劃」

- 最後翊文說：「先 A 後 B」。

## 決定

- 遊戲伺服器自架在翊文的 homelab：Proxmox 上的 Debian CT（無特權容器），Node 遊戲伺服器＋SQLite＋systemd 排程。
- **先用 A 跟朋友試玩**：ASUS 路由器的 DDNS（`名字.asuscomm.com`）。
  - 路由器只轉 443（申請憑證需要的話加 80）到 CT；CT 裡用 Caddy 申請 HTTPS 憑證。
  - 登入用 Firebase Authentication（只用登入，免費方案）。
  - CT 要跟家裡其他設備隔開（Proxmox 防火牆或 VLAN）。
- **確定要長期玩，再換 B**：買一個網域＋Cloudflare Tunnel＋Cloudflare Access。換完把路由器的轉發關掉。
- 同一時間只開一種：B 開著時 A 的連接埠也開著，就會繞過 Access。
- 開工前翊文先做 A0：看路由器的 WAN IP 跟外面查到的是不是一樣。家裡沒有公開 IP，就跳過 A，直接用 B。

## 影響

- 遊戲伺服器用一個設定切換：`ENTRY=ddns` 或 `ENTRY=tunnel`。
- 登入轉接層 `server/auth/`：`firebase.js`（A）、`access.js`（B），都只回傳 email；玩家照 email 對應，從 A 換到 B 帳號、存檔不用搬。
- 網址、模式都寫在設定檔，程式裡不寫死；兩種登入都要有自動測試。
- 帳號（GitHub、Firebase、Cloudflare、網域）都要翊文自己開、自己付款。AI 不能替人開帳號、付款，也碰不到路由器、Proxmox、正式伺服器。
- 步驟 A0–A8、B1–B6、A 的隔離、從 A 換到 B：規劃.md 第五節。換到 B 是階段 19。

## 什麼時候可以再討論

- A0 查出家裡沒有公開 IP 的時候（直接走 B，或 Tailscale Funnel）。
- 試玩之後決定要不要長期玩、什麼時候換 B。
