# 新增玩家拿得到的東西，要怎麼讓館友證跟上

翊文 11-22：「都要雙向用腳本或程式來追蹤，避免改了一部分另一邊沒有改」。`npm test`（單跑 `npm run pass:check`）會擋。規劃在 `docs/規劃/館友證裝備整合規劃.md` 第七節。

## 三個地方

- 登記表 `shared/social/pass_sources.js`：壹類東西壹列（來源清單、存檔欄位、館友證哪壹頁、能不能用、別人看不看得到）。
- 白名單 `tools/check/pass_gaps.json`：`hideSave`（存檔欄位不用顯示）、`hideLists`（清單不是玩家拿得到的）、`hidePass`（passView 的欄位不對應壹類東西）、`gaps`（館友證還沒補完的）。每條都要寫原因。
- 館友證畫面 `web/src/panels/ui_pass.js`。

## 新增壹類東西時

1. 在登記表加壹列。`pass` 寫館友證顯示它的欄位（`passView` 或賭場 `casPassView` 輸出的路徑）；還沒有就寫 `null`，並在 `gaps` 加壹條 `kind: "none"`。
2. 新存檔欄位（`newProfile`、`casWalletNew` 的頂層欄位）：登記進某壹列的 `save`，或加進 `hideSave` 寫原因。
3. `passView` 加欄位、`ui_pass.js` 畫出來；`pub` 只有 `cleanHallView` 對外的欄位才寫，兩邊要互相對得上。
4. 補完缺漏就把 `gaps` 那壹條刪掉（檢查會擋「已經補了還留著」）。

## 檢查會擋什麼

來源多了館友證沒跟上（存檔欄位、清單沒登記、算了沒畫、`none` 缺白名單）；館友證或登記表指到的東西已經改名或拿掉（欄位、檔、清單、對外欄位對不上）。
