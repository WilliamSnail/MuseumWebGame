## 〇、兩個排程都一樣的開頭

1. 在 repo 的最新 `main` 開一個分支：`claude/週劇情-2026-W47`（週一）或 `claude/週劇情-2026-W47-d3`（每天）。
2. 先讀這些（照順序）：
   - `AGENTS.md`（規則）、`docs/界線.md`（不能做的事）。
   - `content/排程設定.json`：`pause` 是 `true`，或這週在 `pauseWeeks` 裡 → **什麼都不寫**，跳到第五節「沒寫內容的時候」。
   - `content/README.md`（格式）、`docs/每週劇情.md` 第三、五、六節（新聞的規矩、可以加什麼、不破梗）。
   - `content/story/帳本.json`（劇情帳本：**主線的主旨 `main.theme`**、主線大綱、季節線 `seasonal`、劇情線、伏筆、角色地點物品、用過的新聞元素）。
   - 這週已經寫好的 `content/weeks/<這週>/`（每天的排程：week.json 和前幾天的檔）。
3. **日期**：用台灣的日曆日期。04:30 時遊戲的 `todayStr()` 還是前一天（05:00 才換日），所以「今天」是 `npm run now` 印出來的那個日期，不是遊戲的今天。週的名字用 ISO 週（週一開始），例如 2026-11-16 是 `2026-W47`。

## 一、週一 04:30：排這一週

> **原則**（翊文 2026-11-09：「主線劇情的主旨還是要繼續下去，季節線跟每日也要像副劇情一樣，圍繞這主軸，即便有使用新聞來參考喔」）：主線的主旨（帳本 `main.theme`）一定要繼續；新聞只決定這週的事件和氣氛，不能帶走主軸；每週的線、每天的書、季節線都是圍繞主軸的副劇情，碰到主線的東西但不揭曉謎底。帳本 `weeks.<週>.ties` 要記這週碰到主軸的哪一點。

1. **查新聞**（`docs/每週劇情.md` 第三節）：台灣最近一兩週熱門的事：熱門搜尋、幾家新聞網站的熱門、天氣、節日、展覽、流行的食物和話題。
   - **選舉、政治話題、兩岸議題都可以用**，轉成我們劇情的講法（翊文 2026-11-09：「新聞可以找最近台灣相關的，連選舉那種都可以，把找到的用我們劇情敘述的方法來呈現」「兩岸 的可以，這是我們喜歡的議題」）。
   - 只取**抽象的元素**：一種天氣、一樣東西、一種心情、一個現象（例如豪雨 → 地下室淹水；排隊美食 → 地下冒出一個只賣那個的攤子；搶票 → 展品搶展台；選舉 → 館內的展品投票選館長）。
   - **不准**：有人受傷、死亡的事故和災難、犯罪；真人、政黨、候選人、公司、品牌、商標、別人作品的名字；選邊站、嘲笑任何一邊（看不出在挺誰）；健康、醫療的說法；抄新聞的文字（只用自己的話）；畫 Pepe 的樣子；跟仇恨符號扯上關係的東西。
   - 帳本的 `news` 用過的元素不要一直重複。
   - 找不到合適的：用「常青」的主題（跟新聞無關），照主線原本的安排走。
   - 新聞的連結只寫在 `content/weeks/<週>/靈感來源.md` 和 PR 裡，**不進遊戲**。
2. **排這週的劇情線**：主線往下延伸一段（帳本 `main.seasons` 這週那一章的 `tell`），新聞只決定這週發生什麼事、氣氛。想好：
   - **季節線**：看帳本 `seasonal.lines` 這週有沒有章（`chapters[].week` 是這週）。有就排這週某一天放一本掛在那條線上的書，寫進 `weeks.<週>.plan`。換季那週（`seasonal.lines` 下一季的第一章）要開新的線：`chapters` 還是空的就照 `direction` 先寫當季的大綱（大約每兩週一章，接當季的節日，每章寫 `ties`），`lines` 也加這條線。
   - 7 天大概推到哪（寫進帳本，不寫進週包：還沒到的天不能先在網頁裡）。
   - 這週怎麼玩：本週異狀（一間房間）、哪幾天在已經過關的樓層加房間、可以找的東西、獎勵。
3. **寫 `content/weeks/<週>/week.json`**：標題、不劇透的大綱、劇情線（這週的線，要的話加主線、樓層的線；這週有季節線的章就加那條 `kind: "season"` 的線，id 和名字照帳本）、本週異狀、5 個每週任務、全做完的獎勵、結局要讀幾本。
   - 想配合這週的主題，寫 `shop` 指定兌換所上架哪幾件限定頭飾（只能挑已經畫好的，`content/README.md` 第四節）。挑不到合適的就不寫，照週號輪流。
   - 每週任務只能指到週一就有的東西（本週異狀的房間、d1 的書和房間），或用 `readWeek`、`dailyAll`、`showDays`、`ending`、`cellar`、`make` 這種不用指定的。
   - 每週任務以**地下的新東西**為主：探索這週新開的房間、走完這週的線、讀到結局。
   - **排限時活動**（`events`，決定 0041，做法看下面「一之二」）：這週排 1～2 場，寫進 `week.json`。
4. **寫 `d1.json`**（週一）：1–2 本書、3 個每日任務、今日特展 3–5 幅（至少 1–2 幅用 `svg` 畫全新的，第二節）、公佈欄那一行、要的話加 0–2 間房間。
5. **寫 `content/weeks/<週>/靈感來源.md`**：一個表：哪則新聞（連結）、取了什麼元素、為什麼安全。審的人看這張就知道有沒有踩線。
6. **更新帳本**（同一個 PR）：
   - `lines` 加這週的線（`start` 寫這週）；主線的 `status` 改成進行中。
   - `weeks.<週>`：`use`、`main`（**這週主線推到哪，一定要寫**）、`ties`（這週的線碰到主軸的哪一點：哪個伏筆、人物、地點）、`news`（這週用的元素）。
   - `foreshadow` 加這週埋的伏筆（`planted`、`due`）；這週要收的標 `closed: true`。
   - `news` 加用過的元素；新的角色、地點、物品加進去。
7. 跳到第三節「檢查、PR、合併」。

### 一之二、排限時活動（週一排這週時一起排）

> 翊文 2026-11-09：「時不時要有一些限時活動，例如晚上8~10點合作打試煉可以更多獎勵之類的」。活動是**給玩家多一個一起玩的理由**，不是催人上線：沒趕上什麼都不會少，也**不要寫「不來就虧」「最後機會」「倒數」這種恐嚇的口氣**。沒有真錢、沒有買東西。

**寫在哪、長怎樣**：`content/weeks/<週>/week.json` 加一欄 `events`（陣列，可以不寫＝這週沒有活動）。每一場：

```json
"events": [
  { "id": "double11", "kind": "coopBoost", "date": "2026-11-11", "from": "20:00", "to": "22:00",
    "title": "雙 11 的招領箱加班夜",
    "words": "雙 11 的夜裡，招領箱前排起壹串人。邀館友壹起下去翻箱底，找得越齊，靈感越多。" }
]
```

- `id`：英文、數字、-、_，同一週裡不能重複。
- `kind`：現在只有兩種，只能從這裡挑（要新的種類是改程式，寫提案，不要自己加）：
  - `coopBoost`：合作地下收藏庫（遊戲裡的「壹起下去」）。活動中**開始**的那一趟：記號對上、猜對、搬回來的靈感 ×1.5，當天多 1 趟有獎勵（平常一天前 3 趟）。開始時在活動內，就照活動算到走完。
  - `trialBoost`：地下的試煉房間（一個人進去、或邀館友一起打的合作試煉都算）。活動中走進去的那一間，過關的技能成長 ×1.5（一間一週還是只拿一次）。
- `date`：**台灣的日期**，一定要在這週之內（週一到週日）。
- `from`、`to`：**台灣時間**、24 小時制 `"20:00"`。`to` 要晚於 `from`；不跨 05:00（遊戲 05:00 換日）所以 `from` 不能早於 `05:00`；最短 30 分鐘、最長 360 分鐘。
- `title`：16 字以內。`words`：60 字以內，一兩句話，說這場活動在劇情裡是什麼。兩個都是畫面上的字：用「壹」不用「一」、沒有英文字母（`雙 11` 這種數字可以）、不犯禁用字。
- 同一天的兩場時間不能重疊；一週最多 3 場（`NUM.events.perWeek`）。`npm test`（`tools/week_check.cjs`）會擋壞的。備用週不能寫 `events`（沒有日期）。

**怎麼排**（`kind` 只有兩種，輪流用，不要連兩週都排同一種）：

1. **時不時，不要每天**：週一排這週時挑 **1～2 場**，同一週不要超過 2 場（第 3 場留給臨時加的）。有些週可以 0 場（尤其是節日很多、劇情很滿的那週）。連續兩週不要都排 2 場。
2. **時間**：平日晚上 **20:00～22:00** 為主；週末（六、日）可以改下午 **14:00～16:00** 或晚上 20:00～22:00。同一週的兩場不要排在相鄰兩天。不要排在 05:00～08:00、不要排會讓人熬夜的時間。
3. **接劇情和節日**：能接這週的故事就接（這週在找什麼、哪個房間、哪個人物），能接帳本 `calendar` 的日子（雙 11、節日）就排在那天。名字（`title`）和文字（`words`）用劇情的口吻，說這場活動在故事裡是什麼（例如招領箱後面有人敲門、館長請大家一起翻箱底）。**`words` 要讓玩家看得出「這場活動鼓勵什麼」**：`coopBoost` 就邀人一起下去；`trialBoost` 就說試煉房間、一個人或找館友一起都行。
4. **新聞和主線的規矩不變**：不選邊、不嘲笑任何一邊、不破梗（不提還沒開放的劇情、結局）、不寫真人政黨公司品牌（`docs/每週劇情.md` 第三節）。活動的字會出現在大廳、公佈欄、Discord，所有人都看得到，所以更要保守。
5. **數字不要自己寫**：加成多少是程式裡的（`NUM.events`，等翊文決定），文字裡不要寫「×1.5」「多 1 趟」，遊戲會自己加（大廳、公佈欄、Discord 都會自動寫出來）。
6. **記進帳本**：`weeks.<週>.plan` 寫「活動：11/11 coopBoost 20:00～22:00」，下週排的時候看得到，避免連續重複。
7. **Discord 不用另外發**：週一的公告會自動列出這週的活動；活動當天的「今日館訊」會自動多一段【今晚限時活動】（`tools/discord_post.cjs`）。
8. **臨時加一場**（翊文說要加、或這週剛好有事）：只改這週的 `week.json` 的 `events`，走一般的 PR，測試過就合併；合併會自動部署（Functions 也會一起更新），**活動開始前要上線**。已經結束的活動不要改。
9. 不要去動遊戲裡的任何數字、不要改別的檔。排的是**內容**，不是程式。

## 二、週二到週日 04:30：寫今天

> **原則**（同第一節，翊文的話）：「主線劇情的主旨還是要繼續下去，季節線跟每日也要像副劇情一樣，圍繞這主軸，即便有使用新聞來參考喔」。今天的書也是圍繞主軸的副劇情；碰到主軸的哪一點，在帳本 `weeks.<週>.ties` 加一行（`d3：…`）。

1. 讀這週的 `week.json`、前幾天的 `dN.json`、帳本裡這週的安排（`weeks.<週>.plan`、`main.theme`、`main.depths`）。
   - **看帳本 `calendar`**（翊文：「雙11購物節那種的也可以加入每日的安排」）：今天如果是雙 11 這種大家會聊的日子，把它融進今天的書、任務或今日特展，可以上網看今年大家在聊什麼；一樣圍繞主旨，不寫平台、品牌、店家的名字。
2. **寫今天的 `dN.json`**（N＝週一是 1、週日是 7）：接著昨天的故事往下。
   - 1–2 本書，至少一本在這週的線上；可以有一本要「在地下某一層找到」或「做完某個任務」才解開。
   - 3 個每日任務，跟這週的故事有關，大約 10 分鐘做得完。
   - 今日特展 3–5 幅，主題跟這週有關；可怕的要擲理智（成功不扣），也要有不可怕的。**每天至少用 `svg` 畫 1–2 幅全新的**（照這週的故事畫，畫風和規矩看 `content/README.md` 第九節）：以場景、物品、抽象、光影為主，同一天的幾幅要明顯不同。**不畫青蛙或任何像 Pepe 的角色**（要青蛙就用 `art: "frog"`）；不下載、不描別人的圖，不用真實的品牌標誌，不畫真人。
   - 公佈欄那一行（例如「招領箱裡多了壹頂棒球帽；書架多了 2 本書。」）。
   - **加一兩樣新東西**：已經過關的樓層多一間房間（例如 B1 多了一扇門）、可以找的東西、書頁。
   - **季節線**：帳本這週有季節線的章、還沒放書（`written` 是 `null`）：排到今天（或週一排好的那天）就放一本掛在那條線上的書（`unlock` 用 `now`），照章的 `tell` 寫，提到當週的節日（`holidayOf`，那天的節日的話）。`week.json` 的 `lines` 還沒有這條線就順手加。放了就把那章的 `written` 寫成書的 id（例如 `2026-W46/s1`）。一天還是 1–2 本書，至少一本在這週的線上。**這週 2026-W46 也算**：第一章「第壹張明信片」。
3. **週日（d7）**：放一本 `"ending": true` 的書收尾，留一個接主線、接下週的線索；或在 `week.json` 寫 `continues` 延到下週（帳本也要寫）。
4. 更新帳本：這天推到哪、`ties` 加一行（碰到主軸的哪一點）、新的伏筆、收掉的伏筆、新的地點物品、季節線那章的 `written`。
5. 如果這週是用備用週（沒有 `content/weeks/<這週>/`）：不用寫，只在帳本 `weeks` 記一下，跳到第三節開 PR（或沒有改就不開，AGENTS.md 第 6 節「沒有要改的就不改」）。

## 三、檢查、PR、合併、上線

1. `npm test` 全過（裡面有 `tools/week_check.cjs` 和它的測試）、`npm run build` 成功。
   - 檢查程式的警告（到期還沒收的伏筆、重複的新聞元素、季節線的章到週日還沒放書、沒寫 `ties`）照貼進 PR。
   - 檢查沒過：照錯誤改到過；04:50 還沒過 → 不合併，照第五節。
2. 照 `維護日誌/範本.md` 寫一篇日誌（類型「內容」，作者翊文，AI 寫 `Claude …（Claude Code 排程）`），跑 `npm run log:index`。
3. commit（最後一行 `AI: …`），推分支，開 PR。PR 寫：
   - 這次加了什麼（週包、這天的書、任務、特展、新的房間）。
   - 靈感來源表（週一）。
   - 檢查程式的警告。
4. **測試過就自己合併**（決定 0024、0031），合併就會自動部署（幾分鐘），05:00 前上線。合併前跟最新的 `main` 一起測過。
5. 合併後打開正式版看一下（`pepe-museum.web.app`）：這週的公告、今天的書。看不到就照第四節。

## 四、上線之後有問題

- 照決定 0024：開一個「把這次改動退掉」的 PR（`git revert`），測試過自己合併，再開 Issue 告訴翊文。
- 退掉之後遊戲自己會用備用週、備用的一天。

## 五、沒寫內容的時候（失敗、來不及、暫停）

- **週一**：沒有 `content/weeks/<這週>/`，遊戲自己用備用週（`content/weeks/備用/`，現在有「常青1」）。
- **其他天**：今天的檔沒有，遊戲自己用備用的一天（`content/weeks/備用/一天/`，現在 3 個）。
- 都要**開 Issue 告訴翊文**：哪一天、為什麼（檢查沒過的訊息、來不及、暫停）。
- 暫停的時候不用開 Issue，帳本 `weeks` 記一下就好。

## 六、可以加的、不能做的（`docs/每週劇情.md` 第五節、決定 0031）

可以（每天一兩樣，跟這週的線有關）：

- 已經過關的樓層多一間房間、可以找的東西、書頁（用遊戲已經有的房間種類組出來，`content/README.md` 第四節）。
- 今日特展的畫：用 `svg` 畫全新的（`content/README.md` 第九節），或用已經有的畫法換參數（`art`）。
- 書、每日任務、每週任務、公告的那一行。
- 獎勵只能用固定的東西（技能書、急救箱、材料），數量在預算裡。房間的獎勵可以多寫技能成長（`"skill": "偵查"`，一週最多 2 間，`content/README.md` 第四節）。
