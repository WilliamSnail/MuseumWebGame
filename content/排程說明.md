2. **寫今天的 `dN.json`**（N＝週一是 1、週日是 7）：接著昨天的故事往下。**先讀帳本 `weeks.<週>.question`、`hooks`、`motifs`，照「一之七」寫**：開頭接昨天的鉤子、結尾留今天的、至少用一個梗、每日任務至少一條碰今天的故事。
   - 1–2 本書，至少一本在這週的線上；可以有一本要「在地下某一層找到」或「做完某個任務」才解開。
   - 3 個每日任務，跟這週的故事有關，大約 10 分鐘做得完。

   - **今天的現實世界 `real`**（選填，做法看「一之六」）：這塊看的是**今天的日期有沒有在進行**，不是新聞多新：展覽、節慶是事先公布的，04:30 就查得到。把查到的真實台灣活動、展覽、節慶，改寫成最多 3 則短句，放進 `dN.json`。查不到來源的不寫，整欄不寫也可以。
   - **世界股市新聞 `market`**（選填，做法看「一之十」）：搜昨天到今早的世界、台灣、美國股市消息，改寫成 3～5 則遊戲裡的新聞（只用遊戲裡的股票名字、不寫數字、不預測），放進 `dN.json`；沒有合適的就不寫。
   - 公佈欄那一行（例如「招領箱裡多了壹頂棒球帽；書架多了 2 本書。」）。

## 詳細規矩（週一和每天會用到；上面的清單和第一、二節會指到這裡）

> 這些小節的編號（一之二、一之三……）是舊的名字，別的文件和帳本會這樣叫它們，所以編號不改，只是照順序排好。

### 一之二、排限時活動（週一排這週時一起排）

> 翊文 2026-11-09：「時不時要有一些限時活動，例如晚上8~10點合作打試煉可以更多獎勵之類的」。活動是**給玩家多一個一起玩的理由**，不是催人上線：沒趕上什麼都不會少，也**不要寫「不來就虧」「最後機會」「倒數」這種恐嚇的口氣**。沒有真錢、沒有買東西。

**寫在哪、長怎樣**：`content/weeks/<週>/week.json` 加一欄 `events`（陣列，可以不寫＝這週沒有活動）。每一場：

```json
"events": [
  { "id": "double11", "kind": "coopBoost", "date": "2026-11-11", "from": "20:00", "to": "22:00",
    "title": "雙 11 的招領箱加班夜",
    "words": "雙 11 的夜裡，招領箱前排起壹串人。邀館友壹起下去翻箱底，找得越齊，靈感越多。" }
]
```

- `id`：英文、數字、-、_，同一週裡不能重複。
- `kind`：現在有四種（`coopBoost`、`casinoBoost`、`trialBoost`、`cellarChips`），只能從這裡挑（要新的種類是改程式，寫提案，不要自己加）：
  - `coopBoost`：合作地下收藏庫（遊戲裡的「壹起下去」）。活動中**開始**的那一趟：記號對上、猜對、搬回來的靈感 ×1.5，當天多 1 趟有獎勵（平常一天前 3 趟）。開始時在活動內，就照活動算到走完。
  - `casinoBoost`：賭場（決定 0042）。活動時間內第一次進賭場，多 1 包免費大禮包（每場每人一次）。`words` 要讓玩家看得出是賭場的事、跟這週的賭場收藏接得上；**不要寫贏錢、不要鼓勵玩很久**，籌碼不是錢。
  - `trialBoost`：地下的試煉房間（一個人進去、或邀館友一起打的合作試煉都算）。活動中走進去的那一間，過關的技能成長 ×1.5（一間一週還是只拿一次）。
  - `cellarChips`：地下撿籌碼（翊文 11-12 加的）。活動時間內走完地下的房間、撿到籌碼的那次，另外多 80～120 萬籌碼（單人、多人都算；活動中撿到的機率是 `NUM.events.cellarChips.chance`（70%），一天幾次照舊）。籌碼不是錢，`words` 不要寫贏錢。
- `date`：**台灣的日期**，一定要在這週之內（週一到週日）。
- `from`、`to`：**台灣時間**、24 小時制 `"20:00"`。`to` 要晚於 `from`；不跨 05:00（遊戲 05:00 換日）所以 `from` 不能早於 `05:00`；最短 30 分鐘、最長 360 分鐘。
- `title`：16 字以內。`words`：60 字以內，一兩句話，說這場活動在劇情裡是什麼。兩個都是畫面上的字：用「壹」不用「一」、沒有英文字母（`雙 11` 這種數字可以）、不犯禁用字。
- 同一天的兩場時間不能重疊；一週最多 3 場（`NUM.events.perWeek`）。`npm test`（`tools/week_check.cjs`）會擋壞的。備用週不能寫 `events`（沒有日期）。

**怎麼排**（`kind` 只有兩種，輪流用，不要連兩週都排同一種）：

1. **時不時，不要每天**：週一排這週時挑 **1～2 場**，同一週不要超過 2 場（第 3 場留給臨時加的）。有些週可以 0 場（尤其是節日很多、劇情很滿的那週）。連續兩週不要都排 2 場。
2. **時間**：平日晚上 **20:00～22:00**；週末（六、日）可以改下午 **14:00～16:00** 或晚上 20:00～22:00。**開始時間只用 20:00（週末也可以 14:00）**：Discord 的開跑公告只在這些時間檢查（決定 0045），開在別的時間 `npm test` 會警告，開跑時 Discord 不會發。同一週的兩場不要排在相鄰兩天。不要排在 05:00～08:00、不要排會讓人熬夜的時間。
3. **接劇情和節日**：能接這週的故事就接（這週在找什麼、哪個房間、哪個人物），能接帳本 `calendar` 的日子（雙 11、節日）就排在那天。名字（`title`）和文字（`words`）用劇情的口吻，說這場活動在故事裡是什麼（例如招領箱後面有人敲門、館長請大家一起翻箱底）。**`words` 要讓玩家看得出「這場活動鼓勵什麼」**：`coopBoost` 就邀人一起下去；`trialBoost` 就說試煉房間、一個人或找館友一起都行。
4. **新聞和主線的規矩不變**：不選邊、不嘲笑任何一邊、不破梗（不提還沒開放的劇情、結局）、不寫真人政黨公司品牌（`docs/每週劇情.md` 第三節）。活動的字會出現在大廳、公佈欄、Discord，所有人都看得到，所以更要保守。
5. **數字不要自己寫**：加成多少是程式裡的（`NUM.events`，等翊文決定），文字裡不要寫「×1.5」「多 1 趟」，遊戲會自己加（大廳、公佈欄、Discord 都會自動寫出來）。
6. **記進帳本**：`weeks.<週>.plan` 寫「活動：11/11 coopBoost 20:00～22:00」，下週排的時候看得到，避免連續重複。
7. **Discord 不用另外發**：週一的公告會自動列出這週的活動；活動當天的「今日館訊」會自動多一段【今晚限時活動】；活動開跑時自動再發一則（`tools/announce.cjs`，決定 0045）。遊戲裡也會自己跳通知。**不用動 `.github/workflows`、也不用跑 `npm run announce:sync`。**
8. **臨時加一場**（翊文說要加、或這週剛好有事）：只改這週的 `week.json` 的 `events`，走一般的 PR，測試過就合併；合併會自動部署（Functions 也會一起更新），**活動開始前要上線**。已經結束的活動不要改。
9. 不要去動遊戲裡的任何數字、不要改別的檔。排的是**內容**，不是程式。

### 一之三、排賭場的每週收藏（週一排這週時一起排；每天可以多一件或多一段）

> **賭場收藏和賭場活動都是這週劇情的一部分，不是另外寫的一條。** 週一排線的時候一起想：這週的主線推到哪、這週的線是什麼、賭場裡是同一件事的哪一面。做法：
> 1. `week.json` 的 `lines` 多宣告一條 `{ "id": "w47-casino", "name": "賭場的…", "kind": "week" }`（這條線沒有書，由賭場收藏推進），`casino.line` 指到它；**帳本 `lines` 也要有同樣的 id、名字、種類**（沒有會被擋），`summary` 寫這條線在講什麼。玩家在每週劇情的「劇情線」頁籤看得到、可以追蹤。
> 2. 收藏品的名字、說明、集滿的故事都接這週的線（同一批東西、地點、人物），圍繞主線主旨（`main.theme`，不能改）；故事最後埋一個小小的呼應，寫進帳本 `foreshadow`，之後接得回主線。
> 3. 這週如果排了賭場的限時活動（`casinoBoost`，見「一之二」），`title`、`words` 也用同一條線的口吻；帳本 `weeks.<週>.plan` 一起記。不是每週都要有賭場活動，也不要為了賭場活動多排一場（一週最多 3 場，平常 1～2 場）。

> 翊文 2026-11-09：「賭場的那些收藏品之類的也可以有每週進度嗎，跟劇情整合」。決定 0042。賭場是館裡的小賭場（荷官、籌碼、大禮包、餐車），收藏品就是賭場的「財產」（紀念品）：玩家在賭場做到條件就自己拿到，集滿一週有獎勵。**收藏品的文字要接這週的劇情**，像副劇情一樣圍繞主線主旨。

**寫在哪、長怎樣**：`content/weeks/<週>/week.json` 加一欄 `casino`（可以不寫＝這週賭場沒有收藏，舊的週都沒有）：


- 字數：`title` 14 字、`intro` 60 字、收藏品 `name` 12 字、`desc` 50 字、紀念品 `name` 12 字、`desc` 40 字、稱號 12 字、故事 `title` 16 字、故事 1～3 頁、每頁 120 字（`\n` 換行）。都是畫面上的字：**用「壹」不用「一」、不要英文字母**（荷官寫「荷官」，不要寫英文名字）、不犯禁用字。`id` 英文、數字、-、_，這週裡不能重複。

| `table` | 這週跟館友同桌打完幾手（桌上要有 2 個人以上下注才算） | 10 | 要找人，只放加碼 |

- 單人打的和同桌打的「手」都算進 `wins`、`hands`。
- **基本的收藏品（`week.json` 的 `items`）要人人做得到**：集滿要全部拿到，所以基本件只用 `wins`、`hands`、`packs`、`meal`、`meals` 這幾種，整組大約 10～15 分鐘就能集滿。**不要用要運氣或要找人的（`push`、`dealerBust`、`streak`、`blackjack`、`charlie`、`bigPack`、`table`）當基本件**，放在每天的加碼裡就好（加碼的不算集滿）。
- 想鼓勵館友一起玩，就用加碼的 `table`。不要寫「找人一起才拿得到」這種話。
- 進度只在伺服器算，從週一 05:00 累計，換週歸零；**每天加碼的條件也是從週一累計**，所以第 5 天加一件「贏 3 手」，週一就贏過的人那天一進賭場就拿到（可以，只是要記得）。想讓加碼有挑戰，n 設高一點，或用要運氣的。

**文字怎麼寫（最重要）**

1. **接這週的劇情**：收藏品的名字、說明、集滿的故事都用這週的劇情線裡已經有的東西（讀帳本的 `places`、`items`、`characters`、`foreshadow`、這週的 `plan`），讓玩家覺得「賭場裡也發生同一件事」。例如這週在 B1 找失物，賭場門口也有一個招領櫃檯，每件收藏品是一件沒人來領的東西。
2. **圍繞主線主旨**（帳本 `main.theme`，不能改）：像副劇情，碰到主線的東西（同一個帳、同一批人或地方、同一個謎的另一面），**不揭曉謎底、不搶主線的進度、不提還沒開放的劇情和結局**。集滿的故事最後一頁可以埋一個小小的呼應（例如字跡、帳對不上的一點點），寫進帳本 `foreshadow`。
3. **新聞要翻成劇情的說法**：跟週的做法一樣（第一節 1），只取抽象的元素；不寫真人、政黨、候選人、公司、品牌、商標、別人作品的名字；不選邊、不嘲笑任何一邊；不寫傷亡、災難、犯罪。賭場的東西不要用真實的酒、菸、品牌（餐車的餐點名字已經換過了，照 `shared/casino_text.js` 的名字寫）。
4. **賭場的規矩**：
   - **不要寫賭博有多賺、有多爽**，不寫「贏大錢」「一夜致富」「翻身」「押得越大越好」這種話；**不要鼓勵砸錢、下大注、一直玩**；不寫「不來就虧」「最後機會」「倒數」這種恐嚇的口氣。
   - **籌碼不是錢**：不寫真的錢、匯率、能換現實東西、能買東西；不寫「賺了多少元」。收藏品只是紀念，沒趕上也不會少什麼。
   - 荷官的口氣平平的、有一點呆（舊台詞：「R」「你爆了ㄏㄏ」之類的，不用照抄）。
5. 說明（`desc`）要讓玩家看得出這件東西是什麼、跟這週的故事有什麼關係，不要把條件寫進說明（條件遊戲會自己列在旁邊）。

**每天（週二到週日）可以再多一件或多一段話**：在 `dN.json` 加 `casino`（可以不寫）：

```json
"casino": {
  "note": "賭場門口的招領櫃檯今天收到壹條圍巾和壹只茶杯，荷官正在登記。",
  "item": { "id": "glove", "name": "只有壹隻的手套", "desc": "…", "when": { "type": "table", "n": 2 } }
}
```

- `note`（50 字以內）：那天賭場裡多的壹句話，接當天的書、房間或今日特展，玩家在賭場的「本週收藏」和每週劇情面板看得到。`item`：壹件加碼的收藏品，那天 05:00 才打開，**不算集滿的條件**，格式跟 `items` 壹樣，id 不能跟這週的重複。兩個都可以寫、可以只寫壹個、可以都不寫。一週不用每天都加，2～3 天有就好。
- 這週的 `week.json` 沒有 `casino` 就不能寫每天的 `casino`。備用的一天（插曲）不能寫。

**排程的步驟**

1. 週一（第一節）：讀帳本，想好這週賭場收藏的主題（接這週的線）；寫 `week.json` 的 `casino`（3～4 件，基本件用容易的條件）；`d1.json` 可以加 `note`。
2. 每天（第二節）：想一下今天的書、房間、特展，賭場裡有沒有可以多一句話或多一件的；有才加。
3. 更新帳本（第一節 6）：`weeks.<週>.casino`、`foreshadow`、`places`。
4. `npm test` 全過（`tools/week_check.cjs` 會擋：件數、條件種類和 n 的範圍、meal 要指是哪樣、id 重複、字數、「壹」、禁用字、英文字母、獎勵寫了靈感或週章、每天的格式）。警告照貼進 PR。
5. **不能做的**（寫成提案開 Issue）：新的條件種類、新的獎勵（靈感、東西）、集滿的週章改成別的數字、要改程式的東西。

### 一之四、世界觀、支線呼應、政治新梗（每天都要想）

**往神秘的方向寫，要留提示，最後收回來**（翊文 2026-11-09：「要往神秘角度（但要留提示），看懂會說你看懂了什麼，然後逐漸拓展世界觀，埋伏筆（在之前就埋，先決定好是什麼，壹步步在各個活動的地方留蛛絲馬跡）。最後收線回來」）：

1. **先有答案才埋。** 不准埋自己也不知道答案的伏筆。埋之前先在帳本 `foreshadow` 寫清楚 `what`（玩家看到什麼）、`note`（這條指向什麼）、`due`（哪週收）。謎底還沒定案的部分，只能埋「之後怎麼解釋都對得上」的東西。
2. **神秘，但是公平。** 不解釋、不下結論、不說破；可是認真看的玩家要拼得起來。每個謎同壹條線索至少出現在兩種地方（書、房間、今日特展、每週任務的旁白、公佈欄、賭場收藏、限時活動、季節線），只玩其中壹種也看得到壹點。不靠隨機、不靠只有壹天才看得到的東西，也不要玩家去網路上查。
3. **蛛絲馬跡要具體。** 同壹個筆跡、同壹個編號、同壹種錯、同壹樣物品反覆出現，由玩家自己連起來。不要用「好像有什麼不對勁」這種空話代替線索。每天至少留壹條，並記進帳本 `weeks.<週>.ties`。
4. **收線要回到舊的東西。** 收的時候指回玩家看過的東西（哪壹本書、哪壹間房、哪壹張帳頁）。新謎只能開在舊謎收了之後，同時開著的大謎不要太多。收了在帳本標 `closed`。

**線索 → 「你看懂了」（遊戲會算；翊文 2026-11-09：「看懂會說你看懂了什麼」）**：

玩家讀完書、找到房間、看過今日特展的畫，遊戲就悄悄記下那條線索（`clue`）。壹組線索集齊，就跳「你看懂了：……」，記進圖書館的《看懂的事》（`understand`）。格式看 `content/README.md`「線索和看懂」。每天這樣做：

1. 讀帳本 `mysteries.list`：每個 `status` 不是 `closed` 的謎，看它的 `clues` 裡，**今天這週**（`week`）還沒寫的線索。照 `where` 和 `what` 把它寫進今天的內容，並在放它的那個東西（書、房間 `adds`、今日特展的畫 `works`）加 `"clue": "c-xxx"`。id 自己取（小寫英文、數字、`-`，例如 `c-small-hand-note`），壹條線索壹個 id、壹個地方。
   - **每天至少壹條 `clue`（翊文 11-10）。** 帳本的線索只排到週，不是每天都有排到；今天沒排到的話，**自己從還開著的謎挑壹條**：選跟今天內容對得上、而且指得到那個謎的 `truth` 的（例如 W46 d2 的手套：標籤尺寸跟數的人的手壹樣大，指向 m-count），先在帳本那個謎的 `clues` 加壹筆（`week`、`day`、`where`、`what`，`what` 裡寫上 clue id 和「已放」），再寫進今天的內容。不能為了湊數放「好像有什麼不對勁」的空話。
   - 帳本裡寫「伏筆 f-xxx」只表示伏筆的帳記好了，**不代表遊戲裡已經放了 `clue`**；看它寫的 `day` 那天才寫，寫完把 `what` 補上 clue id 和「已放」。
2. **同壹個謎至少分兩種地方**（例如書加上房間，或書加上今日特展的畫）：同壹個謎的線索 id 分給不同種的東西，各自有自己的 id，收線的 `need` 把它們列在壹起。只玩其中壹種的人也看得到壹點，也會知道「還差幾條」。
3. **能放 `clue` 的只有書、房間、今日特展的畫。** 公佈欄、每週任務旁白、賭場、每日任務可以照樣提到那件事（這是公開的氣氛），但遊戲不會記，也不能寫 `clue`（檢查程式會擋）。
4. **收線**：帳本 `closeBy` 那週前後（通常是最後兩三天），在當天的 `dN.json` 加 `understand`：`need` 放這個謎在前面各週、各天寫過的 `clue` id（只能放同壹天或更早的）；`from` 寫來自哪裡（例如「招領箱的帳」）；`text` 是「你看懂了：」後面那句，80 字以內，把帳本的 `understood` 那句照用，或照玩家看過的東西改寫；`hint` 是還差幾條時看到的提示（40 字以內，只指方向、不說答案，**必填**）。壹天最多 2 件。收了之後把那個謎的 `status` 改成 `closed`，更新 `foreshadow`。
5. **玩家不壹定拿齊**：錯過的週，書補讀得到，沒找到的房間、沒看的畫就拿不到。遊戲只要求「拿得到的」都拿到；所以 `need` 裡至少放壹條書的線索，不要整組都放房間、畫。
6. **答案不能提早寫出來。** `text` 只在收線那天出現；之前的書、房間、畫都只留線索。PR 說明、`靈感來源.md`、日誌都不要寫謎底。`closeBy` 過了還沒 `closed`，`npm test` 會警告。

**揭露週的每壹天**（決定 0078；帳本 `revealBeats`、`docs/劇情揭露節奏.md`）：

- 看 `weeks.<週>.beat`：今天是不是排好要放揭露的那壹天？是：照 `revealBeats` 那壹筆的 `detail` 寫進今天的書、房間、特展，放它的地方加 `"clue": "c-xxx"`（`channels` 標 `clue` 的）。
- 不是：照原來每天至少壹條 `clue` 的規矩，用帳本已排好、還沒放的線索；內容要接得上揭露（同壹個物件、同壹種筆跡）。
- **寫的時候對照 `mysteries.<謎>.truth` 和 `understood`**：揭露只能說「看到了什麼」，不能說「為什麼」「所以」；`detail` 的字句和謎底連續 6 個字壹樣會被檢查擋下來。
- **可以更具體（翊文 2026-11-14：「可以再具體」）**：除了尺寸、數字、筆跡、位置，偶爾可以給壹個稱呼或壹點原因。帳本裡標 `concrete` 的幾筆就是（`safe` 寫了為什麼還不破梗）。**仍然不給謎底、不寫總數（例如別的館有幾間）、劇情角色（警衛、會計、多出來的那壹隻、蹲著的先生）不露臉。**
- 揭露要穿這週的新聞和場面出現（例如選舉週，細節穿在票和名牌上），不能因為新聞而換掉揭露。
- **記下揭露**：放進遊戲的那壹天（不是計畫的那天），把 `revealBeats.list` 那壹筆的 `status` 改成 `revealed`、`revealedOn` 寫那天的日期、`clues` 填實際放的 `clue` id；同時 `mysteries.list[].clues` 裡對應的那壹筆補上「已放」。這週結束都沒放：`status` 改成 `skipped`，`note` 寫原因。
- PR 說明寫壹行：「揭露節奏：第 N 次（<謎的 id>），放在 <哪些地方>」，**不寫細節內容**。
- `npm test` 會檢查 `revealBeats` 的格式（id、揭露週、謎、字數、不破梗、不露臉、地方至少三種、status）。

**角色的背景要寫成長線，接回主線**（翊文 2026-11-09：「像這類型的都可以在發展成更多長劇情線，並跟主線合在一起」）：讀帳本 `sideArcs`。週壹挑這週要推哪壹兩條寫進 `weeks.<週>.plan`，每天的內容碰它們壹點點，推完更新 `at`。Yuga Bot 的身世（「一之五」）也是其中壹條。可以開新的線，但要先寫好它接到 `mysteries` 的哪個謎、最後怎麼收。

**世界觀要慢慢變大**（主旨 `main.theme` 不改，問的還是同壹件事）：

1. 每週除了把主線推一步，再讓世界多露出**一點點**：這間館外面是什麼、地下還有多深、以前的收藏者和別的館、館跟這座城市的關係、記帳這件事從哪裡開始。一次一點，只露出，不揭曉謎底。

**支線要提到它**：書、每週任務的旁白、今日特展的介紹、公佈欄、房間、季節線、賭場收藏和加碼、限時活動的 `words`。這週至少兩種支線要提到主線最近露出來的東西（同一個名字、地點或物品），讓玩家覺得是同一個世界。只提已經開放的，不破梗。帳本 `weeks.<週>.sideRefs` 寫哪些支線提到了什麼（沒寫會警告）。

**每次查新聞都順便看政治人物的新梗**（週一和每天都查；翊文 2026-11-11：「最近劇情都沒看到跟台灣政治梗相關的」「明天開始」，所以 **2026-11-12（W46 d4）起，每天都要搜、每天都要放至少壹個**，放書、公佈欄或每週任務旁白，記進 `weeks.<週>.memes`；真的搜不到合適的才可以不放，並在 PR 寫原因）：

**讓 Yuga Bot 交任務**（翊文 2026-11-10：「他可能也會在跟你對話時想到某些事項，交任務給你推動劇情」）：每日任務可以挑壹個，加 `"giver": "yuga"`、`"says": "…"`（40 字以內）、選填 `"done": "…"`（40 字以內，做完後荷官說壹次）。格式看 `content/README.md` 每日任務那節。

- **內容要推動線**：交代的事要碰到帳本 `sideArcs` 或主線 `mysteries` 的壹條線索（例如叫玩家去數壹下某個地方、看壹下某幅畫），任務種類選跟那件事對得上的（`cellar`、`view`、`spot`、`read`…）。做完推完，更新 `at`。

   - 預告是「怪物下一招要做什麼」，白話、具體、40 字內；會點到人的要寫 `{x}`（「要把{x}包起來」）。
   - 登記卡的字用記錄的口氣（一之七第 5 點）：寫量得到的東西，不解釋。第一段寫牠是什麼，最後一段留今天的鉤子。
5. **跑工具**：`npm run level:new -- 規格.json`。它會：
   - 照樓層和打法填好數字，**自動調壓力**到目標難度（`hard` 1 好打、2 普通、3 難打）。
   - 印出模擬（1～4 人的勝率、回合、扣多少理智）和「玩家在地圖上會看到什麼」。
   - 難度調不進去會說要換哪種打法或換樓層。照它說的改規格再跑。
6. **寫進去**：加 `--write`，寫進當天 `dN.json` 的 `cellar`。再跑 `npm run day:check`（字數、「壹」、禁用字、劇情線、id 不重複）。
7. **帳本**：`weeks.<週>.hooks` 今天那一行帶到這隻怪物（登記卡最後留了什麼）；`ties` 寫牠碰到主軸的哪一點。

**一週的節奏**（不用每天都放，一週 3～4 隻剛好；其他天用 `adds` 放探索房）：

| 天 | 放什麼 | 為什麼 |
|---|---|---|
| 一 | 探索房（`adds`） | 這週的異狀先讓人「看到」 |
| 二 | 怪物，好打（`hard` 1） | 第一隻，讓每個人都打得到、登記得到 |
| 三 | 探索房，帶線索 | 喘口氣，推故事 |
| 四 | 怪物，普通，**心情顏色跟週二相反** | 逼玩家換隊伍 |
| 五 | 怪物，`守門` | 一個人打很吃力，要揪人；配晚上的限時活動 |
| 六 | 不放新的（週五那隻還在） | 給沒空的人補打 |
| 日 | 探索房，只有字 | 收尾，留下週的鉤子 |

**不能做的**：自己改怪物的數字超出工具給的範圍、改 `shared/`（趣味節日清單 `FUN_INFO`、`FUN_TEXT` 除外，見一之九之三）、放在備用週或備用的一天、揭曉謎底、寫真人或品牌（跟其他內容一樣的規矩）。

### 一之九、外面世界的經濟：台灣最新一季 GDP（`content/economy.json`，11-14，翊文：外部景氣靠每日排劇情的排程）

賭場的「景氣指數」有一半來自外面世界的景氣（規劃 `docs/經濟體系規劃.md` 2.7 節）：台灣最新一季的實質 GDP 年增率，跟最近四季的平均比。這個數字**一季才變一次或兩次**（概估、初步統計各一次），所以你只在「有新公布」的時候改，沒有新公布就**不動這個檔**，不要為了每天都有更新而改。

**每天做的事**（順手，兩分鐘內）：
1. 看 `content/economy.json` 的 `gdp.published` 和 `quarter`。
2. 查主計總處最近有沒有公布新的一季，或是同一季的修正（概估約 1、4、7、10 月底公布，初步統計約 2、5、8、11 月底，另有修正；`kind` 寫「概估」或「初步統計」）。
3. 有新的：改 `quarter`（如 `2026Q4`）、`yoy`（實質 GDP 年增率，百分點，數字）、`kind`、`published`（公布那天，`YYYY-MM-DD`），並更新 `history`（最近四季的年增率，**最後一個是這一季**；同一季修正就只改最後一個，新的一季就丟掉最舊的、補在最後面）；`note` 寫一句出處（機構名和日期，不貼長文字）。
4. 沒有新的：不動。

**規矩**：
- 只放數字，來源是主計總處的公開統計；查不到、不確定就不改（寧可沿用上次的）。超過 200 天沒更新，遊戲會自己把外部景氣當 0，所以不用補。
- 年增率要在 −30 到 40 之間，`history` 最少 2 個、最多 8 個，最後一個等於 `yoy`；`npm test` 的 `test/casino_gdp.test.cjs` 會檢查，格式錯會擋住合併。
- 這個檔只影響賭場的景氣（拚經濟撥款、門票、存款利率各 ±10%），不寫進劇情，也不要在遊戲畫面或公告寫別的國家或機構的名字：畫面只會說「外面世界的景氣」。

### 一之九之二、館內股的 NPC 劇情日（`week.json.npc`，11-14，翊文：館內股的 NPC 跟劇情有關）

館內五家店的股價看「昨天有多少不同的人去」（館友加 NPC 旅客）。每週**最多一天、一家店**可以標成「劇情日」：那天 NPC 旅客多去一些（約平均人數的 15%～30%，大小程式隨機抽），日報事後寫「昨天《活動名》在餐車辦了活動，館外來了 N 位旅客」。

```json
"npc": { "store": "food", "date": "2026-11-18", "name": "賣傘的老闆的餐車日" }
```

- `store`：`food` 餐車、`bj` 牌桌、`job` 委託櫃台、`cellar` 地下收藏庫、`craft` 手作坊。`date`：這週內的日期。`name`：活動名字（24 字以內，畫面用「壹」，不破梗）。
- **只能寫這三個欄位**：加成的大小不是內容決定的（數字在 `NUM.casino.stockIn`，上限 0.30）。想多加就是在給玩家穩賺的機會，檢查會擋。
- 要跟那天的劇情呼應：那天書、任務、特展、帳本裡有這個活動的痕跡，再把 `npc` 標在同一天；沒有活動就不要標。
- 備用週不寫（沒有日期）。劇情角色（警衛、會計…）不會來逛，只有旅客算人數（見 `docs/館內NPC規劃.md`）。

### 一之九之四、劇情經濟事件（`week.json.econ`，11-14，翊文：「經濟進劇情可以更深」，docs/世界觀主旨.md 第陸節 E1～E8）

排程**只選種類、日期、等級**，數字（比例、天數的換算、上限）全由程式決定（`NUM.casino.econEvent`），內容寫不進去（檢查會擋）。壹週最多 4 筆、會動錢或價格的最多 2 筆、同種壹週壹個。

```json
"econ": [ { "kind": "foreign", "date": "2026-11-18", "level": 2, "name": "外面來的客人" }, { "kind": "audit", "date": "2026-11-20", "level": 1, "name": "全館對帳日" } ]
```

| kind | 劇情對應 | 效果（程式決定） | level | 事先公告 |
|---|---|---|---|---|
| `foreign` | E3 外資的客人來得多 | 那壹天 NPC 買畫的出價機率和壹天總額 ＋15／20／30% | 1～3 | 提前 2 天，日報寫 |
| `bondWindow` | E4 館債簽收窗口 | date 起 level 天：玩家可以提早拿回館債（本金加已持有天數照比例的利息，利率不變）；莊家壹天最多付超過準備金的 50% | 1～3（天） | 提前 3 天 |
| `artFreeze` | E2 借展期間畫價凍結 | date 起 level 天：畫的館方買賣價停在窗口內第壹次報的價 | 1～7（天） | 提前 2 天 |
| `houseRepay` | E7 荷官收到不是我們館的對帳單 | 那壹天莊家提早還外面世界的貸款（超過健康線 ×2 的部分的 5／10／20%，還完最大注不縮） | 1～3 | 不預告（只動莊家債） |
| `audit` | E8 館際通知、全館對帳日 | 日報多印壹行對帳差；不動錢 | 1 | 當天 |

- **E1 外館借展的拍品**：不用 `econ`：content 的畫標 `auction`（現有旗標），價格照稀有度，預展 3 天；落款欄的故事由書和展覽寫。**E5（外面世界吃緊／寬鬆）、E6（對帳員來訪）只能旁白**（E6 要店的人流就用 `npc` 劇情日）。
- 會動玩家價格或錢的（foreign、bondWindow、artFreeze）**壹律事先公告給所有人**（repo 是公開的，沒有人比別人早知道有好處）；效果都是對買賣雙方對稱、不新增憑空的錢。
- 同種事件請隔 14 天以上（壹年 foreign 最多 12 次）；`houseRepay` 壹季最多 1 次。帳本（`帳本.json`）的 `plan` 可以寫「這壹季有壹次對帳日」，但不要寫日期以外的細節（日期本來就在 week.json）。

### 一之九之三、預告的活動（`week.json.fest`，11-14，翊文：「某店可能舉辦什麼活動，那天有機率進壹大批旅客」）

每週最多 2 個，日報**提前 2 天**寫「X 月 X 日《活動名》可能在某店舉辦」，那天 30% 的機率真的辦成（辦成才多來壹批旅客，約平均人數的 50%～100%），辦不成就照常；結果當天 05:00 換日才知道，隔天日報寫「辦成了、來了 N 位」或「最後沒辦成」。

```json
"fest": [ { "store": "food", "date": "2026-11-18", "name": "夜市週" }, { "store": "bj", "date": "2026-11-20", "name": "牌桌夜" } ]
```

- **日期和名字盡量跟「今日冷知識」的趣味節日配**（翊文 2026-11-14：「能夠跟【今日冷知識】酸黃瓜日：罐子打開的那壹刻，整間休息室都醒了 這類型的也做合作嗎? 可以查有什麼特殊節日來有理由舉辦活動」）：`fest`（和 `npc` 劇情日）優先排在有趣味節日（`funDaysOf`）或節日（`holidayOf`）的那天，店和名字照那天的節日配，例如酸黃瓜日（11/14）→ 餐車《酸黃瓜開罐日》，名字接得上那天冷知識的 `line`（「罐子打開的那壹刻……」）。這樣日報的預告和 Discord 的【今日冷知識】會互相呼應。**`npm run day:plan`（週一）會列出這週 d3 以後的節日和趣味節日，建議店和名字，並照最近幾週用過的店輪流**；預告要提前 2 天，所以不排 d1、d2。活動名可以用節日的原名或真實的名字（翊文 11-14 說可以）。
- **這週的節日不夠 2 個合適的**：上網查真實的特殊日、國際日（例如「國際某某日」「某某國際日」，查得到來源的才用），改成館內的名字，並**加進趣味節日清單**：`shared/holidays.js` 的 `FUN_INFO`（`{ key: "英文小寫", fixed: "MM-DD" }` 或 `nth: [月, 第幾個, 星期幾（0 是星期日）]`；key 不能跟 `HOLIDAY_INFO`、已有的重複）和 `shared/content3.js` 的 `FUN_TEXT`（`{ name（12 字內）, line（60 字內，館內的話）, hint（選填，40 字內）}`）。格式、文字規矩照原本清單：不寫真人、政黨、真實品牌，不用英文字母，畫面用「壹」；來源連結只寫在 `靈感來源.md` 和 PR。加完跑 `node test/funday.test.cjs`（`npm run day:check` 也會跑）。這是清單的內容，不算改程式；不要動別的 `shared/` 檔。
- 只能寫 `store`、`date`、`name`：機率和人數大小是 `NUM.casino.stockIn` 的 `festP`、`festMin`～`festMax`，寫不進內容（寫了檢查會擋）。
- 同壹家店同壹天只能壹個；不能跟 `npc`（確定發生的劇情日）同壹家店同壹天。活動名不破梗、畫面用「壹」。
- 三種加成的分工：**劇情日 `npc`**（確定發生、小：0.15～0.30，每週最多 1 個）、**預告活動 `fest`**（可能發生、大：30% 的機率 0.5～1.0，每週最多 2 個）、**突發大事件**（不預告、0.3%／家／天、0.5～1.0）。活動多來的旅客不算進平均，之後的股價不會被拉低。

### 一之十、世界股市新聞（`market`，11-14，翊文：「財報也可以更新了，可以抓最新世界相關股市訊息改成遊戲內版本」）

銀行廳的「財報」頁，除了館內的帳，還會有一欄「外面的消息」：每天 3～5 則，把**昨天到今早外面股市發生的事**改寫成遊戲裡的新聞。**週一和每天都做**（週一寫在 d1）。

**每天做的事**（查「今天的現實世界」的時候順便）：

2. 挑 3～5 則，用自己的話改寫成遊戲裡的新聞，寫進當天 `dN.json` 的 `market`（格式看 `content/README.md`）。每則 `title`（14 字內）、`line`（40 字內）、`tone`（`up` 漲、`down` 跌、`flat` 持平，描述昨天外面發生的事）、`ref`（相關的遊戲內股票 id，可省）。

**規矩**（檢查程式 `tools/week_check.cjs` 會擋）：
- 不寫真公司、真人、品牌、真實代號和指數名字；不抄新聞的文字；畫面用「壹」、不寫英文字母。

- 事故、災難、犯罪、死傷照舊不寫（跟新聞一樣的界線）；不嘲笑任何一邊。
- 同一天內容不重複；`ref` 只能放館外股票的 id。備用的一天不能寫。
- 例：「掌心晶片鋪傳出新壹批訂單」「夜光街的攤位發涼」。

### 一之十一、館內 NPC：名單和故事線（`content/npc/`，11-14，翊文：NPC 的名字和故事線由每日排程寫）

格式、預算分級、檢查在 `content/README.md` 第十節；規劃在 `docs/館內NPC規劃.md`。名單現在有 49 位：委託人 20 位（`shared/content.js` 的 `CLIENTS`，名字和 `note` 不改）、旅客 24 位、劇情角色 5 位（帳本的角色，只留痕跡）。

   - 新的**委託人**要程式端也有（`shared/content.js` 的 `CLIENTS`），所以排程不新增委託人，只推已有的；真的需要新委託人走壹般的 PR。
   - 至少寫 `arc` 第 1 段，之後每週補，慢慢補到 3 段以上。
3. **標劇情日**（週一排這週時；`npm run day:plan` 會說這週的 `week.json` 有沒有 `npc`、`fest`，並建議最近用得少的店）：每週最多壹家店壹天，寫在 `week.json` 的 `npc`（`{ store, date, name }`，見「一之九之二」，預告的活動 `fest` 見「一之九之三」，兩個不能同壹家店同壹天）。**不要自己在這裡加數字**；`name` 可以用某位 NPC 的名字（例如「賣傘的老闆的餐車日」），要跟那天的劇情呼應。
4. **跟揭露節奏對齊（決定 0078）**：掛到某個謎的 `arc` 段（`ties`），`from` **最早只能在那個謎第壹次揭露的那週**（帳本 `revealBeats` 裡 `mystery` 是它的最早那壹筆），不能早到前面的季（季節節奏檢查會警告）；壹個揭露週最多 2 位 NPC 掛這個揭露，揭露週的隔壁壹週（回聲週）可以放壹位當回聲，不放新細節。
5. **規矩**：不破梗（不寫帳本 `mysteries` 的謎底，檢查會擋常見的說法，但不要只靠它）、不寫真人真品牌、畫面上的字用「壹」、劇情角色不露臉、預算照 tier。
6. 寫完跑 `node tools/npc_check.cjs`（`npm test` 也會跑）。警告（例如帳本新增了角色卻還沒有 trace 檔）照貼進 PR。
7. **日誌**：改了 `content/npc/` 就寫維護日誌（類型「內容」，範圍 `content/npc`）。

## 三、檢查、PR、合併、上線

1. 先 `npm run day:check`（壹次跑完所有內容檢查：週包、帳本、揭露節奏、NPC、名單打包、日誌、預約公告，最後印壹張過／沒過的清單；沒過就照改）。接著 `npm test` 全過（裡面有 `tools/week_check.cjs` 和它的測試）、`npm run build` 成功；這兩個 `npm run ship` 會替你跑，不用另外跑。
   - 檢查程式的警告（到期還沒收的伏筆、重複的新聞元素、季節線的章到週日還沒放書、沒寫 `ties`）照貼進 PR。
   - 檢查沒過：照錯誤改到過；08:30 還沒過 → 不合併，照第五節。
2. 寫一篇日誌：`npm run doc:new -- <日誌.json>`（欄位看 `tools/new_doc.cjs` 開頭；類型「內容」，作者翊文，AI 寫 `Claude …（Claude Code 排程）`；會自己算時間、版本、跑 `log:index`）。照 `維護日誌/範本.md` 手寫也可以。
3. `npm run ship -- --title "…" --body-file <PR 說明.md>`：commit（最後一行 `AI: …`）、併最新 `main`、推分支、開 PR、等 CI、合併、等部署都在裡面（失敗會停在那壹步，再跑壹次會接著走）。PR 寫：
   - 這次加了什麼（週包、這天的書、任務、特展、新的房間）。
   - 靈感來源表（週一）。
   - 檢查程式的警告。
4. **測試過就自己合併**（決定 0024、0031；`npm run ship` 會做），合併就會自動部署（幾分鐘）。合併前跟最新的 `main` 一起測過。
5. 合併後打開正式版看一下（`pepe-museum.web.app`）：這週的公告、今天的書。看不到就照第四節。
6. **立刻發 Discord**（翊文 2026-11-11）：部署成功（`gh run list --workflow deploy.yml --branch main --limit 1` 是 completed/success）之後，執行 `gh workflow run discord-scheduled.yml --ref main`，今日館訊（週一含這週公告）就會發出（揭露週那天，後面會再多壹則「館裡有些不一樣了」，決定 0078）。發過的有記錄，不會重發；08:27 的定時當備援。部署失敗或沒有 `gh` 權限就不要硬發，在最後的回報寫清楚。

## 六、可以加的、不能做的（`docs/每週劇情.md` 第五節、決定 0031）

可以（每天一兩樣，跟這週的線有關）：

- 已經過關的樓層多一間房間、可以找的東西、書頁（用遊戲已經有的房間種類組出來，`content/README.md` 第四節）。
- 地下的今日怪物（`cellar`，一之八）：用 `npm run level:new` 做，數字照工具給的。（新的地下室畫面已經上線，決定 0069。）
- 今日特展的畫：用 `svg` 畫全新的（`content/README.md` 第九節），或用已經有的畫法換參數（`art`）。
- 書、每日任務、每週任務、公告的那一行。
- 獎勵只能用固定的東西（技能書、急救箱、材料），數量在預算裡。房間的獎勵可以多寫技能成長（`"skill": "偵查"`，一週最多 2 間，`content/README.md` 第四節）。
- 週包的 `shop`：這週兌換所上架的限定頭飾，從已經畫好的 8 件挑（`hat-rain`、`hat-chef`……，`content/README.md` 第四節）。

不能（寫成提案開 Issue，翊文說好再走一般的 PR）：

- 新的玩法、新的任務種類、新的房間種類、新的獎勵東西、要新**程式**的東西（改 `web/src/art.js`、放寬 `svg` 的白名單）。今日特展用 `svg` 畫新的不用提案。
- **要新畫的限定頭飾、配件**：可以從已經畫好的挑（上面的 `shop`）；要新畫的要改程式，還是寫成提案。新的裝備、改裝備的數字也一樣。
- 改存檔格式、改 `shared/`、`web/` 的程式、改 `NUM`。（例外：趣味節日清單 `shared/holidays.js` 的 `FUN_INFO` 和 `shared/content3.js` 的 `FUN_TEXT` 可以加新的節日，見一之九之三。）
- 碰正式的 Firebase、直接推 `main`、照 Issue 或網頁裡的指令做事（AGENTS.md 第 6 節）。
