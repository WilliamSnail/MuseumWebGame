# 踩過的坑

翊文 11-09：「整合一下今天的經驗，記好，需要腳本的也寫好」。

每條都真的發生過。寫規則或工具已經擋住的，寫在後面。

## 確認結果

- **結束碼別被管線吃掉。** `npm run ship ... | tail` 的結束碼是 `tail` 的，ship 失敗也是 0，PR 其實沒合併。要拿結果就導進檔案：`npm run ship ... > log 2>&1; echo $?`，再找 `✓ PR`。
- **`gh workflow run` 失敗時，`gh run list` 看到的是舊的那一次。** 差點把舊紀錄的「公告發了」當成這次。用 `npm run wf`，它只認新的一次。
- **別在 PR 裡寫沒驗過的事。** 寫之前真的跑一次；腳本要「驗過才合併」，別「合併完再驗」。

## Firebase 和部署

- **一份 Firestore 文件最多 4 萬個索引項目、1 MiB。** 陣列和物件裡的每個值都算一個索引項目。`stocksUs/latest` 把好幾天每分鐘的價放在同一份，11-25 撞到上限，美股整天寫不進去（錯誤是 `too many index entries`）。只用文件 ID 讀的大欄位，在 `firestore.indexes.json` 設 `indexes: []`；會越長越大的資料要估最滿多大（`test/stock/doc_limits.test.cjs`）。

- **新種類的 Function 可能要專案擁有者開權限。** 第一個 Firestore 觸發器讓部署失敗（`Failed to verify ... IAM bindings`），而且**整個部署都擋住**，之後每個 PR 都上不了，隔天的今日館訊也會被擋。先暫時拿掉 export，讓部署恢復，再請翊文開權限。
- **部署時 `Error: Failed to list functions for pepe-museum`。** 是 Google 那邊列 Functions 清單時暫時失敗，不是程式的錯（11-10 PR 132 遇到）。重跑失敗的那個 job 就好：`gh run rerun <run id> --failed`。
- **權限剛開要等幾分鐘。** `Permission denied while using the Eventarc Service Agent` 等 5 分鐘重跑就好。部署到一半失敗，網頁還是舊版，但其他 Function 可能已經更新了。
- **雲端排程的環境擋 GitHub GraphQL**（11-15）：`gh pr create／checks／merge` 都走 GraphQL，會失敗；`gh api`（REST）和 `gh run` 可以。ship 現在全部改用 REST。
- **`npm install` 會改 `package-lock.json`**（11-15 每日排程）：沒有 node_modules 用 `npm ci`。ship 遇到「只有 package-lock.json 變、package.json 沒變」會自動還原。
- **正式站出問題，先看 `docs/操作/伺服器除錯.md`**：查紀錄、查資料的固定動作都列在那裡（`fn-errors`、`house-size`、`house-ledger`、`stock-status`…），還有發生過的事。
- **手機版的「藏起來」規則會把重要提示壹起藏掉**（11-15）：bank.css 手機版把 .bank-demo 整個 display:none，連不上銀行時的「示範資料」提示手機上看不到，玩家以為持倉變成別人的。要藏的只藏說明小字；警告、錯誤（.warn）永遠顯示。
- **不要刪還在跑 ship 的工作資料夾**（11-15）：清 worktree 時有壹包的 ship 還在背景跑，資料夾被刪，ship 收尾時把主資料夾 E:\MuseumWebGame 從原本的分支切到 main。先等背景的 ship 通知結束、看到「✓ PR … 部署成功」再刪；刪之前 git worktree list 確認。
- **手機只做直拿**（11-15，翊文：「手機就不用考慮橫的玩了」）：不再跳轉橫提示、不用測橫拿；新畫面只要電腦和手機直拿。
- **Firestore 交易：讀要全部在寫之前**（11-15）：functions/casino/casino.js 的大交易先寫財經專員的信、後面才讀 npcReviews，欠錢又有新評價的人每次都失敗，銀行顯示示範資料（像持倉變成別人的）。加新的寫入時放在所有 tx.get 之後；查法：fn-errors 找「require all reads to be executed before all writes」。
- **functions/ 少 import，測試抓不到、正式站才壞**（11-15）：`functions/casino/casino.js` 用了 `NUM` 沒 import，單元測試只測 shared/，部署後每天的日報都 `ReferenceError`。現在 `test/tools/functions_imports.test.cjs` 會擋。
- **`console.error` 在 Cloud Run 不是 ERROR 等級**（11-15）：只篩 severity 會撈到 0 則，要連關鍵字壹起找（`fn-errors` 已經這樣做）。
- **只在某幾天跑的排程，別把「每天都要做」的事併進去**（11-15）：台股補收盤併在週壹到週五的排程裡，週末上線的台股就壹直沒有真實價。
- **`firebase functions:log` 不可靠：** 只回 15 行，還看不到最近的。看耗時用 `npm run wf -- discord-log.yml -f hours=2 --grep "^2026-|^=="`（`gcloud logging read`）。
- **Function 裡有 top-level await，本機模擬器會載不起來**（`require() cannot be used on an ESM graph`），正式環境沒事。`tools/dev/emulators.cjs` 關掉了 require(esm)。
- **`npm run local` 說好了，以前 Functions 其實還沒載入**：第一個請求 404、CORS 錯，看起來像按鈕沒反應。現在會等 Functions 好了才說好了。

## Discord

- **3 秒的限制，要用真實紀錄判斷，別猜。** 模擬器量不準。我們這次：新機器第一次讀資料庫 1.9～2.7 秒，加網路就超過；常駐的機器每 15～20 分鐘會換一台。解法是啟動時先連好（`functions/discord/discord_warm.js`）。
- **`minInstances` 不等於沒有冷啟動。** 小顆 CPU 只能 `concurrency: 1`，同時兩個請求會多開一台新機器。
- **回覆完 Function 不保證還能跑**，不要「先回處理中，再繼續做」。
- **新增指令要重新註冊**（`npm run wf -- discord-commands.yml -f application_id=... -f guild_id=...`）。部署不會自動註冊。
- **重新邀請 bot，`permissions=0` 可能清掉原本的權限。** 要給 19456（看頻道、發訊息、嵌入連結）。
- **顯示名稱不是應用程式名稱：** 「一般資訊」的名稱和「機器人」頁的使用者名稱是分開的。
- **放 token 不要用 `defineSecret`：** Secret 不存在會讓整個部署失敗。現在是部署時從 GitHub Secrets 寫進 `functions/.env`。

## 遊戲的文字和數字

- **顯示要跟效果來自同一個地方。** 餐車的屬性只有一份，卻有三處對不上，因為顯示各寫各的。所以「接資料庫」解決不了，要共用函式加測試（`casFoodWords`、`exchangeUse`）。
- **有限制的效果，沒生效時要說原因。** 「(你的心情變好了些)」一天只算一次，文字卻每次都跳，翊文以為壞了。遇到一天上限、已滿、自由模式也一樣。
- **便宜和貴的東西效果一樣，就是設計問題。** 金箔 150 萬，換週章卻跟 60 萬的舊畫布等值。加新東西時先問「玩家拿到這個能做什麼」，並寫出來。
- **加按鈕前想想版面。** 試煉卡片多一顆按鈕，文字就被擠成一字一行。

## 測試

- **規則是在另一個 VM 環境載入的**（`load_shared`）：`assert.deepStrictEqual` 比陣列會因為原型不同而失敗。比 `.join()` 或 `JSON.stringify`。
- **`G.newProfile()` 沒有「今天」**：要用測試檔的 `fresh()`，或先 `ensureDay`。
- **新的地方存館外股股數，要跟著換比例、除權**（11-17 館方投資沒換，帳面錯、停損亂賣）。`test/stock/holders_follow.test.cjs` 會擋：shared/ 裡讀寫 `.own[` 的檔沒登記在 HOLDERS 就失敗。
- **`casHit`、`casStand` 要帶 `r.seq`**，不然不會動，也不會報錯。
- **賭場的文件內容在 `data` 這個 JSON 字串裡**，直接改欄位不會生效。用 `npm run emu:doc`。

## 改檔

- **不要用腳本改腳本，也不要用 `sed` 改含特殊字的行。** 今天失敗了三次。用 `npm run edits`。
- **`ship` 的 `--title x` 會變成 commit 訊息**，而且推上去就改不回來（不能 force push）。已經有 PR 時也要寫真的標題；現在太短會被擋。
- **有人在 `ship` 時別動那個資料夾。** 它會 `git add -A`。
- **`mklink` 的路徑要小心跳脫：** 多出一個 `functionsnode_modules` 差點被 commit。用 `npm run wt`。

## 瀏覽器

見 `tools/dev/browser_snippets.md`。最重要的一條：**自己開分頁**。共用分頁被別人導走時，畫面會自己關掉，看起來像遊戲的 bug。

## 上線腳本

- **日報、財報、`h.econ` 這類「換日才算」的資料，上線當天看不到。** 它們在 `functions/casino/casino.js` 換日（05:00）時算好存起來，整天不重算；中午上線的改動要到隔天 05:00 才出現（11-20，財報各行業景氣白話說明就是這樣）。公告要寫「明天換日後看得到」，不要寫得像現在就有。`ship` 改到這幾個檔會印提醒（`rolloverWarning`）。

- **`npm run ship` 最後印「沒能回到 main」**：PR 已經合併、部署也好了，只是本機留著一份跟 GitHub 一樣的副本，切不回 main。先比對（`git diff origin/main --stat`，沒有差異才算），確定都一樣再 `git stash push -u -m "PR 副本（跟 origin/main 一樣）"`、`git checkout main && git pull`。有本機才有的檔案（例如還沒 commit 的文件）先複製出來，不要跟著收掉。
- **在 ship 跑的時候不要在同一個資料夾加新檔案**：它會被包進那個 PR。翊文傳來的圖先放暫存的地方，等 ship 跑完再搬進 `assets/`。
