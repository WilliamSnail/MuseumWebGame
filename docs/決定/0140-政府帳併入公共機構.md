# 0140 政府帳併入公共機構，政府撥 30 億給文化部

- 日期：2026-11-20
- 誰決定：翊文（11-20，Yuga 轉達）：政府帳和公共機構都是「政府」，應該是同壹個；館內收的稅歸公共機構，經補助、公共採購流回已知世界。另外「政府再撥款給文化部 30 億」，搬、不記債
- 狀態：已決定，做完（上線前 Yuga 存基準）

## 決定
1. `house.gov`（決定 0110、0111：證交稅、當沖稅、股利稅、營業稅、娛樂稅）**每天換日整筆搬進公共機構（g-public）的帳**：gov 少 n、`house.world` 多 n、公共機構的 adj 多 n，其他單位不動。是搬，不是憑空。程式 `govSweep`（shared/world.js），設定 `NUM.casino.govSweep { on, pct: 100, capPct: 0 }`；每天壹次（`house.govDay` 擋）。
2. 政府帳這個池子還在，當中繼站（稅先進來、換日搬走）：金流圖、日報、帳本的「政府帳」節點照舊，多壹條線「政府帳搬進公共機構」（`govSweep`：gov → 已知世界）。財報「政府帳」那段文字改寫。
3. 政府撥款：公共機構壹次搬 30 億給文化部（`govGrant`，`cultureGrant: 3000000000`，`house.govGrant` 擋重複），**贈款、不記債**（不動 `house.debt.culture`），只動帳上分類，`house.world` 不動；往來表的種類 `govGrant`。
4. 模擬（`tools/gov_sweep_sim.cjs`，景氣 −1／0／+1、90 天、政府帳起始 3 億、館友每天另交稅 500 萬）：全搬和分批都守恆（差 0）、沒有單位變負；公共機構健康值升到上限 1.2、狀態「一般」；補助累計只多約 1% 到 10%（不暴增）；別的單位最大偏離約 3,600 萬～5,900 萬（民生集團，不到它帳的 1%）。舊餘額壹次全搬不會讓公共機構跳太多，所以不分批（pct 100）。
5. 沒做：公共機構把多的錢主動花掉。補助等往來是照帳上比例流的，所以多的錢大多留在公共機構的帳上（要更快流回，下壹步可以調往來表的比例，另外決定）。
