# 地下室改版規劃：選路、打怪物、預設都能合作

> 2026-11-12，Claude 寫。翊文 11-12：「我要開發地下室探險的部分，我想徹底重新規劃一下，讓整個冒險更有趣，最好還有互動打怪物的部分」「預設都要能合作」。
> 決定在 `docs/決定/0067-地下室改版：選路、打怪、預設都能合作.md`。
> **這份是規劃，程式還沒動。** 標「等翊文」的還沒定，不要自己定。數字、名字、文字都是草稿。

---

## 一、現在的地下室哪裡不夠好玩

- 5 層、每層 4 間，照固定順序走，沒有路可以選（`shared/content3.js` 的 `CELLAR`）。
- 每間是三個選項挑一個、擲一次骰，結果馬上出來（`cellarResolve`、`cellarApply`）。
- 隊伍的佩佩只是一個「強度」數字，沒有各自出手的感覺。
- 沒有敵人。房間只有「心情」「顏色」當相剋的對象。
- 走過的房間再走只給 1 靈感。走完 B5 就沒有理由再下去。
- 單人和合作是兩套流程：單人在瀏覽器跑 `logic3.js`，合作在伺服器跑 `coop_flow.js`。新東西要寫兩次。

## 二、最重要的一條：預設都能合作

翊文 11-12：「預設都要能合作」。

- **每一種點、每一個機制，設計的時候就是 1～4 個人的版本。** 一個人下去＝一個人的隊伍，不是另一套玩法。
- 規則只寫一份（`shared/`，純函式），吃「一隊人」。不再有「單人版的規則」和「合作版的規則」。
- 沿用現在的隊伍：一隊 1～4 人、每人帶 1～2 隻、不滿 3 隻由館方助手補（`COOP`、`PARTY`，決定 0020、0036）。
- 獎勵每個人各拿一份，不互搶（決定 0020）。
- 合作現有的九個機制都留著，接法在第七節。
- 人多的好處是「分工」，不是單純比較強：怪物的壓力照人數放大（沿用 `COOP` 放大門檻的算法）。

## 三、每層變成一張小地圖

- 每層 6～8 個點，從上往下分岔，最底是這層的守門怪物。
- 點有五種：

| 點 | 內容 | 幾個人的時候 |
|---|---|---|
| 探索 | 現在的 20 間房直接搬來用，選項和文字不變 | 投票（現在的做法） |
| 遭遇 | 打一隻怪物（第四節） | 每個人各出一招 |
| 休息 | 回一點理智，或治好一隻受傷的佩佩，只能選一個 | 每個人各選各的 |
| 寶箱、怪事 | 小事件，有好有壞；理智低的時候內容不一樣 | 投票；「兩人一起搬」放這裡 |
| 守門 | 這層的大怪物，兩個階段 | 每個人各出一招 |

- **選路**：全隊投票選下一個點，平手領隊決定（沿用投票 30 秒）。一個人就自己選。
- 地圖每天用 `RNG()` 重排一次（種子＝日期＋層數），同一天大家看到的地圖一樣，可以互相報路。
- 下一個點是什麼看得到；再下面的只看得到種類的剪影。留守的人看得到整張（第七節）。

## 四、打怪物：回合制，看得到對方下一招

### 怪物是什麼

- 收藏庫裡放太久的東西成精：發抖的紙箱、從海報走下來的影子、自己坐著的椅子。跟現有房間的文字接得上。
- **全部原創，不畫青蛙，不像 Pepe**（界線第一條）。名字和來歷是草稿，給 Yuga 寫。
- 每隻怪物有：一條「壓力」（打到零就過）、心情、顏色（沿用現在的相剋）、2～4 招、一個弱點。

### 一回合怎麼走

1. **怪物先亮出下一招**。例如「要撲向小明的佩佩」「要讓大家看到不該看的」。
2. **每個人各選一個行動**（25 秒，時間到當「擋」）：

| 行動 | 用什麼 | 效果 |
|---|---|---|
| 推 | 自己帶的佩佩的強度＋骰子 | 扣怪物的壓力 |
| 看穿 | 偵查或神秘學 | 找到弱點：接下來的「推」算兩倍 |
| 安撫 | 說服 | 怪物這回合的招變弱，夠多人安撫就取消 |
| 擋 | 不用擲 | 這回合受傷、扣理智減半；可以指定幫隊友擋 |
| 招式 | 帽子、姿勢 | 見下面 |
| 撤 | — | 見第五節 |

3. **一起結算**，順序固定：看穿 → 安撫 → 擋 → 推 → 怪物出招。所以同一回合一個人看穿、另一個人推，當回合就兩倍。這是合作的甜頭。
4. 怪物的招打中：被點到的人扣理智，或他的一隻佩佩受傷退場。

- 一個人的時候：自己每回合選一個行動，館方助手自動「推」。
- 心情照舊可以花掉把骰子壓低。
- 技能檢定由出手的那個人擲，所以不同職業各有用處（規劃.md 第三節的「分工」）。

### 帽子和姿勢變成招式

現在這些能力是自動觸發，改成自己決定什麼時候用，一場一次：

- 棒球帽：擋下一次。
- 皇冠：重擲一次。
- 觸手帽：大傷害，帶牠的人扣理智。
- 巫師帽：這回合全隊的「推」加成。
- 躺平、毛帽：回理智（每層第一次才算，不能刷，界線「不要改回去」）。
- 斯拉夫蹲：這回合不會被推倒。
- 比讚：鼓舞，下一回合全隊加成。

改了要同步改 `HAT_AB`、`POSE_AB` 和「隊伍規則」牌子（`docs/架構.md` 4.7.1）。

### 守門怪物

- 壓力比較多，打到一半進第二階段，換一組招。
- 第二階段會讓全隊擲理智。
- 第一次打倒，給現在每層的過關獎勵（`CELLAR_REWARDS`：毛帽、書、鑰匙、倒立、結局都不變）。

### 為什麼是回合制，不做按時機

- 規則可以是純函式，伺服器跑同一份。
- 合作時不怕網路延遲，不會有人因為網路慢吃虧。
- 手機好按，不用另外照顧 `body.reduce-motion`。
- 要「手感」之後可以加演出（動作、震動、音效），不改規則。

## 五、帶著東西往下走

- 這一趟拿到的東西先放「背包」，每個人一個。回到地面才真的入帳。
- **撤退**：全隊投票一起撤，全拿。也可以自己先走，拿自己的背包，隊友繼續。
- **倒下**：自己帶的佩佩都退場，變成幽靈（沿用現在的幽靈）。背包先留著。
- **全隊都是幽靈**：這一趟失敗（決定 0036），每個人的背包剩一半。理智歸零的人照舊回黑房間。
- 這樣「要不要再走一個點」每次都要商量。也符合界線的「理智歸零要算容易出現」。

## 六、獎勵：靈感總量不加

節奏本來就太快（`docs/現況.md` 已知問題），所以：

- **靈感總量照現在的**，只是重新分到各個點。調之前先跑模擬。
- 新的獎勵：
  - **怪物圖鑑**：打過的怪物收進典藏冊，寫弱點和一小段來歷。
  - 怪物掉的材料、證據（接現有的「湊證據」）。
  - 少量籌碼：接現有的撿籌碼（決定 0047），一天幾次照舊。
- 每天前 3 趟有獎勵照舊（`P.coopDay`）。

## 七、跟現有的東西怎麼接

**合作的九個機制**（決定 0036）：

| 機制 | 改版後 |
|---|---|
| 全隊理智壓力 | 平均理智越低，怪物壓力越多、招越兇 |
| 每個人看到的不一樣 | 怪物的弱點每個人看到一部分，要拼起來 |
| 幻覺 | 理智低的人看到的「下一招」可能是假的 |
| 湊證據猜真相 | 照舊；怪物也會掉證據 |
| 短句、叫聲、打字 | 照舊；多幾句打怪用的短句（「我來擋」「先看穿」） |
| 一人留守 | 看得到整張地圖、怪物下一招是真是假 |
| 幽靈 | 照舊敲一下；打怪時可以指出怪物的弱點一次 |
| 留下痕跡 | 照舊；留言牌可以留在地圖的點上 |
| 兩人一起搬 | 放進「寶箱、怪事」的點 |
| 探險報告 | 多寫打倒了什麼、誰補了最後一下 |

**其他**：

- **存檔**：`P.cellar` 的 `best`、`won`、`cleared`、`floorsDone` 都保留，只加欄位。舊存檔走過的層照算。改存檔欄位要寫測試。
- **每週劇情**：`week.json` 的房間格式不變，多一個可以不寫的「本週怪物」。`tools/week_check.cjs` 要跟著認。
- **試煉房間、限時活動**（`trialBoost`、`coopBoost`、`cellarChips`）：照舊，當成地圖上的特別點。
- **伺服器**：怪物的壓力、下一招、骰子都放 `coopRuns/{pid}`（只有 Functions 碰得到）；每個人看到的放 `coopView`。開主控台看不到弱點和假招。
- **回滾**：比照大廳改版（決定 0066）。舊的地下室程式不刪，`NUM.ui.newCellar` 切換。
- **手機**：打怪的畫面一開始就排 375 寬和橫拿，不要做完再補。

## 八、分幾步做

每一步一個 PR。

1. **規劃文件和決定紀錄**（這一份）。
2. **打怪的規則**：新檔 `shared/cellar_fight.js`，純函式，一開始就吃 1～4 人。加測試、加模擬（1～4 人的勝率、平均幾回合、扣多少理智）。
3. **接進合作流程**：`coop_flow.js` 多一個「打怪」的階段，Functions 跟著接。在模擬器用 `emu:call` 走完一場。
4. **B1 一隻怪物的畫面**：放在開關後面。一個人、兩個分頁合作都實際走過；電腦和手機寬度都看。**這一步做完翊文就能玩到。**
5. **地圖、選路投票、休息、寶箱**。
6. **五層的怪物**：一般怪物約 10 隻、守門 5 隻。文字草稿給 Yuga。
7. **背包、撤退、失敗的代價**。
8. **每週怪物、怪物圖鑑進典藏冊**。

## 九、等翊文決定的

寫的是 Claude 的預設，翊文沒說話之前先照預設做，但都還可以改。

1. **互動方式**：預設回合制（第四節）。翊文 11-12 還沒直接回答這一題，只說了「預設都要能合作」；按時機的做法在合作時延遲不公平，所以先照回合制。
2. **一個人下去在哪裡跑**：預設登入的人也走伺服器的合作流程（一個人的隊伍），這樣才真的只有一套。代價是每一步多一次連線。沒登入、離線的人用同一份規則在瀏覽器跑。
3. **走到一半可不可以叫人加入**（規劃.md 的「求救」）：預設先不做，出發時的人數就是這一趟的人數。
4. **新的取代舊的，還是兩個並存**：預設取代，舊的留開關可以切回去。
5. **失敗的代價**：預設背包剩一半、佩佩受傷照現在的天數。
6. **留守算不算走過這一層**：決定 0036 就在等的題目，改版時一起定。
7. **怪物的題材**：預設「收藏庫裡的東西成精」。名字、來歷問 Yuga。
8. **靈感怎麼重新分**：要先訂總預算（規劃.md 第四節「靈感要重新算」）。
