# 0045 活動開跑通知、今日館訊改早上八點半

- 日期：2026-11-09 15:49:28
- 誰決定：翊文（要開跑通知、要八點半）；固定的檢查時間、開跑前幾分鐘發是做的時候定的
- 狀態：有效

## 背景

翊文 11-09：

> 「另外現時活動開跑的時候有辦法能推播嗎」
>
> 「先做 Discord 和遊戲內通知」
>
> 「排程是五點更新對吧。但更新內容能夠早上八點半推播嗎」

## 決定

1. **遊戲裡**：活動開始時跳壹則有按鈕的通知（合作、試煉「去地下」，賭場「去賭場」）。每場每台裝置一次，活動中才打開遊戲也會跳；剩不到 5 分鐘就不跳（`NUM.events.noticeMinLeft`）；不打斷正在做的事；畫面在背景不跳，等回來再跳。
2. **Discord 開跑公告**：`week.json` 的 `events` 自己會發，不用排程另外寫。
3. **今日館訊**：遊戲照舊 05:00 更新，Discord 改早上八點半左右發。
4. **手機推播**：還沒做。

## 為什麼是固定時間檢查，不是每場活動排一個時間

- 每天的雲端排程不該動 `.github/workflows`：它的權限可能推不上工作流程檔，推不上的話當天的內容會跟著卡住。所以活動不能各自有 cron。
- 一直檢查（例如每 15 分鐘）一個月約 2,880 分鐘，超過私有 repo 免費的 2,000 分鐘。
- 所以固定跑：今日館訊每天 08:27、08:47；活動每天 19:53、20:13，週末多 13:53、14:13。一個月約 140 分鐘。
- 活動的開始時間因此只用 20:00（週末也可以 14:00）。開在別的時間 `tools/week_check.cjs` 會警告，要的話一起改 `EVENT_SLOTS`、`FIXED_CRONS`。

## 為什麼不是整點才跑

GitHub 的定時會晚，整點最容易晚。所以提早幾分鐘跑，訊息也寫時間（「今晚 20:00～22:00」），不寫「現在開始了」。實際發出來可能比活動早幾分鐘或晚幾分鐘。

## 要注意

- 只有一個地方會發（`discord-scheduled.yml`），發過的記在 Actions cache，不會重發。部署完如果有該發還沒發的（八點半之後才合併、或早上部署壞了現在修好），`deploy.yml` 叫它發。
- 最新的部署失敗就先不發今日館訊（內容沒上線不要說有新東西）；活動開跑和預約公告照發。
- `DAY_POST_FROM`：11-10 開始才照這個方式發，免得把 11-09 部署時發過的再發一次。
- 每週排行榜（`weekly-board.yml`，週一 05:15）沒有動。
