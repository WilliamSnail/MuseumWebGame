## 改了什麼

- **規則**（`shared/party.js`，純函式）：邀請（60 秒、給對的人）、隊伍（一起融合 2 人、地下 1–4 人；每人帶 1 隻／1–2 隻；選了才能準備；換了要重新準備；隊長走了換人；沒人就解散）、`canStartParty`、`fixParty`（Realtime Database 會弄掉空陣列）、`cleanSay`（之後的自由打字）。
- **一起融合的規則**（`shared/logic3.js`，上一次拆好的 `fuseTogether`）：這次加了測試。
- **伺服器**（`functions/party.js`）：
  - `invite`：對方要是館友、要在線；邀請寫進 `/invites`，通知寫進對方的 `/inbox`。
  - `inviteReply`：接受就組隊（邀請的人當隊長），婉拒就通知邀請的人。
  - `partyAction`：選佩佩、準備、離開（都用 Realtime Database 的交易），隊長按開始：先把隊伍佔住（同時按只跑一次）→ Firestore 交易裡讀兩份存檔、用固定的種子跑 `fuseTogether`、兩份一起寫回（rev 各加一）→ 隊伍寫結果 → 兩個人收到 `save_changed`。失敗就退回準備的樣子，誰都沒扣。
- **資料庫規則**：`/parties/{pid}` 只有隊員讀得到；`/invites`、`/partyOf` 只有伺服器。
- **畫面**（`web/src/ui_party.js`、`party.css`）：
  - 館友小卡「邀請壹起融合」（`FRIEND_ACTIONS`；要用挑戰模式的參觀者）。
  - 被邀請：右下角的邀請卡，60 秒倒數，接受／婉拒。
  - 隊伍的木框：兩個人的卡（選了哪隻、準備好了沒、誰是隊長）、從自己的收藏選壹隻、融合的價錢和今天還能幾次、準備好了、隊長的「開始融合」、結果（同壹隻、兩個人各自的理智檢定）。關掉框＝離開隊伍。
- `net_firebase.js` 加 `watch(path, fn)`；`ui_board.js` 的 `overlay()` 多一個 `onClose`；`ui_login.js` 收到 `save_changed` 就重新讀存檔。

### 11-09：在模擬器實際走一遍，修了這些

第一次走（測試的 subagent）發現「開始融合」每次都失敗，還有幾個會卡住的地方。修好之後重測，結果寫在下面。

- **開始融合的鎖**（`functions/party.js` 的 `startParty`）：原本對 `phase` 做交易，第一次拿到 `null`（Functions 手上沒有快取）就放棄，每次都說「已經開始了」。改成用 `changeParty()`（拿到 `null` 回傳 `null` 讓伺服器給真的值再跑），在同一個交易裡檢查 `canStartParty` 再改成 `running`，交易完再確認是 `running`。
- **存檔寫好之後才出錯**：原本後面寫結果出錯也會說「誰都沒有扣東西」。現在分開：Firestore 交易失敗才退回、才這樣說；結果先過一次 JSON（拿掉 `undefined`）再寫進隊伍。
- **開始不了的原因兩個人都看得到**：伺服器寫在隊伍的 `fail`，畫面寫「開始不了：小華：靈感不夠（融合壹次要 3）」。換佩佩、按準備、有人進出就拿掉。
- **邀請過期**：邀請的人那邊也有一張卡倒數（「等 小華 回覆　還有 N 秒」），到了跳「小華 沒有回應，邀請過期了。」。倒數跟網路的時間比（`nowMs`），不跟電腦的時鐘比。伺服器：回覆了就刪掉 `/invites/{iid}`；送出去還沒回覆的記在 `/sent/{uid}`，同一個人下次邀請時刪掉過期的；同一個人還有沒過期的，回「已經邀請 小華 了，等他回覆」。
  - 本來想在 `/invites` 上用 `orderByChild("from")` 查，Admin SDK 的 `get()` 要在規則裡加 `.indexOn`，模擬器開著改規則不會重新載入（試過，500「Index not defined」），所以改成自己記 `/sent`。
- **斷線**：隊伍的框看館友名單（`/status`），隊友離線超過 10 秒（`PARTY.offlineWaitMs`）就叫 `partyAction` 的 `prune`；伺服器自己再看一次 `/status`，離線至少 5 秒（`PARTY.offlineMinMs`，重新整理一下不會被踢）、不是隱身才移出去，其他人看到「小華 斷線了，離開了隊伍。」。框裡隊友斷線時寫「不在線……」。
- **舊的隊伍通知**：收到 `party` 通知、沒開著那一隊的框時，先讀一次 `parties/{pid}`（不是隊員就讀不到），隊伍還在、自己還是隊員才打開。在門口（還沒選參觀者）、自由模式放不了佩佩，就直接退出那一隊（隊友會看到我離開了，不會一直等）。
- **同時兩張邀請卡**：右下角排成一排（`.inv-stack`），收到的一次只顯示最早的那張，卡上寫「還有 1 個邀請」。
- **`leaveCurrent`**：通知帶 `left`（對方跳「○○ 離開了隊伍」）；解散的隊伍刪掉 `/parties`。
- **錯誤訊息後面的「 [400]」**：是 Functions 的 SDK 加的，`toNetError` 拿掉，玩家只看伺服器那句話。
- **`overlay()` 關掉別的框時叫它們的 `onClose`**（`ui_board.js`）：隊伍的框被別的框蓋掉，會照正常方式關（＝離開隊伍、停止聽隊伍、拿掉鍵盤的監聽）。公佈欄自己打開（`autoBoard`）本來就會等畫面上沒有框，不會蓋上來；這一條是保底，兩個都留著。
- 隊長自己的畫面寫「等你準備好」（`canStartParty` 多回傳 `waitFor`）。
- 也順便修了：結果沒有突變時 `mutations` 空陣列被資料庫拿掉、畫面會出錯（`fixParty` 補回）；`save_changed` 之前先丟掉還沒送出去的存檔（`NET.dropPending()`），不然幾秒後舊的那份會照新的 rev 送出去、蓋掉伺服器剛寫好的；同時邀了好幾個人，第二個接受的會加進同一隊（滿了就說「小明 的隊伍滿了」），不會把隊長拉去開新的一隊；接受時邀請的人已經離線，回「小明 已經離線了」；已經在那一隊又被邀請（重新整理過），不先離開、大家重新按準備；融合好了以後對方按「收下了」離開，不再跳「離開了隊伍」、金幣的聲音只響一次；靈感或今天的次數不夠，選佩佩的地方寫出原因、「準備好了」按不下去。

## 還沒做、要注意

- 不在線的館友不能邀請（規劃寫「不在線就變成信」，還沒做）。
- **重新整理之後隊伍的框不會回來**：伺服器上還是隊員（重新整理很快，不會被當成斷線）。對方再邀一次會接回同一隊、大家重新按準備；對方離開或斷線也會清掉。要接回來得加一個「我現在在哪一隊」的 Functions（瀏覽器讀不到 `/partyOf`）。
- 隱身的人在隊伍裡斷線不會被移出去（看不出在不在線），只能等對方自己離開。
- 過期沒回覆的邀請，要等同一個人下次邀請才刪（`/sent`、`/invites`）；11-09 以前的舊邀請沒有 `/sent`，不會被刪（不影響玩，之後可以排程清）。
- 邀請送出去之後不能取消，只能等 60 秒。
- `save_changed` 會丟掉還沒送出去的那份存檔：隊伍的框開著時沒辦法玩別的，丟掉的只有幾秒內的小東西（例如玩了多久）。
- 開發時（`npm run dev`）改到 `shared/` 或 `ui_party.js`，Vite 會整頁重新整理，開著的隊伍框會不見（伺服器上還是隊員）。
- 一起融合的骰子不能花心情壓（規則的設計，寫在 `fuseTogether` 的註解）。
- 「今天」：伺服器算的時候用隊長那份存檔的 `P.day.date`；換成真實的一天（另一個分支）之後就一樣了。

## 給下一個人

- **Functions 的地區設定放在 `functions/options.js`，每個 Functions 的檔第一行都要 `import "./options.js"`**。11-09 發現：寫在 `index.js` 本文的 `setGlobalOptions` 比 `party.js` 晚跑（ES 模組的 import 先跑完），邀請、組隊被放到 us-central1，網頁去 asia-east1 找不到。

- 隊伍的改動一律走 `changeParty()`（Realtime Database 的交易），裡面的函式要是同步、純的（`shared/party.js`）。
- **Realtime Database 的交易，第一次拿到的常常是 `null`**：要回傳 `null` 讓伺服器給真的值再跑，不能直接回傳 `undefined`（那會整個放棄）。11-09 開始融合就是壞在這裡。
- Admin SDK 用 `orderByChild` 加 `get()` 查，規則裡要有 `.indexOn`；模擬器開著改 `database.rules.json` 不會重新載入。能不查就不查（例如 `/sent` 自己記）。
- 開發時在 console 用 `import()` 拿畫面的模組（`ui_core.js`、`net_firebase.js`），要用 `performance.getEntriesByType("resource")` 裡帶 `?t=` 的那個網址；改過的檔 Vite 會加 `?t=`，不帶的話會多載一份、看到的是另一份 `P`。
- `startParty` 裡 `setRng`、`setDayClock` 到換回來之間不能 `await`（Firestore 交易重跑也會算出同一隻，因為種子一樣）。
- 畫面聽 `parties/{pid}`：讀回來先 `fixParty()`。
