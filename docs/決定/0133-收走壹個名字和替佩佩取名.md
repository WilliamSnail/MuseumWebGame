# 0133 門檻那晚收走壹個名字，和替佩佩取名

- 日期：2026-11-19
- 誰決定：翊文（11-19，Yuga 轉達）：所有佩佩都能取名（做成壹般功能）；收走的是「玩家自己取過名、最新那隻」，都沒取過才收融合稱號那隻；館友號碼用加入順序
- 狀態：已決定，程式和測試做完；畫面（取名輸入、空白名牌、名牌背面號碼、小空心圓章）交美術統籌。接在決定 0132（水位）後面

## 決定
1. **取名**（`pepeRename`、`pepeNameClean`，`shared/logic.js`）：收藏裡每壹隻佩佩都能取名或改名，名字存在 `P.pepes[key].nm`，`P.nmSeq` 是取名先後（越大越新）。去頭尾空白、最多 `PEPE_NAME.max`（12）字、不能有控制字元、不能含不雅的字（`PEPE_NAME.bad`，夾空白、標點、大小寫也擋）。名字是純文字，畫面不當 HTML。
2. **待收**：門檻那晚過去，隔天日報（`casPoolDay`）把 `pool.take` 標成那壹晚。
3. **收走**（`casPoolTake`，`shared/casino_bank.js`，被資助那位館友下次進來、有存檔時，`playCore` 同壹個交易）：
   - 挑「玩家自己取過名、`nmSeq` 最大」的那隻；都沒取過名，就挑有融合稱號（`title`）、還沒被收過、序號 `s` 最大的那隻；都沒有就清掉待收、什麼都不動。
   - 名字清成空白（`nm` 空）；稱號留著，畫面把名牌顯示成空白。記 `tk ＝ { no, day, n, stamp: false, was }`。`no` ＝ 館友號碼，**加入順序**（`members` 的 `joinedAt` 排第幾），第壹次收的那刻算好存下，再收還是同壹個；`n` ＝ 被收幾次。
   - 不動錢。存檔 rev 加壹、通知 `save_changed`。
4. **重新取名**：被收過的佩佩再取名，`tk.stamp ＝ true`，畫面在新名字旁邊畫小空心圓章；一般取名沒有。圓章顯示條件：有 `tk.stamp`。
5. **信**：同壹個交易寄兩封（從文化部）：短信（標題「水到門檻了」）和收據，字在 `CAS_TAKE`（`shared/casino_text.js`，劇情 session 的字），`{pepe}` 被收的名字、`{no}` 三位數號碼。信一年後過期。
6. **水位**：收完就是 0132 說的退回起點，不另外動。
7. **公開資料**：Hosting `/data/pool.json`（函式 `poolPublic`，`npm run pool` 印出）只給 `{ day, lv, dir, band, night, trace, hits }`，跟 peek 回的 `pool` 壹樣；不寫是誰、不寫淨值。給每日排程讀（沒有 fb 金鑰）。
