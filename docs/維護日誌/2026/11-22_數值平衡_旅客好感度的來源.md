# 旅客好感度的來源

## 為什麼要改

旅客好感度的存檔和答應率加成早就有了（`npcRelBonus`），但沒有任何地方會加分，所以永遠是 0。這次把三個來源接上。好感度不給籌碼、不給靈感，只換文字、稱號和答應率。

## 改了什麼

- `npcRelTravelerAdd(w, 旅客id, 日, 來源, 旅客清單)`：旅客 id 要在清單裡、劇情角色（trace）不算；稱號名字讀 `content/npc` 的 `bond.title`（字串或 `{name}`），沒寫就不發稱號。`npc_pack.cjs` 多帶 `bond` 欄位。
- 邀請被答應 +1：21 點（`casTNpcInvite`）和德州（`casHNpcInvite`）。
- 同桌打牌 +2：`npcRelTogether`，每手結算（21 點 `casTFinish`、德州 `hdSettle`）幫座位記「跟某位旅客一起打了幾手」，剛好第 `NUM.npcRel.togetherHands`（5）手給一次。
- 一起下地下 +4：`coopNpcEnd`，整趟走完（`run.over === "done"`）才給，每位館友對每位同行旅客。
- 找旅客下地下的答應率也吃好感度加成（`npcCoopChance(n, gift, bonus)`）。

## 怎麼確認的

npm test。德州桌跑到第 5 手好感度剛好 +2、之後不重複。

## 還沒做、要注意

- 送禮（旅客版，壹天 2 隻、喜好）：content 還沒有旅客的喜好，畫面也沒有，沒做。
- `bond.title` 還沒有任何旅客寫：目前不會發旅客稱號。
- 下地下好感度沒有在模擬器走過。
- 座位上的 `tw` 欄位只活在那張桌子上：離座再回來，手數重算。

## 給下一個人

- 好感度的加分都在伺服器的交易裡改錢包，不要搬到客戶端。
