## 為什麼要改

翊文看著展廳畫面說：
> 「這些分享不需要用分享碼了，直接可以選擇館友才對」

後來又補一句：
> 「信箱如果收到其他館友收到的信，收到的館友打開遊戲進館就要有大提示說有誰送了你，請去看信」

登入之後有館友名單，不必再複製貼上一長串碼。

## 改了什麼

- 新的共用小窗 `PANELS.pickFriend({ title, hint, onPick, keep, doneOf })`（`web/src/ui_visit.js`）：列出 `NET.roster` 除了自己的所有館友，線上排前面，有燈號、暱稱、在哪裡或多久前來過；沒有別的館友時寫一句話；暱稱一律純文字。
- 展廳：
  - 「分享」「看別人的展廳」拿掉。
  - 新「看館友的展廳」：選館友，走進他的展廳（原本就有的 `friendHall`）。
  - 新「請館友來看」：選館友，寄通知，沒有獎勵。同一天對同一位只能一次，伺服器檢查（新 Function `hallCall`，資料放 `calls/{對方}/items/call-日期-請的人`，編號一樣就是請過了）。請過的那一格變成「今天請過了」。
  - 對方在線上：馬上跳一則有「去看看」按鈕的通知（`toast` 多了 `action`）；不在線：下次進館在大廳那條「館友來過」、進館大卡看得到（`socialNews` 多回 `calls`）。去看了或按「知道了」就標成看過。
- 本週特展：兩顆碼的按鈕併成「跟館友比比看」。新 Function `visitWeekly`（只讀）：檢查對方是館友，只回那一週的最高分和展台；格子走 `cleanHallSlot`，分數限制 0–100，主題用伺服器算的；不算來訪、不寄信。對方還沒開館、這週沒擺過（或存的是別週）只回旗標，畫面寫一句話。文字沿用「對方的特展…最高 N 分。你這週最高 M 分。對方贏了。」
- 館長室：頁籤「交換碼」改「送館友」。選館友 → `openGift(friend)`（`PANELS.giftTo`）→ 選一隻 → 寄進對方信箱，收到的走原本的信箱。自由模式寫原因、按鈕停用。貼碼收下拿掉。沒登入時這個頁籤不出現。
- 進館大提示卡（`PANELS.autoMail`，`afterEnter` 在公佈欄、簽到卡前面叫）：信箱有還沒領的館友來信、或有人請你去看展廳，跳一張大卡。寫誰送了什麼（「小明 送了你 開心的紅佩佩」），來訪謝禮分開寫（「小華 來看了你的展廳，謝禮在信箱」），最多列 5 則、其餘「還有 N 封」；按鈕「去看信」「去看看」「先不用」。卡片關了才輪到公佈欄、簽到卡。還沒領就每次進館都跳；領完不跳；同一次登入只跳一次。教學、合作地下接回去、黑房間進行中不會走到這裡。
- 已經在線時收到新的信：不跳大卡（會打斷手上的事），改成通知（20 秒、有「去看信」按鈕）加信箱紅點。這是我替翊文先選的。
- 公佈欄多一則館方公告「分享不用貼碼了，直接選館友」（shared/notices.js，id friends-pick，重要，今天發布），白話寫新的玩法。
- 拿掉畫面用不到的：`hallVisit`、`params.view`、`copyText` 的 import、`hallCode`、`parseHallCode`、`weeklyCode`、`parseWeeklyCode`、`giftCode`、`receiveGift` 的 import。
- 畫面文字裡叫人用碼的句子改掉（怎麼玩的「送交換碼」改「送佩佩給館友」）。第 1 代的文字沒動。

- 第 3 套模擬器（`EMU_SET=3`），`?user=小明`、`?user=小華`：
  - 小明請小華（小華在線）：小明的格子變「今天請過了」；小華的畫面跳通知有「去看看」，同時進館大卡（教學略過之後）也列出來；按「去看看」走進小明的展廳。
  - 再按一次（重新整理後）：伺服器擋下，寫「今天已經請過這位館友了，明天再請」，格子變「今天請過了」。
  - 小華在館友名單看到小明（含離線時「離線・N 分鐘前」）、看館友的展廳可以進。
  - 比特展：小明這週有 37 分、小華 0 分，小華看到「對方的特展「8+9 週」：最高 37 分。你這週最高 0 分。對方贏了。」和小明的展台；把小明改成上週的資料，寫「這週的特展還沒開始」。
  - 館長室「送館友」：小明（小華離線）選小華 → 選佩佩 → 送出；小華再進館，大卡寫「小明 送了你 開心的紅佩佩」，去看信領到，下次進館不跳。

  - 電腦 1366、手機 375 都看過大卡、選館友的小窗。
  - 單機（`#hall`，不登入）：展廳沒有這幾顆按鈕，畫面正常。

## 還沒做、要注意

- 沒測：平板 800、正式版、聲音（通知的鈴聲沿用原本的 `bell`，還沒人聽過）。
- 舊的 `#office:trade` 網址在單機會落到名片頁，沒在瀏覽器試（程式裡寫了）。
- 以前交換碼可以送抱枕；現在「送館友」走 `sendGift`，只能送佩佩、失敗作、修復品（`GIFT_KINDS`）。抱枕不能送，要的話得改規則。
- 一天一位的限制只擋同一位；沒有「一天最多請幾位」的總量上限。朋友之間先這樣，被洗版再加。
- 比特展的最高分是存檔裡的 `best`，玩家自己能改；伺服器只檢查範圍，沒重算。
- 請館友來看要自己的展廳有開館（用挑戰模式進過館），不然沒東西可看，伺服器會擋。
- 要部署：`firestore.rules` 沒改（`calls` 走「一律不准」），只要部署 Functions。這次沒部署、沒碰正式的 Firebase。

## 給下一個人

- `hallCode`、`parseHallCode`、`weeklyCode`、`parseWeeklyCode`、`giftCode`、`receiveGift`、`TRADE_TEXT` 還在 `shared/`、測試也還在，但**畫面現在沒人用**。要清掉的話連測試一起拿，要另外開一個 PR。
- `ui_screens2/3.js` 不能 import `ui_visit.js`（它在後面）：要叫選館友、送佩佩、比特展，用 `PANELS.pickFriend`、`PANELS.giftTo`、`ADDONS.hallCall`、`ADDONS.weeklyVs`。
- `autoMail` 要排在 `autoBoard` 前面並且 `await`：公佈欄的自動打開不會等它，晚叫會被蓋掉。
- `overlay()` 會把開著的別的框關掉，所以大卡一定要等沒有別的視窗才開（`mailBusy`）；忙超過 5 秒就這次不跳。
- 瀏覽器開發分頁的帳號記在 sessionStorage：同一個分頁網址換 `?user=` 不會換人，要換人得開新分頁。
