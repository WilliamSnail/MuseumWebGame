## 為什麼要改

1. `npm test` 要 184 秒，其中經濟自我檢查單項就占 156 秒：`test/econ_check.test.cjs` 開 13 次 `tools/econ_check.cjs`，每次（連 `--ledger` 帳面模式）都先把約 7 秒的規則檢查整個跑完。
2. 部署（deploy.yml）的 test job 和 deploy job 是循序的，裝套件、打包要等測試跑完才開始。
3. 合併到 main 的部署會把 PR 已經過的同一份測試再跑一次（約 2 分鐘）。

## 改了什麼

- `tools/econ_check.cjs`：規則面的 ~100 項 `check(...)` 包成 `runRules()`，只有規則模式才呼叫；`--ledger` 帳面模式不跑規則（0.5 秒）。帳面用到的 `W`、`npcDay` 留在函式外。規則模式的輸出跟以前逐字相同（改前改後 diff 過）。
- 因為經濟檢查不慢了，拿掉「只改內容的 PR 跳過經濟自我檢查」：`ci.yml` 的 changed_files 步驟、`run_all` 的 `slowEcon`／`SKIP_SLOW_ECON`、`tools/changed_files.cjs` 的 `skipSlowEcon`／CLI 都刪掉（ship 用的 `isContentFile`、`contentOnly` 留著）。CI 現在一律跑全套，這樣部署才能確定「CI 測過的就是全套」。
- `tools/deploy_gate.cjs`（新）：合併到 main 時，比對這個 commit 的 tree（`git rev-parse HEAD^{tree}`）跟 PR 的 CI 測過的 tree。`ci.yml` 在測試前把 `git rev-parse HEAD^{tree}` 寫進步驟名字「測試的 tree <40 位>」（pull_request 測的是 GitHub 暫時合出來的 merge ref，不是 PR head，所以要記下實際測的 tree）；gate 讀這個 PR head 的 ci.yml 成功的 run 的 jobs，要 job 成功、「測試」「打包」兩步真的跑過（不是 skipped）、tree 記在測試之前、tree 一樣才跳過。其他情形（手動部署、讀不到、tree 不一樣＝中間有別包先合進 main、API 錯誤）一律照跑，這支永遠不報錯離開。
- `deploy.yml`：拆成 `test`（第一步 gate；沒跳過才裝套件＋`npm test`）、`prepare`（裝套件、`npm run build`、dist 用 artifact）同時跑，`deploy` `needs: [test, prepare]`（任何一個紅就不部署）；node_modules 用 actions/cache（key＝兩個 lock 檔的 hash，沒中才 `npm ci`）；deploy 下載 dist artifact、確認 `dist/index.html` 有東西才部署，firebase 部署那段（金鑰、`functions/.env`、trap 清除）沒動。test、prepare 都沒碰 secrets。
- 測試：`test/econ_check.test.cjs` 加「帳面不跑規則」；`test/deploy_gate.test.cjs`（新）用假 API＋真的暫存 git 測跳過、tree 不同、手動、壞資料、CLI、ci.yml／deploy.yml 結構；`test/ci_skip.test.cjs` 改成「沒有任何跳過測試的開關」。

## 怎麼確認的

- 規則模式輸出改前改後完全相同；`--ledger` 12 次測試通過；`npm test` 全過、`npm run build` 通過。
- 秒數（這台本機、11 項同時跑）：`npm test` 184 秒 → 124.5 秒（本機當下負載較高，econ 測試單項 156 → 23 秒）。CI、部署的實測秒數寫在這個 PR 的說明和回報裡。
- ship 流程：ship 合併前會把 main 併進 PR 分支再等 CI，所以 merge commit 的 tree 通常等於 CI 測過的 tree，部署可以跳過測試；等 CI 的期間 main 又被別包合進去時 tree 不同，gate 會照跑，不會漏測。ship 不用改。

## 還沒做、要注意

- `deploy.yml` 要合併到 main 才會真的跑，PR 階段只能驗 CI 和 YAML。第一次部署如果 gate、cache 或 artifact 步驟出問題，看 Deploy 的 test job（gate 的結論會寫在 job summary）。
- 步驟名字「測試的 tree …」「測試（規則、內容、特效、模組、日誌格式）」「打包」是 ci.yml 跟 deploy_gate 的約定，改名要一起改（`test/deploy_gate.test.cjs` 會擋）。
- 手動部署（workflow_dispatch）照舊跑全套。

## 給下一個人

- 想再快：`npm test` 剩下最慢的幾項（規則測試、美股、世界經濟）可以再拆；PR 的 CI 可以也用 node_modules cache；ship 開 PR 後的 `sleep(15000)` 可以拿掉。
- 部署跳過測試的條件只有一條（tree 完全一樣），不要放寬；有疑問就照跑。
