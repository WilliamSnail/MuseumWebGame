# 0095 看展的散客順路逛別間，大廳熱絡門檻重訂

- 日期：2026-11-15 23:40:00
- 誰決定：翊文（「怎麼所有散客都集中在我的展廳?」→ 選「看展的會順路逛別間」）；比例、房間權重、門檻由數值平衡定
- 狀態：有效

## 為什麼

決定 0094 之後大廳看得到各房間人數，結果整天約 986 位看展的散客都在展廳，別的房間幾乎是空的（逛店的散客每店每天不到 1 組）。大廳看起來只有展廳有人。

## 決定

1. **看展的散客，每一組有 60% 的機率**在待展廳的中間一段（停留的 15%～50% 之後開始，持續 25%～50%）去別的房間逛。去哪一間照權重抽：畫廊 3、圖書館 2、賭場 2、手作坊 2、圖鑑／融合／抱枕／銀行／委託／辦公室各 1、地下 0.5。種子含伺服器祕密，同一時刻大家看到一樣（`crowdWander`，`shared/npc_spend.js`；數字在 `NUM.casino.npcSpend.crowd.wander`）。
2. **只改「現在各房間幾位」（`now.rooms`）**。不花錢、不算館內股（`now.shops`、`npcShopArrive`、館內股盤中修正都不動）、不動門票和展廳分紅（`hallFeed`、`hallPot`、`crowdVisitsToday` 都不動）。逛別間的人在 `rooms[房間].wander` 另外記一筆，`n` 裡有算。
3. **展廳的人數跟著扣**：逛別間的那段時間，那組不算在展廳。`now.crowd`、`now.total`（右欄「展廳現在有 N 人」）和大廳圖上「展廳」那一格用同一個數，不會差。這兩個欄位只給畫面看，不碰錢。
4. **大廳熱絡門檻重訂**（`shared/room_mood.js`）：`roomLv` 從 `[1, 2, 4]` 改成 `[1, 4, 10]`；展廳的人本來就多，門檻乘 `roomScale.hall = 8`（8／32／80）。

## 沒有改的

- 館內股的人數、盤中價格、跳空（決定 0094）。逛別間的散客不算店的客人，所以賭場的 `rooms.casino.n` 會比 `shops.food + shops.bj` 多（差 `wander`）。
- 館友的人數、被邀去賭場的 NPC：照舊加在畫面端。
