## 給下一個人

- **`npm run emulators` 開起來，遊戲用的 Realtime Database 其實沒有規則**：模擬器把 `database.rules.json` 放在預設的 `demo-pepe4-default-rtdb`，遊戲和 Functions 用的名字是 `demo-pepe4`（`firebase_config.js` 有寫）。所以本機誰都讀得到，以前的測試也是這樣。要測規則：開好之後 `node tools/emu_rules.cjs`（第 N 套前面加 `EMU_SET=N`）。
- 打字格（`chatPanel`）整趟同一個，`refreshChat` 只換短句那一塊，`drawRun` 只換左邊和隊員：重畫不會洗掉打到一半的字，也不會打斷中文輸入法（輸入法選字時按的 Enter 用 `isComposing` 擋掉）。中文輸入法 AI 測不到，只用程式打過字。不要改回整塊 `replaceChildren`。
- `viewFor` 一律走 `coopFilterView`。要加新的祕密放在 `run` 裡，記得在那裡拿掉，並在 `test/coop_fun.test.cjs` 加一條「看不到」。
- 一間房的記號用 `run.seed` 算的小骰子（`coopLocalRng`），不動共用的 `RNG`：交易重跑一樣，也不會改到舊測試的骰子順序。擲骰還是用 `RNG`。
- `startCoop(members, floor)` 不給 `opt.fun` 就是原本的規則（舊測試、模擬靠這個）。伺服器都開。
- `functions/coop.js` 的 `runStep`：Realtime Database 不能在 Firestore 交易裡讀，所以 `coopChatLog` 在交易外面先讀好。
- `coopAct` 一開始 `run.fresh = {}`：事件只給一步，畫面照 `view.step` 判斷是不是新的。沒有 `step++` 的動作（投票）不會重演。
- `run.members[].san` 是每一步對齊 `P` 的；變形看這個，不要信畫面。
- 骰子（`FX.rollOverlay`）平常的 z-index 比木框低，`body.coop-on` 才蓋得上去（`coop.css`）。`auto: true` 才不用人按。
- 測試的 `G.setRng(() => 0.01)` 會擲出 100（十位 0、個位 0）。要小的數字用 `0.15`（11）。
- 開著框的時候改 `shared/`、`ui_coop.js`，Vite 會整頁重新整理：剛好可以測接回去。
- 停模擬器要照連接埠找 PID，Java 那個要另外停（`netstat` 看 `$2` 的本機位址）；不要用 `pkill -f`，會碰到別人的。
