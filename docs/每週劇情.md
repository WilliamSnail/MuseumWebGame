# 每週地下劇情（規劃）

> 2026-11-09 00:36:31 寫。還沒做；要決定的事在最後一節。
> 翊文的原話（還有第九節的書架分類）：
> 「地下室的劇情會有每週推進，切成每日的進度，規劃一下該怎麼做才對，那一州可能跟最近的新聞關係，可以上網查最新的熱門新聞，當靈感，自動規劃下一周並製作每日、每周任務」
> 「這個也要在布告欄上說」

跟 `規劃.md` 第四節「劇情推動」「誰負責什麼（自動化）」是同一件事，這份把地下收藏庫的每週劇情寫細。

---

## 一、玩家看到的樣子

- **每週一 05:00（台灣時間）**：
  - 公佈欄「特展活動」出一則「本週地下收藏庫：〈標題〉」，重要（導覽列蓋火漆印）。
  - 內文：這週故事的開頭、7 天的節奏、每週任務、獎勵、**剩幾天幾小時**、「前往」按鈕直接到地下收藏庫。
  - 地下收藏庫入口掛「本週異狀」告示：這週多一間特別的房間或一件特別的展品。
- **每天 05:00**：
  - 開一段「今天的線索」：要下去地下收藏庫走一趟、在某一層撿到才讀得到（約 5 分鐘）。
  - 每日任務 3 個，跟這週的故事有關，約 10 分鐘做得完。
  - 公佈欄**同一則**活動公告多一行「第 3 天的線索出現了」，不另外發一則洗版；導覽列的公佈欄只亮小紅點。
- **錯過的天**：同一週內線索都還在，可以補讀；每日任務只有當天。
- **週日**：讀完 7 段線索（和全館目標，見第七節），開「本週結局」。
- **下一週**：這週的故事放進「劇情回顧」，隨時重讀；獎勵只有那一週拿得到。
- **節日那週**：節日優先，故事跟節日有關（跟簽到的節日活動用同一張節日表）。
- 時間照「每天玩 20 分鐘」設計：線索 5 分鐘、每日任務 10 分鐘，剩下的自由玩。

## 二、主線和每週的關係（建議）

- **主線**：地下收藏庫的大謎團，慢慢推，四週（一季）一個段落。主線由 Claude 寫大綱、Yuga 改，事先排好。
- **每週**：一個獨立的小事件，用新聞當靈感；結尾留一個跟主線有關的小線索。
- 這樣新聞怎麼變，主線都不會亂；某一週沒有合適的新聞，也只影響那一週。

## 三、新聞怎麼當靈感（規矩）

- 每週一次，Claude 的排程上網查**台灣最近 7 天**熱門的事：熱門搜尋、幾家新聞網站的熱門、天氣、節日、展覽、流行的食物和話題。
- **只取抽象的元素**：一種天氣、一樣東西、一種心情、一個現象。舉例（不是真的新聞）：
  - 颱風、豪雨 → 地下室淹水，展品漂走了
  - 某種排隊美食爆紅 → 地下冒出一個只賣那個的攤子（不寫店名）
  - 搶演唱會門票 → 展品們搶展台的位子
- **不准**：
  - 有人受傷、死亡的事故、災難、犯罪：不當題材，更不能開玩笑。
  - 政治、選舉、兩岸、戰爭、宗教。
  - 真人的名字、公司、品牌、商標、別人的作品名。
  - 健康、醫療的說法。
  - 抄新聞的文字：只用自己的話；新聞的連結只寫在 PR 裡，**不進遊戲**。
  - 畫 Pepe 的樣子；跟仇恨符號扯上關係的東西（`docs/界線.md`）。
- 找不到合適的：用「常青」主題（跟新聞無關，見第四節的備用週）。
- 每份草稿附一張**靈感來源表**：哪則新聞（連結）、取了什麼元素、為什麼安全。審的人看這張就知道有沒有踩線。

## 四、每週的流程（自動）

| 時間（台灣） | 誰 | 做什麼 |
|---|---|---|
| 週四 10:00 | Claude 的排程（雲端，每週跑一次） | 查新聞 → 選主題 → 寫**下一週**的「週包」→ 跑檢查 → 開 PR（附靈感來源表） |
| 週四到週六 | Yuga、翊文 | 看 PR；Yuga 改文字（Yuga 改過的為準） |
| 週日中午前 | 合併（誰按，見第十節） | 測試過才合併；合併就自動部署 |
| 部署時 | GitHub 自動部署 | 週包上傳到 Firestore，照時間開放 |
| 每天 05:00 | 遊戲自己（不用 Claude） | 照時間開放當天的線索、任務、公告 |

- **備用週**：先手寫 4 週「常青」的週包放在 `content/weeks/備用/`。下一週沒有合併、或排程失敗，就自動用備用週，遊戲不會空掉。
- 排程失敗（查不到、檢查沒過）就開 Issue 告訴翊文。
- 這個排程用的是翊文的 Claude 帳號額度（每週一次：查新聞、寫草稿、開 PR）。

## 五、週包長怎樣

一週一個檔：`content/weeks/2026-W47.json`（週一 05:00 開始的那一週），旁邊一份 `2026-W47.md` 放靈感來源表（只給審的人看，不進遊戲）。

- 這週：標題、主題、開始日期、是不是節日週。
- 本週異狀：特別的房間或展品（從遊戲已經有的房間種類、展品種類裡挑，再配新的文字）。
- 7 天，每天：
  - 線索：標題、幾句話、在哪一層撿到。
  - 每日任務 3 個。
  - 公佈欄要加的那一行。
- 每週任務 5 個、獎勵；本週結局的條件和文字。
  - 每週任務以**地下的新東西**為主（翊文 2026-11-09 00:40:05：「每周任務可能是地下房探險多新劇情線等等的」），例如：
    - 探索這週新開的地下房間（走到、打過、拿到裡面的東西）。
    - 走完這週新的劇情線（7 段線索讀完、開本週結局）。
    - 在新房間找到這週的特別展品、帶回展廳擺。
    - 一起打（合作地下收藏庫做好之後）：跟館友一起過這週的特別房間。
  - 新的房間要用遊戲已經有的房間種類組出來；真的要新的玩法，另外寫程式、走一般的 PR。
- **任務只能從固定的種類挑**（例如：做一隻某個顏色的佩佩、走到地下第幾層、看某一幅畫、融合一次、參觀館友的展廳、送館友一隻佩佩、簽到）。新的種類要寫程式，走一般的 PR，排程不能自己發明。
- **獎勵有上限**：每週給的靈感、心情加起來不能超過預算（數字放 `NUM`，跟規劃第四節「靈感總預算」一起定）。

## 六、不破梗：還沒開放的不先送到玩家手上

- 週包**不打包進網頁**，不然打開原始碼就能先看完（`docs/界線.md` 第三節最後一條）。
- 部署時上傳到 Firestore：`weeks/{週}/days/{第幾天}`；資料庫規則寫「時間到了才讀得到」（`request.time` ≥ 開放時間）。時間照伺服器的，改電腦時間也沒用。
- 上傳只在 GitHub 自動部署裡做（用部署的服務帳號），AI 不直接碰正式資料庫。
- 檢查程式 `tools/week_check.cjs`（放進 `npm test`）：
  - 格式、日期（週一開始、7 天）、字數。
  - 畫面文字用「壹」。
  - 任務種類存在、每天做得完、獎勵不超過預算。
  - 禁用字清單（政治、品牌、災難……），有就擋。

## 七、進度怎麼算

- **個人進度**（先做）：讀了幾段線索、做了幾個任務，存在自己的存檔。
- **全館進度**（建議第二步）：大家一起的目標，例如「這週全館一共找回 100 件漂走的展品」，達成了週日的結局多一段、大家都有獎勵。要 Cloud Functions 加總。

## 八、先後順序

1. **真實的一天**：換日、每週、網路時間（subagent 在做）。
2. **簽到**：用同一套每日、每週的骨架，節日表、簽到日曆也在這裡做。
3. **每週劇情第一版**：週包格式、檢查程式、4 週備用週（手寫）、地下的「本週異狀」、每日線索、每日和每週任務、公佈欄自動公告、Firestore 照時間開放。
4. **合作地下收藏庫**：本週特別的房間可以一起打。
5. **Claude 的每週排程**（新聞 → PR）：先手動跑 2～3 週看品質，再改成自動。
6. 全館進度、劇情回顧、主線。

## 九、書架要分類（劇情回顧放哪）

> 「讀書館的書也要有一些分類，不然都平鋪就會一直增加下去」（翊文 2026-11-09 00:37:25）

現在起源室只有兩排：「館藏」（佩佩起源考的章節、續集）和「禁書」。每週劇情一週一本、加上節日故事，一年會多五十幾本，平鋪會一直變長。

- **書架分成幾個頁籤**（草稿）：
  - 館藏：佩佩起源考、續集（照舊）。
  - 禁書（照舊）。
  - 主線：地下收藏庫的大謎團，一章一本。
  - 每週劇情：一週一本。
  - 節日：節日那週的故事。
- **合訂本**：每週劇情照「季」（4 週）收成一本合訂本，書架上只放這一季的幾本，舊的季變成一本「第 N 季合訂本」，點開再選哪一週。節日照年份收。
- 每個頁籤上寫「幾本、還沒讀幾本」；還沒讀的書背亮一點。
- 書架一排最多放的本數固定（例如 8 本），超過就分頁或收進合訂本，畫面不會被撐長，手機也一樣。
- 跟第六節一樣：還沒開放的書不會先出現在書架上。
