# 0051 Discord聯動

- 日期：2026-11-09 18:15:10
- 誰決定：翊文
- 狀態：有效

## 背景

翊文：

> 「理想是Yuga bot可以在我們discord channel 跟玩家互動，內容也是跟我們數據庫即時同步的」
>
> 「Yuga Bot 接話：有人說「要不要」就回「不要」這個不用做」
>
> 「可以的話，能夠連線玩家相應的Discord 帳號，讓玩家可以在discord 直接玩賭場或是斗內等等的」

## 決定

1. Yuga Bot 在 Discord 用指令和按鈕跟玩家互動，跟遊戲讀寫同一個資料庫。
2. 不做接話、不聽一般聊天，所以不需要一直開著的機器。
3. 全走 Firebase Functions；排程公告照舊走 GitHub Actions。
4. 分三步：綁定和查資料、遊戲大事發到頻道、在頻道玩（玩家連上自己的 Discord 帳號後，能玩 21 點、大禮包、餐車、拚經濟，也能斗內）。
5. 遊戲規則不寫第二套，Discord 呼叫同一份 `shared/` 和伺服器交易。

6. Bot 用現在這隻，改名成 Yuga Bot（2026-11-09，翊文：「好」）。
7. 綁定送 100 萬籌碼，每個遊戲帳號一次（2026-11-09，翊文：「送100萬」）。
8. 21 點牌局只給本人看，打完公開結果（2026-11-09，翊文：「可以結果給所有人看，中間的互動加牌等等不用」）。
9. 指令全部 `pepe-` 開頭，例如 `/pepe-綁定`（2026-11-09，翊文：「反斜線後面可以都用比如 Pepe-綁定 這樣的，只要打Pepe就會建議其他的嗎」）。
10. 頻道裡有館友以外的人，都是認識的，所以暱稱和 21 點結果可以公開（2026-11-09，翊文：「有，不過都是認識的人」）。
11. Discord 伺服器裡的人都能用 `/pepe-加入` 自己成為館友，不用改 Firebase，也不限身分組（2026-11-09，翊文：「好，就這樣」）。做好之前照現在的邀請名單。

12. 第一步動工（2026-11-09，翊文：「可以開始做了」）。做的時候新定的事（都是預設，可以改）：
    - **3 秒**：不另開 codebase、不用 `FUNCTION_TARGET` 懶載入、不設 `minInstances`。量過載入整個 Functions 1.3 秒、最薄的入口 1.2 秒，差不多，花的時間在 Firebase 套件上。正式環境冷啟動還沒量，常超過才設 `minInstances`（先查價再問）。
    - **碼**：綁定碼 6 位數、10 分鐘、一次性；同一個 Discord 帳號 10 分鐘內打錯 5 次暫時擋。加入連結碼 16 個字、30 分鐘、一次性，再打一次 `/pepe-加入` 舊的作廢。
    - **獎勵**：記在 `discordBonus/{uid}`（解除綁定不會刪）；籌碼直接加進 `casinoWallets/{uid}`，沒進過賭場的人先照賭場的做法開錢包（開場籌碼照給）再加；不從莊家扣。
    - **加入的守門**：Google 要驗證過 email；碼無效（過期、用過）就當作沒帶碼，照原本的邀請名單；被停用、這個 Discord 已經換過帳號、今天名額滿，直接擋（連模擬器的 `@dev.local` 也一樣）。被停用的人帶連結回不來，那個 Discord 帳號也不能再用 `/pepe-加入`（包括靠連結加入之後才被停用的）。
    - **沒設定**：Application ID、Public Key、伺服器 ID 還是空字串時，`discordBot` 回 503，遊戲裡不顯示「綁定 Discord」，其他 Function 不受影響。
    - **回覆**：只放遊戲暱稱；`/pepe-排行榜` 只列名次、暱稱、數字（不放建議和提醒）；`/pepe-誰在線` 不列房間，也不列隱身的（連 `members` 的 `invisible` 也檢查）。
    - **公佈欄**：功能要等翊文設定 Discord 才通，所以第一步沒有加公告，要上線通才加。

13. 第一步通了（2026-11-09，翊文在真的 Discord 試過，Bot 顯示名 Yuga v2.2，八個指令）。接著做後面兩步和兩個小東西（翊文：「應該要今天的一些現實活動吧? 還有近期更新指令之類的」）。新定的事（都是預設，可以改）：
    - **`/pepe-今日活動` 加兩塊**：「今日館訊」（跟早上 Discord 公告同一行，只有今天那一天）和「今天的現實世界」。後者來自 `dN.json` 的新欄位 `real`（字串陣列，最多 3 則、每則 50 字）。每天的排程查新聞時，只寫查得到來源的真實台灣活動、展覽、節慶，來源記在 `靈感來源.md` 和 PR，不進遊戲；界線照決定 0048（不寫真人名字、綽號、頭銜、政黨，不碰未證實指控、官司、貪腐、犯罪、傷亡、災難）；沒有就留空，指令不顯示這塊，**不能編**。`tools/week_check.cjs` 擋壞資料。打包用 `tools/copy_shared.cjs`（`functions/shared/day_data.js`，只放日期、標題、`board`、`real`）。
    - **新指令 `/pepe-更新`**：全頻道看得到，預設列最近 5 則（可給 1～10）玩家看得到的公佈欄公告，日期、標題、遊戲連結。跟公佈欄用同一個發布、下架判斷（`noticeLive`）。標題有「理智、怪癖、靈感」的公告不列（頻道裡不放這三樣的字），在遊戲的公佈欄還看得到。
    - **第二步：大事發到頻道。** 交易成功之後寫 `discordOutbox/{事件id}`（只有 Functions 碰得到；寫不進去只記錄，不影響原本的交易），`onDocumentCreated` 的 `discordOutboxSend` 發到頻道。事件：莊家破產、有人一把把莊家打到破產、莊家被救回來（拚經濟的 rescued）、有人靠 `/pepe-加入` 成為館友、實況開播、斗內感謝。同一種事件冷卻 10 分鐘最多一則（斗內 1 分鐘），數字在 `NUM.discord`；冷卻中的不補發。事件的身分就是文件的名字，同一件事只有一份、只發一次。寫進去超過 30 分鐘還沒發的不發。發失敗只記錄原因（不含 token），不重試。只有暱稱，`allowed_mentions: { parse: [] }`，暱稱是 `@everyone` 也不能 tag。
    - **Token**：`.github/workflows/deploy.yml` 部署前用 `printf` 把 `DISCORD_BOT_TOKEN`、`DISCORD_CHANNEL_ID`（GitHub Secrets）寫進 `functions/.env`（被 `.gitignore` 擋住），部署完（包括失敗）用 `trap` 刪掉；不印出來、不開 `set -x`。Function 從 `process.env` 讀，沒有就不發、不報錯（標 skipped）。不用 `defineSecret`（secret 不存在會讓整個部署失敗）。模擬器完全不看環境變數裡的 token、也不連真的 Discord，改成把「會發的訊息」寫進 `discordTestSent`。
    - **第三步：在 Discord 玩。** `/pepe-21點`（按鈕要牌、停牌）、`/pepe-大禮包`、`/pepe-餐車`（選單）、`/pepe-拚經濟`、`/pepe-實況`、`/pepe-斗內`，要先綁定（沒綁定的人收到怎麼綁定或加入）。遊戲規則只有一套：`functions/casino.js` 的 `play` 拆成 `playCore`（吃 uid、nick、email），遊戲和 Discord 各包一層；每個動作在交易裡做的事搬成 `actDeal` 等函式，遊戲的 switch 和 Discord 都呼叫它們。次數、上限、籌碼、存檔共用。
    - **3 秒**：每個動作當場做完交易就回，不先回再繼續做，也不編輯訊息演出；拚經濟的 `lines`、大禮包的結果一次列出。
    - **公開與否**：21 點的牌局和餐車只有本人看得到；大禮包、拚經濟、實況、斗內回在頻道。21 點打完，頻道多一行結果（只有暱稱和輸贏，沒有籌碼餘額），同一個人 5 分鐘內連打併成一則：第一手發出去之後，後面的手編輯那一則（累計手數、勝負平、淨賺賠）。在遊戲裡打完的那手不公開。
    - **按鈕**：`custom_id` 帶動作、`seq`、Discord ID（`bj:hit:3:12345…`）；`seq` 擋連按兩下和過期的訊息，Discord ID 擋別人按（再驗 interaction 的使用者）。過期的按鈕把訊息換成現在的牌局。
    - **存檔**：21 點的連勝連敗和餐車會改存檔，跟遊戲一樣在同一個交易裡寫、`rev` 加一、事後通知 `save_changed`；改的是存檔裡「挑戰模式」那位參觀者（`profiles.challenge`），跟遊戲裡的賭場一樣。遊戲分頁同時開著不會把伺服器寫的值蓋掉（見 `docs/Firebase做法.md` 第十二節）。
    - **文字**：回覆一律過 `dcScrub`，不放 email、理智、怪癖、靈感（遊戲裡的「理智 -1」「心情、理智不會再加了」會被拿掉）。21 點理智低看錯牌照算，只說「眼睛有點花」「你剛剛有 N 張牌看錯了」。
    - **不搬**：同桌 21 點、籌碼換小獎、舊錢包認領、稱號。
14. 沒錢可以跟 Yuga 借、Yuga Bot 交任務（2026-11-10，翊文）：
    - **新指令 `/pepe-借錢`**（本人才看得到）：呼叫 `functions/casino.js` 的 `actRelief`（遊戲的 `relief` 也用同壹個），規則還是 `casRelief`（低於 `reliefBelow`、壹天 `reliefPerDay` 次、補到 `reliefTo`），數字沒改。`/pepe-21點`、`/pepe-餐車`、`/pepe-斗內` 因為錢不夠失敗、而且借得到時，多壹行「打 /pepe-借錢 跟 Yuga 借」。
    - **Yuga Bot 交的任務**：每日任務可以有 `giver: "yuga"`、`says`。`/pepe-籌碼`、`/pepe-21點`、`/pepe-餐車` 的回覆（都只有本人看得到）最後多壹行 `says`，今天有這個任務才讀存檔，做完了就不說。公開的指令不放。

細節和預設數字在 `docs/Discord聯動規劃.md`。

## 什麼時候可以再討論

- 要接話的話，要有一直開著的機器和讀訊息的權限。
- 自己加入之後如果進來不認識的人，可以改成要「館友」身分組才能加入。
