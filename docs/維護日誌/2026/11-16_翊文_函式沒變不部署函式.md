# 函式沒變就不部署函式；舊打包檔只留 1 天

## 為什麼要改
翊文截圖 Firebase 專案費用：11 月到 16 日約 82 美元，Cloud Functions 81.58。用量圖：函式叫用 1.7 萬次（免費 200 萬的 0.8%）、Firestore 讀寫都在免費額度內 → 錢不是玩家用出來的。
推測是部署：11-14～16 每天部署 70～110 次，每次 firebase deploy 都把 40 多個函式重新打包（Cloud Build 每天免費 120 分鐘），每次還多存壹份容器映像（Artifact Registry）。費用從 11-06 開始上升，跟部署變多的時間對得上。
翊文：「1 和 2 都改」（1 函式沒變就不部署函式、2 自動清掉舊的打包檔）。

## 改了什麼
- tools/fn_hash.cjs：先跑 copy_shared（跟部署前壹樣），再把 functions/ 底下會上傳的檔照路徑排好算 sha256；不算 node_modules、.env、shared/notices_data.js（每包上線都會多壹則公告，函式裡只有 Discord 機器人讀它，晚壹點更新沒關係）。
- deploy.yml：算指紋 → 查 Actions cache fn-deployed-<指紋>：有（上次部署過同壹包）就只 firebase deploy --only hosting,firestore,database；沒有就連函式壹起部署，部署完存 cache。手動部署（workflow_dispatch）壹律連函式。
- 連函式部署時順便 firebase functions:artifacts:setpolicy --location asia-east1 --days 1（舊映像只留 1 天；失敗不影響部署）。
- test/fn_hash.test.cjs（加進 run_all）：同內容同指紋、不算公告和 .env、改了函式指紋就變。

## 怎麼確認的
fn_hash 3 過、deploy_gate 過，deploy.yml 用 yaml 解析過。上線後看下壹次只改網頁的部署，Actions 的 summary 要寫「函式這包沒變」。

## 還沒做、要注意
- 每天的內容排程（content/weeks、world、npc 會被打包進函式）那壹包照樣會部署函式，這是對的。
- Discord 機器人的「公告」指令看到的公告會比網頁晚（等下次函式有變才更新）。
- 費用原因是推測：翊文可以在 Google Cloud 帳單報表「依 SKU」看，最大的如果是 Cloud Build／Artifact Registry 就對了。
- discordBot 設了 minInstances: 1（常駐壹台，24 小時計費），這次沒動。
