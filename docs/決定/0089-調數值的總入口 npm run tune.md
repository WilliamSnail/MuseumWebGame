# 0089 調數值的總入口：npm run tune

- 日期：2026-11-15 22:00:00
- 誰決定：翊文（「有快速準確的腳本依據需求更新全部東西的各項數值嗎」→「要做」）
- 狀態：有效

## 決定

1. `npm run tune`（`tools/tune.cjs`）是**改數值的總入口**：一張清單改好幾處，自己找到該改的檔，改完自動跑檢查和模擬，不過就還原。
2. 改動的寫法：`NUM.路徑=值`（`shared/config.js`，也可以是別的 `export const`，例如 `LIMITED_FX.館員帽.skill=6`）、`unit:集團id.欄位=值`（叫 `world:unit` 的 set）、`npc:NPCid.欄位路徑=值`（叫 `world:npc` 的 set，這次新增）。也可以 `--file 清單.txt`（`#` 開頭是註解）。
3. 改 `config.js` 用 **acorn 找到那個屬性、只換那個值**（註解和排版不動）；只能改單一的數字、字串、true／false，**型別不能變**；物件、陣列、算式要手改。
4. 改完自動跑：`world:check`、`econ:check`、`npc_check`（有改 NPC 時）、世界經濟的測試（`--full` 改跑整套 `npm test`），再模擬 30 天（景氣 0 和 −1）印「改之前 → 改之後」：外面世界、NPC 每天花多少、莊家、預算池、錢包、各狀態的集團數、守恆、有沒有破產。`--no-sim` 跳過模擬。
5. **任何一項沒過、或模擬破產／守恆不對 → exit 1，檔案還原成原本的樣子**（包括打包出來的名單）。`--dry`：改了、檢查、模擬，然後還原，不留下任何改動。
6. 以後改數字壹律用它（`AGENTS.md`、`tools/README.md` 已寫）。

## 做得出的效果（實測）

`npm run tune -- NUM.casino.world.growBase=4000000 unit:g-island.share=0.1 --dry`：`econ:check` 抓到「外資 NPC 買畫上限 ≤ 外面世界每天成長」被這個改動弄壞，標紅字、還原、什麼都沒寫（約 3 分鐘）。

## 限制

- 只改單一的值；要加新欄位、新單位用原本的腳本（`world:unit add`）。
- 模擬是 30 天、兩種景氣，不等於正式站的行為；改經濟的數字還是要照 `docs/經濟系統的坑.md` 想過。
- 全部檢查加模擬約 3 分鐘；`--no-sim` 大約 1 分鐘。
