# 0043 手機以橫向為主

- 日期：2026-11-09 15:20:00
- 誰決定：翊文（手機改橫向）；怎麼做、數字、提示的字是做的時候先定的，標「先照這樣」的等翊文看
- 狀態：有效

## 背景

- 翊文 11-09：「手機介面改成橫向操作好了，可能比較正確」。
- 以前手機的版面都看「寬度」（`max-width: 760px`），為直拿設計。橫拿的手機高度只有 360～430，812×375 這種會吃到電腦版，上面的導覽列、下面的狀態列就佔掉一大半。
- 網頁做不到真的鎖橫向：iPhone 的 Safari 不能鎖方向；Android 只有全螢幕或裝成 App 才能用 `screen.orientation.lock`。

## 決定

翊文定的：

- 手機以橫向操作為主。

先照這樣（等翊文看）：

### 一、手機拿直的時候，請玩家轉橫

- 條件：`(orientation: portrait) and (max-width: 760px) and (pointer: coarse)`。**電腦、平板不受影響**；電腦把瀏覽器視窗拉窄也不會跳（要手指操作才算）。
- 蓋一層全畫面、博物館風格的提示（`z-index` 比所有畫面都高）：轉手機的小圖示（動畫減量時不動）、「把手機轉橫，比較好玩」、一顆「先用直的」。
- 轉橫就自己消失（純 CSS，不用 JS 判斷）。
- 按「先用直的」記在這台裝置（`localStorage` 的 `pepe_orient_skip`），**不進存檔、不上傳**；之後不再跳。設定頁的「手機直拿提醒」可以再打開。
- 蓋在上面不會打斷任何東西：合作地下、賭場同桌、計時照常跑，提示只是擋住畫面。
- Android 上，第一次按按鈕（進館、開始）試一次 `screen.orientation.lock("landscape")`，失敗（沒全螢幕、iPhone 沒這功能）就算了，不丟錯、**不強制全螢幕**。按「先用直的」不算，也不鎖。
- 直拿的版面照舊留著，一行都沒刪。

### 二、橫拿的版面

- 條件：`@media (max-height: 500px) and (orientation: landscape)`，全部寫在 `web/src/css/landscape.css`，**在 `main.js` 最後 import**（才蓋得過前面按寬度寫的規則）。電腦（高 > 500）和直拿的手機都不會碰到。
- 導覽列 40px、狀態列 42px，合起來 360 高佔 22%、430 高佔 19%（要求不超過 25%）。導覽列的圖示和字都留著、縮小，放不下就橫向捲，換房間時自己捲到現在這間；狀態列心情、理智、靈感、籌碼、委託都看得到，進度條拿掉。
- 大廳導覽圖用橫的那張，滿寬；下一步、簽到那些條壓成一行高。（`planPortrait()`：直的那張只給「寬度窄、而且不是橫著的手機」。）
- 蓋在畫面上的框（公佈欄、信箱、每週劇情、兌換所、賭場、合作地下、館友、簽到）吃滿高度，內容自己捲，關閉鈕永遠在右上角。
- 能左右分欄的都分欄：手作坊（青蛙固定在左）、揭曉、地下收藏庫的房間、合作地下（左邊舞台和房間、右邊隊員和聊天）、賭場牌桌、拉霸機、擲骰。
- 點擊範圍至少 40px。沒有橫向捲軸（這個意思是整個頁面不橫向捲；導覽列、狀態列、頁籤列自己橫向捲）。
- 鍵盤跳出來：`visualViewport` 量出被蓋住的高度放進 `--kb`，蓋在畫面上的框縮到鍵盤上面；點到輸入格會把它捲到看得到的地方。合作地下的輸入列、賭場同桌的聊天列貼在底下。

### 沒做的

- 沒有改規則和數值，只動畫面。
- 沒有強制全螢幕、沒有叫玩家裝成 App。

## 為什麼先這樣定

- 「先用直的」記在裝置上：直拿的人有時是被迫的（單手、公車上），不能每次都擋。
- 只用 CSS 判斷「要不要跳」：轉橫就消失不會有延遲，也不會因為 JS 晚載入而閃一下。
- 橫拿的版面不另外做一套畫面，只用 CSS 覆蓋：規則、存檔、伺服器都一樣，不會有「橫版壞了直版沒壞」的分裂。
