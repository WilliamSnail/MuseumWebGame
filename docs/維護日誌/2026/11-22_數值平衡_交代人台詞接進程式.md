# 交代人台詞（chat.mention、title、pairs）接進程式

## 為什麼要改

Yuga 把交代人台詞第三批（chat.mention、title、pairs）上線了，程式要讀進來。翊文加碼：提到別人時，那個稱呼要能點，展開他的卡。

## 改了什麼

- **稱號（title）**：到 Lv3 發的成就 id 改成 `npc:<交代人id>:<title.id>`，名字用 `content/givers` 的 `title.name`，說明（`casAchInfo` 的 desc）查 `title.desc`。沒寫 title 就退回 `GIVER_TITLES`。旅客照舊 `npc:<旅客id>`。已經領到舊格式 `npc:<交代人id>` 的人不會再領第二個。
- **chat.mention**：Lv2 起、今天第 3、6 下閒聊，輪流提到有寫的另一位（句子 id `<交代人>:chat.mention.<對方>:<序>`）。選句在 `ui_giver_talk.js` 的 `giverPickLine`。
- **串門子（pairs）**：`giverPairs()` 列全部 6 組；`giverPairAt(時段, 日期, uid)` 回現在這個玩家遇到的那一組（一個時段壹天壹組、同壹人同壹天壹樣、週日限定只在週日）；`giverPairTalk(sid)` 查那段對話。句子 id `pair:<a>-<b>:<第幾段>`，只記在字母順序在前那位名下（記在後面那位名下的伺服器丟掉）。
- 打包（`givers_pack`）本來就整份放，不用改。

- **提到別人的連結**：句子裡的稱呼（荷官、堂主…）變成連結，點了在下面展開那位的卡（用 ADDONS.giverStrip）；句子裡找不到稱呼就在後面加「（看他）」。

## 怎麼確認的

npm test；giver 測試 12 項。瀏覽器沒有看過連結，伺服器沒有在模擬器實測。

## 還沒做、要注意

- 畫面：串門子同框、稱號說明、圖書館查字（`ui_giver_log.js` 的 `giverLogText` 還不認 `chat.mention.<對方>` 和 `pair:`）。
- 串門子不加熟識度（規劃沒寫）。
- `_ids.json`（台詞只能往後加的檢查）：等延伸劇情世界補。

## 給下一個人

- 串門子的對話是壹段壹個 id，不是壹句壹個；兩位的本子都要顯示同壹段，標「旁聽」。
