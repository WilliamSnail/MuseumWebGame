## 要做成什麼

- 玩家把 Discord 帳號連到自己的遊戲帳號，就能在 Discord 直接玩賭場、斗內。
- 玩家在 Discord 打指令、按按鈕，Yuga Bot 在頻道回應。
- Discord 和遊戲讀寫同一個資料庫，沒有第二份資料。遊戲裡的籌碼變了，Discord 下一秒查到的就是新的；在 Discord 玩，遊戲裡也馬上算數。
- 遊戲裡發生的大事，自動出現在頻道。

## 不做

- **Yuga Bot 接話**：不聽頻道的一般聊天，不做「要不要」回「不要」。所以不開讀訊息內容的權限，也不需要一直開著的機器，homelab 不用動。
- 不把籌碼換靈感、舊錢包認領、管理員功能搬到 Discord。這些留在遊戲裡。
- 頻道裡不顯示 email、理智、怪癖、靈感，也不公開誰破產、誰最後一名。

## 怎麼接

全部走現有的 Firebase Functions，分成三條路：

| 方向 | 怎麼走 |
|---|---|
| Discord → 遊戲（指令、按鈕） | Discord 把指令送到新的 Function `discordBot`，驗簽名後當場讀寫資料庫，再回覆 |
| 遊戲 → Discord（大事） | 規則先寫一筆到 `discordOutbox`，由 Firestore 觸發的 Function 發到頻道 |
| 排程公告（今日館訊、活動開跑、週榜） | 照舊走 GitHub Actions，不改 |

遊戲 → Discord 走 outbox，是為了 **Discord 掛掉或發失敗都不影響遊戲**，也能在同一個地方限制頻率、避免重複發。

### 共用規則，不寫第二套

- 拚經濟、21 點、大禮包、餐車、斗內都呼叫跟遊戲一樣的 `shared/` 規則和交易。
- `functions/casino.js` 的 `play(req, …)` 現在靠 `req.auth` 認人，要先拆成吃 `uid` 的核心，遊戲和 Discord 各包一層。
- 新的純規則放 `shared/discord.js`（解析指令、組訊息），才測得到。

### 要先處理的技術風險

Discord 要求 **3 秒內回應**，這是最大的風險，還沒量過：

1. Functions 閒置後第一次啟動可能超過 3 秒。入口要很薄，只載入需要的東西；必要時獨立成另一組部署。
2. 回應送出後，Function 不保證還能繼續跑。所以要花時間的動作不能「先回處理中、接著在同一支裡做」，要寫一筆到 Firestore，由另一支做完再補結果。
3. 上面都做了還是常常超過，才設 `minInstances: 1` 常駐。這會多一點費用，到時候先查價再問翊文。

第一步上線前要在正式環境量真實的回應時間。

## 安全和隱私

- **驗簽名**：每個請求都用 Discord 的公鑰驗（Node 內建 ed25519），過不了就回 401。這是 Discord 的要求，也擋掉假冒的請求。
- **綁定才碰個人資料**：沒綁定的人只能查公開的東西。
- **綁定不靠打名字**：遊戲裡按「綁定 Discord」拿 6 位數的碼（10 分鐘內、只能用一次），在 Discord 打 `/pepe-綁定 碼`。打錯太多次暫時擋。這樣別人沒辦法冒認你的帳號。
- **只有館友**：還是要在 `members/{uid}` 名單上。一個 Discord 帳號只綁一個遊戲帳號，兩邊都能解除。
- **資料放哪**：`discordLinks`、`discordCodes`、`discordOutbox` 只有 Functions 碰得到（`firestore.rules` 最後一條已經擋掉其他人）。
- **自己的資料只給自己看**：`/pepe-籌碼` 這類回覆用只有本人看得到的訊息（ephemeral）。
- **隱身的人**：`/pepe-誰在線` 要遵守隱身設定，不能比遊戲裡露得更多。
- **金鑰**：Bot token 不進 repo、不給 AI。只有發頻道（第二步）才需要讓 Functions 拿到 token；回覆指令用 Discord 給的臨時 token 就好，所以第一步不用動它。

## 分三步做（每一步都能單獨上線）

### 第一步：綁定和查資料

| 指令 | 內容 | 誰看得到 |
|---|---|---|
| `/pepe-綁定`、`/pepe-解除綁定` | 接上或拆掉遊戲帳號 | 本人 |
| `/pepe-籌碼` | 自己的籌碼和戴的稱號 | 本人 |
| `/pepe-莊家` | 莊家現在多少錢、有沒有破產 | 全頻道 |
| `/pepe-排行榜` | 最近一次的週榜 | 全頻道 |
| `/pepe-今日活動` | 今天的限時活動和趣味節日 | 全頻道 |
| `/pepe-誰在線` | 現在在館裡的館友（隱身的不列） | 全頻道 |

要注意的：週榜現在每週一才算一次（`boards/{週}`），第一版就查這份快照，「這週目前的排名」要另外做。活動的內容要讓 Functions 讀得到。

### 第二步：遊戲大事發到頻道

- 預設會發：莊家破產、莊家被救回來、有人把莊家打到破產的那一把。
- 做好才接：實況開播和斗內感謝（`docs/賭場規劃.md`）。
- 每種事件有冷卻時間，預設同一種 10 分鐘最多一則，同一個事件只發一次。
- 名字只用遊戲暱稱。

**做好了（11-09，模擬器測過，還沒部署）**：

- 做法：遊戲裡的交易成功**之後**寫 `discordOutbox/{事件id}`（`functions/discord_out.js` 的 `outboxPut`：寫不進去只記錄、不丟錯，所以不會讓交易失敗），`discordOutboxSend`（`onDocumentCreated`）發到頻道。規則在 `shared/discord_out.js`（事件的字、冷卻、太舊、body）。
- 事件：`broke` 莊家破產（拚經濟或別的把莊家弄成負的）、`breaker` 某人贏的那一手把莊家打到負的、`rescued` 拚經濟把莊家拚回來、`join` 靠 `/pepe-加入` 成為館友、`liveOn` 開播、`donate` 斗內感謝；第三步加了 `bj`（在 Discord 打完的 21 點）。同桌打到破產只說「莊家破產了」（沒有「是誰」）。
- 冷卻 `NUM.discord.outCooldownMin`（10 分鐘）、斗內 `outDonateMin`（1 分鐘）；冷卻中的不補發（標 skipped）；超過 `outMaxAgeMin`（30 分鐘）才輪到的不發。每天最多 5 人靠 Discord 加入，但「加入」這一種 10 分鐘只發一則。
- 同一件事只發一次：文件名是事件的身分，發送前在交易裡把 `pending` 改成 `sending`。發失敗記 `failed` 和原因，不重試。沒 token：標 `skipped: no-token`，不佔冷卻。
- 在 Discord 開播、斗內的回覆本身就是公開的，不另外寫 outbox（不然頻道會出現兩則）。

**要翊文確認的**：第一次部署這個 Firestore 觸發的 Function（`discordOutboxSend`）可能要在 Google Cloud 開 Eventarc 的 API 或給部署用的服務帳號權限；部署失敗的話看 Actions 的錯誤訊息。Bot 在頻道要有「發送訊息」權限（現在發公告的就是同一隻）。

### 第三步：在頻道裡玩

要先綁定才能玩，籌碼、次數和上限都跟遊戲共用，不會因為換到 Discord 多拿一份。

| 指令 | 內容 | 誰看得到 | 要等什麼 |
|---|---|---|---|
| `/pepe-21點` | 下注，用按鈕要牌、停牌 | 牌局只有本人；打完自動公開結果 | 不用等 |
| `/pepe-大禮包` | 開今天的大禮包，用編輯訊息演拉霸 | 全頻道 | 不用等 |
| `/pepe-餐車` | 用選單買吃的，抽券照舊 | 本人 | 不用等 |
| `/pepe-拚經濟` | 跳字演出，結果公開 | 全頻道 | 賭場的拚經濟 |
| `/pepe-實況`、`/pepe-斗內` | 開播；斗內隨機金額，全頻道感謝 | 全頻道 | 賭場的實況和斗內 |

- **21 點走同一份牌局**：遊戲開一半可以到 Discord 打完。理智低看錯牌、連勝連敗、成就都照算。
- **21 點的結果**（翊文 11-09：「可以結果給所有人看，中間的互動加牌等等不用」）：加牌過程只有本人看得到，打完在頻道發一行結果。預設同一個人 5 分鐘內連打，併成同一則。
- **會改存檔的動作要測**：21 點和餐車會加減心情、理智。要測遊戲分頁同時開著會不會存檔衝突，也要定好改的是哪位參觀者（預設現在選的那位）。
- **斗內**：對方也要是館友；每日上限照 `docs/賭場規劃.md`。實況不一定要在 Discord 開，遊戲開的也能在 Discord 斗內。
- **不搬**：同桌 21 點（要計時輪流，留在遊戲裡）、籌碼換小獎。

**做好了（11-09，模擬器測過，還沒部署）**：

- 六個指令都做了：`/pepe-21點 下注`（可以打 `10000`、`10萬`；不填下注＝接著打還沒打完的那手）、`/pepe-大禮包 [幾包]`（預設 1 包）、`/pepe-餐車`（選單 9 樣）、`/pepe-拚經濟`、`/pepe-實況 [開播｜下播]`（預設開播）、`/pepe-斗內`。沒綁定的人收到怎麼綁定或加入。
- 做法：`functions/casino.js` 的 `play` 拆成 `playCore`，每個動作在交易裡做的事搬成 `actDeal`、`actHitStand`、`actPack`、`actBuy`、`actEcon`（`liveAct` 也匯出），遊戲和 `functions/discord_play.js` 都呼叫它們。文字和按鈕在 `shared/discord_play.js`（`DC_TEXT`、`CAS_*`）。
- 公開與否：21 點牌局和餐車只有本人；大禮包、拚經濟、實況、斗內回在頻道。**和原本表格不同的地方**：大禮包、拚經濟不演拉霸和跳字（要編輯訊息，違反 3 秒），一次列完；拚經濟的結果公開。
- 21 點打完，頻道多一行結果（走 outbox，同一個人 5 分鐘內連打併成一則：編輯第一則）。在遊戲裡打完的不公開。
- 存檔衝突的結論：見 `docs/Firebase做法.md` 第十二節。

## 要翊文做的（AI 碰不到）

1. 到 Discord 開發者頁面，把 Interactions Endpoint URL 填成部署好的 Function 網址（AI 給網址）。
2. 確認 bot 有 `applications.commands` 權限，沒有就重新邀請一次。
3. 把 Application ID、Public Key、伺服器 ID 給 AI。這三個不是密碼，可以放設定檔。**Bot token 不要貼給 AI。**
4. （第二步）token 不用放 Secret Manager：`deploy.yml` 部署時從 GitHub Secrets 的 `DISCORD_BOT_TOKEN`、`DISCORD_CHANNEL_ID`（發公告用的同一組）帶過去。確認這兩個 Secret 還在。
5. 指令從 8 個變成 15 個，要到 GitHub → Actions →「註冊 Discord 斜線指令」再按一次，打 `/pepe` 才看得到新的。

## 翊文決定了的

- **自己加入**：Discord 伺服器裡的人都能用 `/pepe-加入`（見「自己加入」）。
- **頻道裡的人**：有館友以外的人，都是認識的（翊文 11-09：「有，不過都是認識的人」）。所以暱稱和 21 點結果可以公開；還不是館友的人可以用公開的查詢指令，不能玩賭場。email、理智、怪癖不出現。
- **指令名字**：全部 `pepe-` 開頭（翊文 11-09：「反斜線後面可以都用比如 Pepe-綁定 這樣的，只要打Pepe就會建議其他的嗎」）。打 `/pepe` 就會列出全部。Discord 規定指令名字要小寫，所以是 `pepe-綁定`，不是 `Pepe-綁定`。
- **Bot**：用現在發公告的那隻，改名成 Yuga Bot（翊文 11-09：「好」）。翊文自己到開發者頁面改。頭像留著現在這張（翊文 11-09：「頭像要留著現在這張，這是Yuga自己畫的」）；它只在 Discord，不進遊戲和 repo，決定 0005 不變。

- **21 點**：牌局只給本人看，結果公開（見第三步）。

## 自己加入

翊文 11-09：「有沒有辦法讓還沒是館友的人自己加也可以加進來，不用我一直更改firebase」。翊文同意了提案，選「任何人都能加入」（「好，就這樣」）。**第一步做好了；「頻道發一則○○加入了」第二步做好了。**

現在的做法：第一次登入時，`join` 查 `invites/{email}`，不在名單上就進不來。管理員介面已經能加 Gmail，不用進 Firebase 後台，但還是要翊文一個一個加。

做法：**在 Discord 伺服器裡的人，打 `/pepe-加入` 就能自己成為館友。**

1. Yuga Bot 回一個只有本人看得到的一次性連結（30 分鐘內有效、只能用一次）。
2. 點連結用 Google 登入，`join` 認這個碼，建好館友，順便綁定 Discord 帳號，也發綁定獎勵。
3. 頻道發一則「○○ 加入了博物館」，翊文看得到誰進來。

守門和善後：

- 能不能進，等於能不能進 Discord 伺服器，所以邀請連結要由翊文管好。
- 不限身分組，伺服器裡的人都能打。之後想變嚴，再加「館友」身分組的限制。
- 一個 Discord 帳號只能換一個館友帳號；預設一天最多 5 人自己加入，超過就請找翊文。
- 要把人請出去，用管理員介面現有的停用；還要讓那個 Discord 帳號不能再用 `/pepe-加入`。
- 碼只有 Functions 碰得到；連結不帶 email 或任何個人資料。
