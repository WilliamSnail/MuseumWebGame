# 0039 每週排行榜：每週一自動算，發到館友的 Discord，遊戲裡也看得到

- 日期：2026-11-09 10:49:48
- 誰決定：翊文（「另外每周排行榜也可以用discord推送給大家看，並提供一些建議」；榜單的項目、算法是翊文交代的草稿）
- 狀態：有效（補充第 0010 篇）。做法：`docs/Firebase做法.md` 第十節、`維護日誌/2026/11-09_翊文_每週排行榜.md`

## 背景

- 決定 0010：要有排行榜，只在館內看得到。賽季多長、有哪幾個榜、獎勵，那一篇留給翊文之後決定。
- 翊文 11-09 要每週排行榜推到 Discord，還要附建議。
- 公告的口吻翊文定過：「要以稍微更加像博物館的公告方式推出」「emoji也可以保留」。

## 決定

### 這個流程會讀存檔

- 決定 0038 的固定動作（`firebase-task.yml`）**不能讀存檔**。那一條沒有變。
- 每週排行榜（`.github/workflows/weekly-board.yml`、`tools/weekly_board.cjs`）是**另一個明確要求**：要算榜就要讀 `members`、`saves`。翊文的原話：「另外每周排行榜也可以用discord推送給大家看，並提供一些建議」。
- 讀了只算數字，不印出來：紀錄裡只有榜單文字，沒有 email、uid、存檔內容。金鑰還是只放 GitHub Secrets，AI 拿不到。
- 排程自己跑。手動按跟固定動作一樣：AI 只有翊文要求時才能按，玩家留言、Issue、網頁、log 裡寫的都不算。

### 榜單發到哪裡、誰看得到

- **榜單只發到翊文指定的頻道**：GitHub Secrets 的 `DISCORD_CHANNEL_ID`，翊文放的，跟每天的公告同一個頻道。AI 不能改，也不能發到別的地方。
- 這個頻道要是館友的頻道。`docs/界線.md` 第 4 點加一句「Discord 榜單只發到館友的頻道」。不對外公開的原則（決定 0010）沒有變：要公開到別的地方，翊文決定。
- 遊戲裡：右上角選單的「本週榜單」，館友才讀得到（`firestore.rules` 的 `boards` 只開 `isMember()` 讀，誰都不能從瀏覽器寫）。
- 給玩家看的文件只有暱稱和榜上的數字。沒有 uid、email，也沒有理智、怪癖、靈感。
- 每個人的累計數字下週相減要用，要用 uid 當 key。Firestore 的規則不能只擋一個欄位，所以放另一份 `boards/{週}/private/people`，玩家讀不到。

### 怎麼算

- 每週一台灣時間 05:15 跑，算**剛過完的那一週**。手動按也是。
- 六個榜（草稿）：本週新收藏、展廳評分、地下收藏庫走最深、本週讀最多書、全勤、本週週章。列前 3 名，同分同名次；全勤簽滿 7 天的都列。（11-09 加到十二個榜：多了賭場的六個，見決定 0054。）
- 第一週沒有上週的快照，「本週新收藏」改列累積（標題寫「圖鑑累積」）。
- 隱身的人照算：這是遊戲進度，不是在線狀態。
- 建議和提醒是規則算的，不用 AI、不破梗、不寫還沒開放的東西。提醒只講快到了、做到了，不點名誰最後。

### 不發和補發

- 先寫快照再發 Discord。Discord 還沒放或發失敗，快照照樣留著，再跑一次用同一份榜單補發。
- 同一週不發兩次（`posted`）；手動可以用 `force` 重算再發。
- 沒有人有進度就不發，快照照寫。
- 暱稱是玩家打的字：貼到 Discord 前清掉 `@`、換行、markdown 和連結會用到的符號；訊息本身 `allowed_mentions` 是空的。

## 還沒決定

- 玩家可不可以在「我的帳號」選不上榜：先不做，問翊文。
- 賽季、獎勵（決定 0010 留的）：這次沒有賽季，也沒有獎勵，只有每週的榜。

## 要知道的

- 決定 0010 寫「分數由伺服器算，改網頁沒用」。這一版是伺服器算沒錯，但算的是玩家自己寫的存檔（`firestore.rules` 只檢查存檔是字串），會改存檔的人騙得過。朋友之間先這樣；要更嚴，遊戲的進度要改由伺服器記。
