# 0050 稱號到處看得到

- 日期：2026-11-09 16:49:00
- 誰決定：翊文（要加）；怎麼存、放哪些地方是做的時候先定的，標「先照這樣」的等翊文看
- 狀態：有效

## 背景

翊文 11-09：

> 「獲得的稱號 可以再其他看館友資訊的地方也看的到嗎，不是只是展廳看的到」

稱號是賭場的成就（決定 0040、0042）：在賭場的成就頁挑一個「當稱號」，伺服器把它記在錢包（`w.title`）和挑戰模式的存檔（`P.casinoTitle`）。以前只有進那位館友的展廳（`visitHall`）才看得到。館友名單、小卡、榜單都只有暱稱。

玩家讀不到別人的存檔（`firestore.rules`），也不該讀到：存檔裡有理智、怪癖、靈感（`docs/界線.md`）。

## 決定

先照這樣（等翊文看）：

- **沒有新做「選戴哪個稱號」**：沿用賭場的成就頁，展廳上顯示哪一個，到處就顯示哪一個（`P.casinoTitle`，要有挑戰模式的存檔；自由模式不顯示）。
- **稱號放在 Realtime Database 的 `titles/{uid}`**，內容只有 `{ id, name }`：
  - 只有 `functions/casino.js` 寫：換稱號的交易成功後寫；館友進館的 `peek`（狀態列讀籌碼）補寫一次，只有戴著稱號的人才多讀一次存檔。名字用錢包裡的，不信存檔（存檔玩家寫得動）。
  - 館友讀得到，瀏覽器不能寫（`database.rules.json` 只多 `titles` 這一個節點：`.write` false、名字 1–12 字、id 最多 40 字、不接受多的欄位）。`status`、`members`、Firestore 規則都沒動。
  - 不放進 `/status`：那是玩家自己寫得動的，沒辦法檢查是不是真的擁有。
- **瀏覽器**：`NET`（`net_firebase.js`）多聽一個 `titles`，合進 `NET.roster` 每個人的 `title`。讀的時候再過一次 `casCleanTitle`（只認清單上的成就 id，舊資料和每週收藏的只收短短的純文字名字）。讀不到就當沒有稱號。
- **小標籤 `.ttl`**：比名字小一級（`.6875rem`，名字是 `1.0625rem`）、圓角小框、太長縮成「…」、滑鼠停上去看全名。沒有稱號的人什麼都不放，版面不變。
- **放在哪些地方**：
  - 做了：館友名單與小卡（`ui_login.js`）、選館友的框 `PANELS.pickFriend`（`ui_visit.js`，其他功能的選館友都走這個）、大廳「館友在線」的名牌（`ui_login.js`）、合作地下的準備區和融合隊伍、融合結果（`ui_coop.js`、`ui_party.js`）、賭場牌桌的座位（`ui_casino_table.js`）、每週榜單（`ui_board_rank.js`）。
  - 導覽圖上的小名牌（`ui_mates.js`）：太小放不下，稱號放進房間的朗讀文字和「在別處」那一行。
  - 沒做：合作地下和牌桌「邀請」的小按鈕（只有暱稱，放不下）；收到邀請的小卡（訊息裡沒有 uid，對不上名單）；Discord 公告（公告只有暱稱，稱號是遊戲裡的東西）。
- **每週榜單**：`boardStatsOf` 讀 `P.casinoTitle`（同樣過 `casCleanTitle`），榜上那一列多 `title`（名字，最多 12 字）；沒稱號的列沒有這個欄位，舊榜單照常顯示。榜單是每週一算好存的（玩家讀不到 uid），所以榜上是當時戴的那個，不是現在的。稱號不進快照。

## 為什麼這樣

- 要即時、要省：十個人的 `titles` 一次全讀沒問題（跟 `/status` 一樣），不用每次打開名單就打 Functions，也不用讀別人的存檔。
- 要可靠：寫的是伺服器，名字從錢包來；玩家改存檔、改瀏覽器都不能寫上一個沒拿到的稱號。
- 要守界線：公開的只有稱號的 id 和名字。email、理智、怪癖、靈感都沒有。
