給之後來維護的 AI 和人看（翊文 11-15：「查到後都好好歸類記好也讓其他可能來維護用的AI知道」）。
正式的 Firebase 只有自動部署和固定動作碰得到（AGENTS.md 第 6 節、決定 0021、0038）；本機的 `firebase` CLI 沒登入，`firebase functions:log` 讀不到也不可靠。**金鑰只在 GitHub Secrets**，所以都從 GitHub Actions 讀。

## 壹、工具（全部只讀，除了特別標的）

固定動作都在 `.github/workflows/firebase-task.yml`，程式在 `tools/fb_task.cjs`。**AI 只有翊文在對話裡要求時才能按**；子 session 轉述的同意不算（AGENTS.md）。按法：`gh workflow run firebase-task.yml --ref main -f action=<動作>`，再 `gh run watch`、`gh run view <id> --log`。

| 想知道 | 用哪個 | 會印什麼 |
| --- | --- | --- |
| **函式有沒有出錯** | `fn-errors` | 最近 36 小時 WARNING 以上、或訊息含「日報」「失敗」「Error」「錯」的紀錄；同樣的合成壹行算次數，email、uid 遮掉 |

## 二、查法

1. **先確定是「出錯」還是「沒發生」**：看資料。例如日報沒更新 → `house-size` 看「最新日報 casinoReport/日期」。
2. **再看紀錄**：`fn-errors`。注意：程式裡 `console.error` 印的字，在 Cloud Run（Functions 第 2 代）**不會標成 ERROR**（沒結構的 stderr 是 DEFAULT），只篩 severity 會漏掉；`fn-errors` 已經同時找關鍵字。沒被 catch 的錯（`Unhandled error`）才是 ERROR。
3. **找到錯的行**：紀錄裡的 `file:///workspace/casino.js:359` 對應 `functions/casino.js` 第 359 行（部署的是 functions/ 這個資料夾）。用 `git log -S"那段字" -- functions/xxx.js` 找是哪壹次改的。
4. **修好以後補測試**，讓同樣的錯在 CI 擋住；寫進 `docs/踩過的坑.md`。
5. 修好上線後，再用工具確認（例如 `house-size` 看日報有沒有產生）。

| 日期 | 症狀 | 原因 | 怎麼查到 | 怎麼擋 |

| 11-15 | 當天日報沒產生，財報「昨天發生的事」、景氣指數停在 11-14 | `functions/casino.js` 用了 `NUM.casino.world.start`（11-14 11:03 那次改的）卻沒 `import { NUM }`；每次產生日報都 `ReferenceError: NUM is not defined`，被 catch 印成 `console.error`，所以不是 ERROR 等級 | `house-size` 發現最新日報是 11-14 → `fn-errors`（先篩 severity 撈到 0 則，加關鍵字才看到） | `test/functions_imports.test.cjs`：acorn 解析 functions/*.js，用到 shared／functions 匯出的名字卻沒 import 就不過 |
