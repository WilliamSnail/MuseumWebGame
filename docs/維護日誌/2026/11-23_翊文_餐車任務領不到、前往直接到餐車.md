## 為什麼要改

> 「餐車吃完當下會有寫完成，但任務版沒辦法領，另外去賭場按下去沒有直接到餐車」

## 改了什麼

- 原因：餐車買東西時，伺服器在同壹個交易裡改存檔（心情、理智）並把 rev 加壹。畫面收到 save_changed 就重讀伺服器那份，前壹刻本機剛記的「今天吃過了」（P.story.acts）被蓋掉。所以當下顯示完成，任務板卻是 0／1。
- 修法：play() 多壹個 opts.act。伺服器這次本來就要寫存檔時（saveDirty），先用 storyAct 把「做過了」記進同壹份存檔。餐車 buy 帶 act: food，21 點 deal 帶 act: casino。
- 不會因為這樣多寫存檔：本來不寫存檔的動作照舊只靠本機記（多寫壹次會讓畫面重讀、丟掉還沒送出的進度）。
- taskGo：food 改成 { room: casino, params: { tab: diner } }；goStep 遇到蓋在畫面上的框（賭場）把參數交給 PANELS，所以「去賭場」直接開餐車那頁。

## 怎麼確認的

- 手機：前往打開賭場，停在餐車。
- giverPick 在賭場還挑得到餐車任務（測試）。

## 還沒做、要注意

- 伺服器那段沒在模擬器實際買過壹次（要登入），上線後請在正式版買壹樣東西，看任務板是不是 1／1、領得到。
- 今天已經吃過但沒算到的人：再買壹次就會算（同壹天只記壹次）。

## 給下一個人

- 伺服器會改存檔的動作，要算每日任務的，都要在 play() 帶 opts.act；不然畫面重讀會把本機的紀錄蓋掉。
