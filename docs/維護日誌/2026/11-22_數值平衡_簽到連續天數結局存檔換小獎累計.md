## 為什麼要改

翊文 11-22 決定館友證整合要改三條規則：簽到算連續天數、B5 結局存檔、換小獎留紀錄（規劃第十節第 5 點）。

## 改了什麼

- **簽到連續天數**：`signStreak(save, 今天)` 回 `{ cur, best, makeups }`，從 `SAVE.signin.days` 的日期算（補簽補上的日子接得起來；今天還沒簽從昨天算，不算斷）。不另存欄位，所以存檔格式不變。`passView` 的 records 多一行「連續簽到」（畫面傳 `o.streak`）。
- **B5 結局存檔**：走完 B5 的那一刻（`cellarAdvance`，單人和合作共用）就把 `P.endings.cellar` 寫上日期。以前只在結局畫面打開時才寫，合作走完沒看到畫面就沒記。結局畫面打開還是會寫（日期會更新成看的那天）。
- **換小獎累計**：錢包多一個頂層欄位 `exTot: { 項目 id: { n, chips } }`（只加不減，每週重算的 `ex` 不影響它），`casExchange` 成功時記；`casPassView.swap.tot` 回給館友證。舊錢包讀回來補成空的，累計從上線那天算（以前沒留紀錄，補不回來）。

## 怎麼確認的

npm test。換小獎沒有動任何數字（價格、上限、獎勵不變），只多記一筆，所以沒有存 house-ledger 基準。
