# Discord 聯動規劃

翊文 11-09：「理想是Yuga bot可以在我們discord channel 跟玩家互動，內容也是跟我們數據庫即時同步的」「Yuga Bot 接話：有人說「要不要」就回「不要」這個不用做」「可以的話，能夠連線玩家相應的Discord 帳號，讓玩家可以在discord 直接玩賭場或是斗內等等的」。

**狀態：只有規劃，還沒動工。** 決定 0051。數字和標「預設」的都可以改。

## 要做成什麼

- 玩家把 Discord 帳號連到自己的遊戲帳號，就能在 Discord 直接玩賭場、斗內。
- 玩家在 Discord 打指令、按按鈕，Yuga Bot 在頻道回應。
- Discord 和遊戲讀寫同一個資料庫，沒有第二份資料。遊戲裡的籌碼變了，Discord 下一秒查到的就是新的；在 Discord 玩，遊戲裡也馬上算數。
- 遊戲裡發生的大事，自動出現在頻道。

## 不做

- **Yuga Bot 接話**：不聽頻道的一般聊天，不做「要不要」回「不要」。所以不開讀訊息內容的權限，也不需要一直開著的機器，homelab 不用動。
- 不把籌碼換靈感、舊錢包認領、管理員功能搬到 Discord。這些留在遊戲裡。
- 頻道裡不顯示 email、理智、怪癖、靈感，也不公開誰破產、誰最後一名。

## 怎麼接

全部走現有的 Firebase Functions，分成三條路：

| 方向 | 怎麼走 |
|---|---|
| Discord → 遊戲（指令、按鈕） | Discord 把指令送到新的 Function `discordBot`，驗簽名後當場讀寫資料庫，再回覆 |
| 遊戲 → Discord（大事） | 規則先寫一筆到 `discordOutbox`，由 Firestore 觸發的 Function 發到頻道 |
| 排程公告（今日館訊、活動開跑、週榜） | 照舊走 GitHub Actions，不改 |

遊戲 → Discord 走 outbox，是為了 **Discord 掛掉或發失敗都不影響遊戲**，也能在同一個地方限制頻率、避免重複發。

### 共用規則，不寫第二套

- 拚經濟、21 點、大禮包、餐車、斗內都呼叫跟遊戲一樣的 `shared/` 規則和交易。
- `functions/casino.js` 的 `play(req, …)` 現在靠 `req.auth` 認人，要先拆成吃 `uid` 的核心，遊戲和 Discord 各包一層。
- 新的純規則放 `shared/discord.js`（解析指令、組訊息），才測得到。

### 要先處理的技術風險

Discord 要求 **3 秒內回應**，這是最大的風險，還沒量過：

1. Functions 閒置後第一次啟動可能超過 3 秒。入口要很薄，只載入需要的東西；必要時獨立成另一組部署。
2. 回應送出後，Function 不保證還能繼續跑。所以要花時間的動作不能「先回處理中、接著在同一支裡做」，要寫一筆到 Firestore，由另一支做完再補結果。
3. 上面都做了還是常常超過，才設 `minInstances: 1` 常駐。這會多一點費用，到時候先查價再問翊文。

第一步上線前要在正式環境量真實的回應時間。

## 安全和隱私

- **驗簽名**：每個請求都用 Discord 的公鑰驗（Node 內建 ed25519），過不了就回 401。這是 Discord 的要求，也擋掉假冒的請求。
- **綁定才碰個人資料**：沒綁定的人只能查公開的東西。
- **綁定不靠打名字**：遊戲裡按「綁定 Discord」拿 6 位數的碼（10 分鐘內、只能用一次），在 Discord 打 `/綁定 碼`。打錯太多次暫時擋。這樣別人沒辦法冒認你的帳號。
- **只有館友**：還是要在 `members/{uid}` 名單上。一個 Discord 帳號只綁一個遊戲帳號，兩邊都能解除。
- **資料放哪**：`discordLinks`、`discordCodes`、`discordOutbox` 只有 Functions 碰得到（`firestore.rules` 最後一條已經擋掉其他人）。
- **自己的資料只給自己看**：`/籌碼` 這類回覆用只有本人看得到的訊息（ephemeral）。
- **隱身的人**：`/誰在線` 要遵守隱身設定，不能比遊戲裡露得更多。
- **金鑰**：Bot token 不進 repo、不給 AI。只有發頻道（第二步）才需要讓 Functions 拿到 token；回覆指令用 Discord 給的臨時 token 就好，所以第一步不用動它。

## 分三步做（每一步都能單獨上線）

### 第一步：綁定和查資料

| 指令 | 內容 | 誰看得到 |
|---|---|---|
| `/綁定`、`/解除綁定` | 接上或拆掉遊戲帳號 | 本人 |
| `/籌碼` | 自己的籌碼和戴的稱號 | 本人 |
| `/莊家` | 莊家現在多少錢、有沒有破產 | 全頻道 |
| `/排行榜` | 最近一次的週榜 | 全頻道 |
| `/今日活動` | 今天的限時活動和趣味節日 | 全頻道 |
| `/誰在線` | 現在在館裡的館友（隱身的不列） | 全頻道 |

要注意的：週榜現在每週一才算一次（`boards/{週}`），第一版就查這份快照，「這週目前的排名」要另外做。活動的內容要讓 Functions 讀得到。

### 第二步：遊戲大事發到頻道

- 預設會發：莊家破產、莊家被救回來、有人把莊家打到破產的那一把。
- 做好才接：實況開播和斗內感謝（`docs/賭場規劃.md`）。
- 每種事件有冷卻時間，預設同一種 10 分鐘最多一則，同一個事件只發一次。
- 名字只用遊戲暱稱。

### 第三步：在頻道裡玩

要先綁定才能玩，籌碼、次數和上限都跟遊戲共用，不會因為換到 Discord 多拿一份。

| 指令 | 內容 | 誰看得到 | 要等什麼 |
|---|---|---|---|
| `/21點` | 下注，用按鈕要牌、停牌 | 牌局本人；結果可選擇公開 | 不用等 |
| `/大禮包` | 開今天的大禮包，用編輯訊息演拉霸 | 全頻道 | 不用等 |
| `/餐車` | 用選單買吃的，抽券照舊 | 本人 | 不用等 |
| `/拚經濟` | 跳字演出，結果公開 | 全頻道 | 賭場的拚經濟 |
| `/實況`、`/斗內` | 開播；斗內隨機金額，全頻道感謝 | 全頻道 | 賭場的實況和斗內 |

- **21 點走同一份牌局**：遊戲開一半可以到 Discord 打完。理智低看錯牌、連勝連敗、成就都照算。
- **會改存檔的動作要測**：21 點和餐車會加減心情、理智。要測遊戲分頁同時開著會不會存檔衝突，也要定好改的是哪位參觀者（預設現在選的那位）。
- **斗內**：對方也要是館友；每日上限照 `docs/賭場規劃.md`。實況不一定要在 Discord 開，遊戲開的也能在 Discord 斗內。
- **不搬**：同桌 21 點（要計時輪流，留在遊戲裡）、籌碼換小獎。

## 要翊文做的（AI 碰不到）

1. 到 Discord 開發者頁面，把 Interactions Endpoint URL 填成部署好的 Function 網址（AI 給網址）。
2. 確認 bot 有 `applications.commands` 權限，沒有就重新邀請一次。
3. 把 Application ID、Public Key、伺服器 ID 給 AI。這三個不是密碼，可以放設定檔。**Bot token 不要貼給 AI。**
4. 第二步時，把 token 放進 Firebase 的 Secret Manager，或同意改部署流程從 GitHub Secrets 帶過去。

## 動工前要翊文決定的

1. **Bot 的名字和頭像**：現在發公告的 bot 要不要直接改成 Yuga Bot？預設用同一隻，改名字。頭像不能用舊的 Pepe 圖（決定 0005）。
2. **頻道裡有誰**：除了館友，還有沒有別人？有的話，第二步公開暱稱要再保守一點。預設只有館友。
3. **綁定獎勵**：綁定時要不要送一次籌碼？預設送 10 萬籌碼，只送一次。
4. **21 點的訊息**：牌局只給本人看，還是全頻道看得到大家打牌？預設只給本人看，比較不洗版。

## 測試

- 純規則（解析指令、組訊息、綁定碼、冷卻）走 `npm test`。
- 用測試金鑰簽假的請求打模擬器，測簽名過不過、綁定、權限；不用連真的 Discord。
- 上線前在真的頻道試一輪，並量回應時間（Discord 只能連正式站）。
