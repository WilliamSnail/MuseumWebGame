# 館友證和兌換所裝備的整合規劃

翊文 11-22：「館友證應該要有 兌換所裡穿的東西，規劃一下怎麼整合，以及這部分還有什麼缺漏的」。

這份只是規劃，沒有動程式。示意圖在 `.claude/交接/館友證裝備三方向.png`（不進 repo，裝備圖用的是真的 `ART.gear`）。

## 現況（11-22 查的）

- 館友證封面（`web/src/panels/ui_pass.js` 的 `certCard`）：照片是收藏過的佩佩（`passPhoto`），不是參觀者本人。封面沒有任何裝備。
- 裝備只出現在兩處：參觀者頁最下面的「裝備 x／上限」清單（`visitorPane`，只能看、不能穿脫），和館長室名片（`ADDONS.sheet`，`ui_shop.js` 的 `sheetGear`，能脫不能穿）。
- 穿脫只能在兌換所裝備頁（`gearCard`）。規則在 `shared/core/shop.js`（`wearGear`、`takeOffGear`、`buyGear`）。
- 裝備共 8 件（`GEAR_ITEMS`），三級；上限 `NUM.shop.gearWorn` = 2 件。擁有的放博物館（`P.shop.gear`），穿的放各參觀者（`P.gear`，換人時各穿各的）。
- 要注意：**裝備是工具，不是衣服**（放大鏡、銅板、算盤、手套、提燈、筆記…）。照片是佩佩，不是人。所以「頭像戴帽子」這種畫法對不上。帽子是 `LIMITED_ITEMS` 的「佩佩部件」，是手作坊做佩佩用的，另一回事。
- 限定裝飾（`LIMITED_ITEMS`）已經在館友證「裝飾」頁，有「拿去用」。

## 一、怎麼整合：三個方向

### 方向一（建議）：證件加「隨身物」兩格，參觀者頁直接穿脫

- 封面照片下面加一條「隨身物」：兩個格子，穿了就顯示 `gearArt`，沒穿是虛線空格＋「＋」。右邊寫「2／2」。
- 點有東西的格子：跳到參觀者頁的穿著那段；點空格：跳到參觀者頁「有的、還沒穿」（沒有就到兌換所）。滑鼠移上去、手機長按（`tipOn`）顯示名字和效果。
- 參觀者頁的裝備那段改成三段：**穿著**（有「脫下來」）、**有的、還沒穿**（有「換上」；滿了就寫「先脫 1 件」）、**兌換所還能換**（顯示價錢和你有幾枚週章，按了直接買，買完問要不要穿；最底下「到兌換所看全部」）。
- 頁面上面加三個座位的小切換（第 1／2／3 位），可以看別的位子穿什麼；別位的只能看，要換人才能改（規則本來就只改現在這位）。
- 優點：封面一眼看到；穿脫不用離開館友證；兌換所照舊，只是多一條路；改動集中在 `ui_pass.js`、`pass.css`、`shared/social/pass.js`。
- 缺點：參觀者頁變長；買裝備在兩處（兌換所、館友證），要共用同一個 `gearCard`，不能複製一份。
- 手機：左邊證件縮成一條時（`.ps-side` 的窄版）把兩格縮成 28px 小圖放在名字旁，不加新的一行。

### 方向二（最小）：照片角落疊小圖

- 照片右下角疊穿著的裝備小圖，其他頁都不動。
- 優點：最快，大約半天。
- 缺點：看不出「還能穿幾件」、不能穿脫；小圖在 48px 的手機照片上很擠；三位換人後還是看不到別位。

### 方向三（最大）：新增「裝備」頁籤

- 館友證變 6 個頁籤，新的「裝備」頁：上面三個座位各自穿什麼，下面是 8 件全部（買、穿、脫、哪位穿著）。兌換所的裝備頁搬過來，兌換所只剩技能、限定、材料。
- 優點：最完整，三位參觀者一目了然，裝備只有一個地方。
- 缺點：要拆兌換所、改 `PANELS.shop` 的入口（大廳小卡、每週劇情都連到它）；頁籤變 6 個，手機一排塞不下；工作量最大。

### 建議

選**方向一**。理由：翊文要的是「館友證上看得到」，封面兩格就達到；穿脫搬進參觀者頁，不用拆兌換所。三位一覽（方向三的好處）用參觀者頁上面的座位切換補上。日後覺得裝備變多再升級成方向三，方向一的格子和三段清單可以直接沿用。

## 二、缺漏清單

編號後面是在哪個檔。「改」是建議要動的，「問」是要翊文決定的。

兌換所東西在館友證看不看得到：

1. **裝備**：只有參觀者頁一張清單，封面沒有、不能穿脫（`ui_pass.js` visitorPane、`pass.js` passVisitor）。→ 方向一解決。
2. **沒穿的、已經有的裝備**：館友證完全看不到「有哪些」，`passVisitor` 只回穿著的（`shared/social/pass.js:55`）。→ 改：`passView` 多回擁有的清單和買了的日期。
3. **兌換所還沒換的裝備**：看不到有哪些、多少枚。→ 方向一的第三段。
4. **限定裝飾和頭飾**：在「裝飾」頁，但 `ui_pass.js:171`、`PASS_TIPS.deco`（`pass.js:29`）寫「只有每日簽到和兌換所拿得到」，不對：主題展、每週特展到金也會給（決定 0035，`LIMITED_ITEMS` 的 `from`）。→ 改字。
5. **沒拿到的限定品寫「？？？」**，不知道去哪拿（`ui_pass.js:169`）。→ 改：鎖著的顯示來源（簽到／兌換所／主題展／特展），「兌換所這週賣」的給「前往」。
6. **提升技能**：館友證技能列沒有提升入口，也沒有上限（`visitorPane` 的 `pv-skill`；`ui_shop.js` `skillPane`）。→ 改：技能那段加「提升」前往，帶到兌換所的「提升技能」頁。
7. **技能數字有加成但沒標**：`skillOf` 已含裝備加成（`legacy.js:259`），館長室有標「（放大鏡）」（`ui_screens3.js:400`），館友證沒標。→ 改：`pv-skill` 後面補同樣的標。
8. **週章怎麼拿**：封面只有「週章 N 枚」，沒說怎麼拿、能換什麼（`stampHow()` 在兌換所有）。→ 改：週章那行加說明牌，並「前往」兌換所。
9. **材料換週章**：館友證看不到手上有幾份材料（`matCount`）。→ 小：問要不要放。
10. **委託櫃台的課、地下試煉房間**：只在原房間。→ 不建議搬，只要在參觀者頁技能那段寫一句「也可以上課、打試煉」並「前往」。

別人、換人：

11. **別人的館友證**：沒有「看館友證」這個畫面。名單只有暱稱、稱號、狀態、所在房間（`net_firebase.js:245` 的 `rosterNow`），展廳只公開展台、畫、裝飾、紀念品、稱號（`shared/social/visit.js:102` 的 `cleanHallView`）。→ 問：要不要讓別人看到你穿什麼？做法：`cleanHallView` 多一個白名單欄位 `gear`（只收 `GEAR_ITEMS` 的 id、最多 2 個），`hallView`（`shared/social/gifts.js:37`）帶出去，展廳的館主名牌旁畫兩個小圖（`ui_visit.js:120`）。順帶：目前也看不到對方的頭像和週章，要不要一起做是同一個問題。
12. **三位參觀者換人後**：`P.visitors[].gear` 有存，但館友證只顯示現在這位（`passVisitor`）。館長室的歷任牆（`officeHistory`，`ui_screens3.js:456`）也不顯示裝備。→ 改：`passView` 多回三個座位的穿著（方向一的座位切換）。
13. **規則上的坑**：換人時「同一位子的下一位接著穿」（`shop.js` 開頭註解）。三位都穿同一件算合法，館友證要照實顯示，不要顯示成「被誰穿走了」（方向三的「第 N 位穿著」要改成「幾位穿著」）。
14. **自由模式**：沒有裝備、`wornGear` 回空。封面的兩格在自由模式要整條不畫（`v.free`）。

說明和操作：

15. **裝備效果說明**：參觀者頁每件裝備有 `desc` 一行，OK；但封面的小格沒有，要用 `tipOn`（`web/src/core/ui_tip.js`）。說明要含：名字、效果、等級、怎麼換（價錢）。`PASS_TIPS`（`pass.js:24`）要加 `gear` 一筆。
16. **手機長按**：`tipOn` 已經支援長按（450ms，長按後那一下點擊不算）。小格要用 `tipOn`，**不要**另外做 `title`（手機看不到）。格子本身又是「點了跳頁」的按鈕，長按和點擊的衝突 `tipOn` 已處理。
17. **「前往」能不能回到對的那頁**：`PANELS.shop()` 呼叫時沒帶 tab，永遠落在「裝備」頁（`ui_pass.js:102`、`ui_pass.js:172`）。`openShop(o)` 本來就吃 `o.tab`（`ui_shop.js:62`，值是 gear／skill／limited／mat）。→ 改：裝飾頁的「兌換所」帶 `{ tab: "limited" }`、技能的帶 `{ tab: "skill" }`；從兌換所回館友證沒有路（問：要不要加「回館友證」）。另外，`goBtn` 一按就先關掉館友證（`leave`），買完就回不去；方向一把買裝備放在館友證內就不用離開。
18. **總覽頁的「參觀者」格**：只寫「裝備 1／2」（`ui_pass.js:82`）。→ 改：寫裝備名（或顯示小圖）。
19. **新手第一次**：還沒有週章時，空格寫「用週章到兌換所換」（`ui_pass.js:101`）但沒說週章怎麼拿。→ 空格說明牌帶 `stampHow()`。
20. **測試**：`test/game/pass.test.cjs` 要加：`passView` 多的欄位、自由模式沒有、三個座位、鎖著的來源文字。

## 三、裝備部分做的順序（如果選方向一）

1. `shared/social/pass.js`：`passView` 加 `gearAll`（擁有）、`seats`（三位穿著）、`gearShop`（還能換的）；`PASS_TIPS` 加 `gear`；改裝飾頁的說明字。補測試。
2. 把 `ui_shop.js` 的 `gearCard`／穿脫抽成可以在館友證裡重用的函式（放 `ui_shop.js` export，`ui_pass.js` 已經 import 它的檔不繞圈，需再確認）。
3. `ui_pass.js` + `pass.css`：封面兩格、參觀者頁三段、座位切換、技能補標、前往帶 tab。
4. 手機窄版的縮小排法；用 `#pass` 預覽、`ui:check`、模擬器登入各看一次。
5. 館方公告、維護日誌。

## 五、缺漏的幾個共通問題

盤點下來，缺漏不是一條一條獨立的，而是四種模式：

1. **只有數字或「N 種」**：失敗作、修復品、抱枕、配方、展台、成就、紀念品、每週的書。→ 統一加「列表」小元件（縮圖＋名字＋數量），一個元件重用。
2. **完全沒有**：禁書、工坊升級、遺物與歷任牆、三位參觀者、試煉、探險報告、畫、海報、簽到歷史、地下解鎖的選項和鑰匙、餐車吃過什麼、大禮包剩幾包。→ 需要新的區塊（見第六節的頁籤）。
3. **算了但沒畫**：`passView.souvenirs`（`pass.js:119`）、賭場 `pass_view.js` 的幾個欄位。→ 這類最容易被「雙向檢查」抓到。
4. **文字和資料對不上**：`PASS_TIPS.deco`（`pass.js:29`）和 `ui_pass.js:171` 說裝飾「只有簽到和兌換所」；「看懂的事」兩份清單；`ui_pass.js:128` 的說明只在非自由模式成立。

另外有幾個**資料層的問題，不是館友證能解的**：B5 結局沒存檔欄位；怪物沒有戰利品；簽到沒算連續天數；換小獎沒留紀錄。要顯示就得先改規則，每一個都要翊文決定要不要做。

## 七、怎麼寫成檢查（翊文：「都要雙向用腳本或程式來追蹤」）

### 要擋的兩個方向

- **① 來源多了、館友證沒跟上** → 擋。
- **② 館友證或登記表指到的東西，來源已經改名或拿掉** → 擋。

### 登記表：`shared/social/pass_sources.js`

一列一類東西。只放字串（檔名、清單名、欄位名），不 import 別的檔，所以不會造成繞圈。每列：

```
{ id: "gear", name: "兌換所裝備",
  from: { file: "shared/core/config.js", list: "GEAR_ITEMS" },      // 來源清單（有 id 的）
  save: ["P.shop.gear", "P.gear"],                                  // 存檔欄位
  pass: { tab: "visitor", key: "gearAll" },                         // 館友證哪一頁、passView 回傳哪個欄位
  use: "wear",                                                      // 能不能用：none／wear／hang／use／goto
  pub: "gear" }                                                     // 別人看得到：cleanHallView／cleanPassView 的哪個欄位，沒有寫 null
```

### 檢查腳本：`tools/check/pass_sources.cjs`（配測試 `test/tools/pass_sources.test.cjs`，加進 `test/run_all.cjs`）

方向 ①（來源 → 館友證），三道：
1. **存檔欄位對帳**：載入 `newProfile()`（`shared/core/logic.js:67`，新存檔的預設）和賭場錢包 `casWalletNew()`，每個頂層欄位都必須在登記表的 `save` 出現，或在「不顯示」白名單（寫原因，例如 `P.day`＝今天的暫存）。**新增任何存檔欄位就會被這道擋住**，逼寫的人回答「館友證要不要顯示它」。這是抓「新類別」最可靠的辦法；比掃清單名穩。
2. **清單掃描**：`config.js`、`systems_text.js`、`text.js` 的 export 裡，名字符合 `*_ITEMS|*_TEXT|UPGRADES|RECIPES|CAS_*|CELLAR_*|TRIAL_*|UNDERSTAND_*` 的，必須出現在登記表的 `from.list`，或在白名單。
3. **每列的 `pass.key`，`passView` 跑一遍假存檔，輸出裡必須真的有這個欄位，而且 `ui_pass.js` 的原始碼裡真的有人讀它**。（抓「算了但沒畫」：`souvenirs` 現在就會被擋。）

方向 ②（館友證 → 來源），三道：
4. 登記表每列的 `from.file` 存在、`from.list` 真的是那個檔的 export；有寫 `ids` 的每個 id 都還在清單裡。
5. `passView` 輸出的每一個欄位，都必須對應到某一列（或在白名單）；賭場的 `pass_view.js` 同理。（抓「來源拿掉了，館友證還在顯示」。）
6. **對外**：登記表 `pub` 的集合必須等於 `cleanHallView`（和之後的 `cleanPassView`）的白名單欄位，兩邊互相比。多一個少一個都擋。

另外，一道文字檢查：`PASS_TIPS` 和各區塊的說明文字提到「只有…拿得到」這種話，必須是從登記表產生的，不能手寫（現在 `PASS_TIPS.deco` 就是手寫、而且是錯的）。

### 白名單：`tools/check/pass_gaps.json`

照 `AGENTS.md`「加檢查前先全掃現有程式」：**這份文件第四節總表裡所有「無」和「數字」的格子，就是白名單的初始內容**（約 40 條，每條 `{ id, reason, since }`）。規則：
- 補了一條就刪一條（檢查會反過來擋「白名單裡的東西其實已經有了」，避免白名單忘了清）。
- 白名單條目指到的欄位如果不存在了也擋。
- 這樣一加進 `npm test` 就是綠的，而且之後缺漏只會變少。

- **怪物圖鑑**（最輕，沒有任何數字）：每種怪第一次打贏就記一筆（哪天、哪一層），館友證和地下各有一頁。要記的只是新欄位 `P.cellar.foes[id]=日期`。這其實就是「戰利品」的最小版：收集感，不動經濟。
- **裝飾性掉落**：打贏某隻怪（或 B5 王）第一次掉一件限定品：佩佩部件（例如怪物形狀的帽子）、展台裝飾。走現有的 `LIMITED_ITEMS`，只好看，不影響數值，也不進經濟。
- **材料掉落**：掉舊畫布、金線、金箔。這會多一個週章來源（3 份換 1 枚），所以**要先跟數值平衡那位確認上限**，跑經濟自我檢查才動。放最後。
- **地下收藏品**（獨立的小冊子）：每層一組「遺落的展品」，找到才算，集滿給稱號。像賭場的每週收藏，館友證有進度條。比圖鑑重，但最有「這層有東西可以找」的感覺。

我的建議：**先做怪物圖鑑**，再加幾件裝飾性掉落，材料掉落留到平衡那位有空再說。

**11-22 翊文「照建議做」**：先做怪物圖鑑，再做裝飾性掉落，**材料掉落先不做**。資料（`P.cellar.foes`、掉落清單）由數值平衡做，品項和圖由美術統籌配合。
