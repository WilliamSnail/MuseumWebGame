| 館友 | 真的玩家 | 有 | — | 不是 NPC |

## 二、統一成「館內 NPC」

### 2.1 一個 NPC 有什麼

放在一份內容檔（建議 `content/npc/npc.json`，Yuga 可以改，不進程式碼）：

```
{ id, name, kind, intro, likes, avoids, route, budget, story }
```

| 欄位 | 意思 | 例 |
|---|---|---|
| `kind` | `visitor` 旅客（來參觀、給留言的人）、`client` 委託人（給委託的人）、`trace` 劇情角色（只留痕跡，不計人數）。**每一種都有名字** | `client` |
| `arc` | **故事線**：這個 NPC 自己的幾段故事（見 2.5） | `[{ "week": "2026-W47", "step": 1, … }]` |
| `likes` | 喜歡的主題、店、畫的稀有度；影響去哪、留什麼言、買什麼畫 | `["餐車", "雨天", "少見的畫"]` |
| `route` | 一天的行程權重：去展廳、餐車、牌桌、委託櫃台、地下收藏庫、手作坊、銀行、拍賣，各一個權重 | `{ "餐車": 3, "展廳": 2, "拍賣": 0 }` |
| `budget` | 這個 NPC 一天最多花多少（參加拍賣、付門票用），只在步驟 4 以後用 | `{ "artDay": 3000000 }` |
| `story` | 跟每週劇情的連結（哪一週開始出現、哪些事件會改他的行程） | `{ "from": "2026-W47" }` |

- 委託人（現有 20 位）直接搬進來當 `kind: "client"`，**名字和 `note` 不改**（Yuga 寫的文字以 Yuga 的為準），再補 `likes`、`route`。
- **展廳的參觀者、留言的人也都是有名字的旅客**（`kind: "visitor"`，翊文 11-14：「每個 NPC 也都在館內有名字了」）：一位旅客一個名字和一句身分（跟委託人的 `name`／`note` 一樣的格式），Yuga 寫（草稿我可以先列）。**日報、留言、拍賣結果都寫名字**，不是只寫人數。
- **劇情角色（`trace`）不算人數、不進股價、不出價**：他們的設定是「不露臉、只有痕跡」，算人頭或讓他們去拍賣會破梗（界線：說明不破梗）。他們只在日報、公告、展廳的痕跡句裡出現，由每週劇情決定。

### 2.2 一天的行程怎麼來

伺服器每天 05:00 換日時（跟館內股的 `casInRoll` 同一個時間點）算一次，**種子含伺服器祕密**（`祕密｜日期｜NPC id｜route`），玩家和看原始碼的人都算不出今天誰去哪：

1. 每個 NPC 抽今天要不要「出門」（機率看 `kind`；旅客約 60%，委託人看今天有沒有他的委託）。
2. 出門的 NPC 抽 1～3 個地方（依 `route` 的權重，再乘上今天的劇情加成）。
3. 結果存在莊家文件 `house.npc = { day, visits: { 地方: [NPC id…] } }`，只留最近 12 天，給：
   - 館內股的「不同的人」（見第三節）、
   - 日報的新聞句（事後寫，名字只在事後出現）、
   - 展廳參觀者留言、委託人出現、門票。

### 2.3 跟每週劇情怎麼接

現有的接口：`content/weeks/*/week.json`（`events`、`casino`、`anomaly`…）、`dN.json`、`content/story/帳本.json`（`characters`、`places`、`news`、`calendar`、`sideArcs`）。

| 劇情裡的事 | 對 NPC 的影響 | 例 |
|---|---|---|
| 某家店辦活動／出事（`week.json` 新增 `npc` 區塊） | 那天那家店的路線權重 × 加成（上限見 3.1） | W47「數東西」：地下收藏庫的清點日，NPC 多去地下 |
| 某個地方鬧鬼／封閉（`places`、`events`） | 那個地方的權重降到 0，NPC 改去別處 | B3「差一角的畫框」封起來那幾天，沒人去 B3 |
| 節日（`shared/holidays.js`） | 全體旅客出門機率 ＋ 一點，展廳多留言 | 國定假日旅客多 |
| 新聞線（`news`、`newsThreads`） | 某類 NPC 的喜好改變 | 選戰週，委託人多半想要某種佩佩（不碰真實政黨，決定 0048） |
| 週末（`outStockWeekend`） | 旅客加一成 | 週末多 |

- 每週的劇情由排程每週一寫；`npc` 區塊每週**最多一家店一天**標加成，內容檢查擋超過上限。
- **Yuga 寫文字，數字（加成上限、機率）寫在 `NUM`，劇情內容不能自己改數字**（跟 `casino.json` 一樣，檢查程式擋）。

### 2.4 NPC 的錢

- **NPC 沒有自己的錢包，錢從外面世界的池子來（11-14，翊文：「NPC 的錢從外面世界來」；規劃 2.12 已上線）。** NPC 付的錢（買畫、付門票）是 `house.world` 搬給賣家、預算池、館方帳（`casWorldOut`／`casPoolWorldOut`，來源 `npcArt`、`ticket`…）；NPC 向館方買畫付的錢搬回外面世界（`casWorldIn`／`casHouseWorldIn`）。**不再用 `casMint`／`casBurn`**。池子吃緊（低於起始 10%）時 NPC 買畫也受「一天最多付池子 1%」的上限（`casWorldRoom`），買不起就不出價。NPC 不需要有「存款」，只需要「今天願意花多少」（`budget`，下面）
- **每個 NPC 的 `budget` 按他是誰，數字一定不一樣**（翊文 11-14：「每個 NPC 根據他是誰，可以拿的數目一定不一樣」）：身分分五級（`NUM.npc.tiers`，程式在 `tools/npc_check.cjs` 檢查）——`none` 劇情角色不帶錢、`drifter` 路人（一天 2 萬～20 萬）、`modest` 小資（10 萬～60 萬）、`comfortable` 小康（50 萬～150 萬）、`collector` 藏家（150 萬～300 萬）；每一級有 `perDay`（一天最多花多少）和 `max`（單筆最多）的範圍，兩者都取一千的倍數、`max` ≤ `perDay`，**同一個全館裡沒有兩位 NPC 的 `perDay` 一樣**（就算同一級，也各有各的數字）。例：咖啡店老闆（小康）`perDay` 70 萬、`max` 40 萬；收藏家（藏家）最多 300 萬。身分決定「他夠不夠格買孤品」：`max` 低於畫現價的 NPC 不出價。
- 全館一天 NPC 買畫的總額另有上限（見 3.2），再受池子吃緊的上限。
- 以後如果要有「NPC 有帳本、會越有錢」的玩法，另外一步決定（步驟 5）。

### 2.5 NPC 的故事線（翊文 11-14：「來參觀的、給委託的等等，他們還有故事線」）

來參觀的、給委託的 NPC，每一位都有自己的故事線，**不只是一句 `note`**：

| 項目 | 規則 |
|---|---|
| 一條故事線 | 3～6 段（`arc`），每一段一句到三句話：第 1 段是他第一次出現，之後隨時間或玩家做的事解鎖。例：「賣傘的老闆」第 1 段「只在下雨天開門」→ 第 2 段「他問起 B1 那把沒人認領的傘」→ 第 3 段… |
| 什麼時候往下一段 | (a) **時間**：每週劇情（`week.json`）指定某一週開始第 N 段；(b) **玩家做的事**：全館累計完成他的委託 N 次、全館有人在他來的那天看完某幅畫；**不看個別玩家**（全館共同的進度，不排名）；(c) 兩者都要的話取較晚的 |
| 怎麼跟主線接 | 每一段可以標 `ties`：呼應主線的哪個地方／角色（`帳本.json` 的 `mysteries`、`foreshadow`、`sideArcs`）。**主線角色（`trace`）仍然不露臉**，NPC 的故事線只能「遇到痕跡」「聽說」，不能直接講破梗的事（界線） |
| 在哪裡出現 | 日報的新聞句（「昨天賣傘的老闆在餐車問起那把傘」）、展廳留言（照他現在的那一段說話）、委託的內容和完成後的話（`CLIENT_COMMENTS` 照他的段）、拍賣結果公告（他要是得標，寫在故事裡）、公佈欄的小故事 |
| 對行程和喜好的影響 | 每一段可以改他的 `route` 權重和 `likes`（例：第 3 段之後他不再去地下，改去銀行）。這樣故事線讓股價的人氣有「理由」，不是亂數 |
| 誰寫 | Yuga 寫文字，排程每週一排進去；數字（機率、加成上限）寫在 `NUM`，故事內容不能自己改數字 |
| 存哪裡 | 內容在 `content/npc/`（每位一個 json）；全館進度在莊家文件 `house.npc.arc[NPC id] = { step, since }`（不是個別玩家的存檔） |

## 三、接經濟

### 3.1 館內股：NPC 也是「不同的人」

**已經規劃在 2.8k**（K＝0.03 不用重算，模擬 N＝3～20、NPC 平均 0～3 位，預測每天賺 ≤ 0.05%、自己多去一次 −0.4%～−0.7%）。納入整體規劃後的規則：

| 項目 | 規則 |
|---|---|
| 怎麼算 | 每家店昨天的「不同的人」＝ 館友 ＋ 去了這家店的 NPC（`kind` 不是 `trace` 的）。一個 NPC 算 1 人，一天一家只算一次。也算進前 7 個有效日的平均 |
| 人數從哪來 | 第一步：每家每天 Poisson(2)（2.8k 的 λ）；第三步起：由 2.2 的行程加總，**期望值對齊 2 位**，所以模擬的結論不變 |
| 劇情日加成 | 劇情標的那天那家店，NPC 多去 `round(b × 前 7 個有效日平均)`，**b 每次在 0.15～0.30 隨機抽**。預期跳空 K × b ≤ 0.9% ＜ 來回成本 1.04%，預先進場賺不到（b ＝ 0.5 就賺 0.5%／次，所以上限寫死 `npcBoostMax`＝0.30） |
| 不能被事先算出來 | 行程種子有伺服器祕密；劇情日的**日子**是公開的、**大小**是隨機的；NPC 人數隔天才在日報公開 |
| 上限 | NPC 加起來占一家店一天人數的 ≤ 40%（超過就砍，免得館友少時股價完全由 NPC 決定） |
| 館友 ≤ 5 位的世界 | NPC 讓「不調價」的日子從 92% 降到約 35%（館友 5 位、λ＝2） |

### 3.2 畫的拍賣：NPC 當買家

現有拍賣（`shared/casino_auction.js`，2.10b）：封閉式、第二高價成交（只有一人出價付底價）、館方拍珍藏孤品、玩家也可以拍自己的畫（底價 ＝ 現價的 80%～、出價上限 150%）、成交公開、出價者不公開。

| 問題 | 建議 | 為什麼 |
|---|---|---|
| NPC 出什麼價 | 每場最多 1 位 NPC 出價，價 ＝ 現價 ×（0.80～1.00 隨機，種子有祕密）× 喜好係數（喜歡這個稀有度 ×1.05，不喜歡 ×0.95），夾在 0.8～1.0 倍現價 | 不超過現價：不讓 NPC 把價格抬過「館方賣回」的行情，玩家出價才是正主 |
| 為什麼不超過現價 | 玩家拍賣底價下限是 0.8 倍現價；NPC 最多出 1.0 倍，所以賣家透過 NPC 最多拿到現價，**比賣回（現價 90%）好一點、比館方買家好賺的差距有限**；沒有 NPC 的場照舊 | 防止「買畫 → 掛拍賣 → NPC 用更高價收」變成穩賺（2.10a：價差要讓人短線賺不到） |
| 錢從哪來 | **外面世界的池子**（規劃 2.12，11-14 翊文：「NPC 的錢從外面世界來」）：NPC 標到玩家的畫＝池子付錢給賣家（`casWorldOut`，來源 `npcArt`，賣家扣 5% 手續費進預算池），畫從賣家手上搬走；NPC 標到館方的畫＝錢搬回池子（`casHouseWorldIn`／預算池，來源 `npcArtBuy`），不是 burn | 跟股票一樣：外面世界是有帳的池子，NPC 是外面世界的人；錢不憑空也不消失，日報「跟外面世界的往來」看得到 |
| 會不會印錢 | 有上限：**全館一天 NPC 買畫總額 ≤ 300 萬 ×（1 ＋ 外部景氣 × 0.2）**（約一個全勤玩家半天的收入）；每位 NPC 一天 ≤ 自己的 `budget.perDay`、單筆 ≤ `budget.max`（按身分不同，2.4）；池子吃緊時再受「一天最多付池子的 1%」；NPC 贏的畫不再回館方（變成「館外收藏家的收藏」，`house.art.own` 要扣掉）。池子本身不會被 NPC 抽乾：300 萬 ÷ 100 億 ＝ 0.03%／天 | 池子是真的有帳的，NPC 買畫是把外面世界的錢搬進來，不是印錢；池子每天還成長約 500 萬 |
| 會不會抽乾 | NPC 標走館方的畫，錢是搬回外面世界（池子變多），每天 ≤ 300 萬；跟莊家買畫收的錢相比很小 | — |
| 要不要讓玩家知道對手是 NPC | **知道**：結果公告寫「得標：館外的收藏家（NPC 名字，若有）」，出價者名字照舊不公開；NPC 出價不鎖玩家的錢 | 世界觀要透明（不是機器人暗盤），NPC 有名字也是劇情素材 |
| 不能被預測 | NPC 是否參加、出多少，種子有祕密、收標前不公開；一場最多 1 位，所以玩家「多出一點」永遠有機會 | 防止 NPC 變成可預測的「價格底」 |

### 3.3 給委託、留言、參觀展覽

跟現有系統怎麼接，**錢不變，只換人名**：

| 現有 | 接法 | 錢 |
|---|---|---|
| **委託**（`dailyCommissions`、`casino_job`） | 每天的委託由「今天出門的委託人 NPC」出（`kind: client`），委託內容按他的 `likes`；完成後的話（`CLIENT_COMMENTS`）用他的口氣。劇情週時，委託人隨劇情變（例如選戰週的委託）| 靈感照舊；籌碼照舊由莊家出（`casHouseMove "job"`）。**不是 NPC 出錢**，因為 `casino_job` 的籌碼是玩家勞動換的，且已經有每天 5 張的上限 |
| **留言**（展廳 `VISITOR_COMMENTS`、留言牌） | 留言掛 NPC 的名字（`旅客某某：「…」`），口氣按 `intro`；劇情角色（`trace`）只留痕跡句，不留名字 | 沒有錢 |
| **參觀展覽（門票）**（`casino_ticket`） | 展廳的參觀者從「今天出門的旅客」裡輪流來（`visitorArrive` 的人選換成 NPC），**付門票的錢不變**：玩家展廳評分 × `perScore`，一天最多 `perDay` 位（20），分給展廳主 30%／預算池 20%／館方帳 50%，錢都是外面世界進來的（`mint.ticket`） | 不變。不同的是日報可以寫「昨天有 N 位旅客逛了你們的展廳，最常去的是……」 |

| **Yuga Bot** | 日報新聞句用 NPC 的名字（「昨天賣傘的老闆在餐車排了很久」） | 沒有錢 |

## 四、分幾步做

每一步都**可以單獨上線**、都有測試、都有館方公告、都不改玩家的錢包；每一步最後有「要翊文決定的」。

### 步驟 1（最小可上線）：隨機的 NPC 人數＋日報一句話

- 內容：館內股的「不同的人」多算 NPC（每家每天 Poisson(2)，種子有祕密，存 `house.sin.npc[日期][店]`，只留 12 天）；日報多一行「昨天館外來了 N 位旅客」。**沒有名字、沒有劇情、沒有拍賣。**
- 程式：`shared/casino_stock_in.js` 的 `casInJump`（a ＋ NPC），`casInRoll`（抽 NPC），`casino_report.js`（一行）。約 1 個 PR。

### 步驟 2：劇情日加成（翊文選 **B（建議）＋ C**，11-14）

- 內容：`week.json` 新增 `npc: { store, day, kind }`（每週最多一家一天）；那天 NPC 多去 `round(b × 平均)`，b ∈ 0.15～0.30 隨機（**B**，日子公開）；日報事後寫「昨天《某某》在餐車辦了活動」。
- **C 要怎麼做才不會被套利**：2.8k 的 C ＝ 劇情日（日子公開）大加成 b ≥ 0.5，預先進場每次賺 0.5%（b ＝ 1 賺 2%），會被套利。所以 **C 改成「突發的大事件」（我把 C 解讀成這個）**：大加成（b ＝ 0.5～1.0）發生在**沒有預告的日子**：每家每天 0.3% 的機率（約一年 4 次）由伺服器祕密抽，事後才在日報寫「昨天……突然來了好多人」。日子不能預測，預期跳空 ＝ 機率 × K × b 近乎 0，所以不會被套利，但股價偶爾有戲劇性的一天。如果翊文要的 C 是**公開日子的大加成**，請先看 2.8k 的模擬表：那會讓預先進場的人穩賺，我不建議。
- 程式：週內容檢查（擋 b 上限、同週同家）、`casInJump`。約 1～2 個 PR。
- **要翊文決定**：誰寫劇情日標記（Yuga 每週一排）；B 的上限 0.30 行嗎；C 做成突發的大事件（不預告）可以嗎，機率 0.3%／家／天、b ＝ 0.5～1.0 行嗎。

### 步驟 3：有名字、有行程、有故事線的 NPC（**11-14 翊文：「直接做到步驟 3」，內容和檢查已上線；排程和每位的故事線寫在 content/npc 和 content/排程說明.md**）

## 五、界線和風險（每一步都要守）

- **不破梗**：劇情角色（警衛、會計、多出來的那壹隻、蹲著的先生）只留痕跡，不計人數、不出價、不寫長相（`帳本.json` 的 `characters.how`）。
- **不寫真人、真公司、真政黨**（決定 0048）：NPC 名字用虛構的；選戰週的委託只談館內的事。
- **記帳**：NPC 的錢一律 mint／burn，一定有來源名字，日報看得到；沒有任何地方「NPC 的錢憑空不見」。
- **上限**：每步都有每天的上限（人數占比、買畫總額、每位 NPC 的 `budget`），不會被「放很多東西等 NPC 收」印錢。
- **不能被預測**：種子有伺服器祕密；公開的是日子（劇情日）不是人數；NPC 出價收標前不公開。
- **不鼓勵沉迷**：NPC 沒有「每天回來領」的獎勵，沒有排行，不影響玩家的連續登入。
