## 為什麼要改

> 「好幾個 session 同時上線，合併時一直撞衝突……公告改成一則一個檔案、目錄（和總表）自動產生，以後不要再撞」

撞的三個地方：`shared/notices.js` 的 NOTICES 大陣列（每個 PR 都在最上面插公告）、`維護日誌/README.md`（`npm run log:index` 重產的目錄）、`docs/音效與特效總表.md`（`npm run fx:report` 重產）。

## 改了什麼

- **公告一則一個檔**：`content/notices/<id>.json`（290 個）。選 JSON 不選 JS：不會有人在裡面寫程式、工具（`npm run notice`、遷移）讀寫簡單、語法錯誤一眼看得出來，排程和別的 AI 也比較不會手滑。檔名必須等於 id。
- `tools/notices_build.cjs`：把這些檔合成 `shared/notices_data.js`（`export const NOTICES_DATA = [...]`），**不進 git**（.gitignore），內容沒變就不重寫，很快、可重複跑。`shared/notices.js` 只留函式，`import { NOTICES_DATA }` 再 `export const NOTICES = NOTICES_DATA`。
- 順序：沒有 `order` 的（`npm run notice` 新加的，帶 `at` 寫入時間）排在最前面、新的在前；有 `order` 的（遷移時照舊陣列順序編的）照 order。畫面最後還是照發布日新到舊排，這個順序只決定同天同重要度誰先，跟以前「新的插在最上面」一樣。
- `tools/notices_migrate.cjs`（`npm run notices:migrate`）：舊陣列拆成檔，**可以重跑**（rebase 後 main 又在舊陣列插了公告，再跑一次就全拆出去）。遷移前後 id 集合和順序一樣（測試 `test/notices_split.test.cjs`）。
- **舊陣列偵測（選的是「報錯」不是自動接收）**：`shared/notices.js` 又出現 `export const NOTICES = [`，`notices_build`（所以 npm test／dev／build／部署都會停）會報「請改用 npm run notice，已經插進去的跑 node tools/notices_migrate.cjs」。另外 `npm run merge:main`（ship 的自動併 main）遇到 notices.js 衝突時會自動救：舊 notices.js 裡 main 還沒有的公告拆成檔、notices.js 留 main 的。
- 接上產生腳本的地方：`test/run_all.cjs` 開頭、`test/load_shared.cjs`（ORDER 加 notices_data.js，並在載入前產生，所以單獨跑任何測試也行）、`vite.config.js`（plugin：dev 啟動和 build 開始前）、`tools/copy_shared.cjs`（部署 predeploy；Functions 複製 shared 前先產生）、`tools/discord_digest.cjs`（每天 20:00 彙整的 Actions）、`tools/notice.cjs`（寫完順手更新）。CI、deploy 的 `npm test`／`npm run build` 本來就會經過這些，不用改 workflow。
- `tools/notice.cjs` 改成寫 `content/notices/<id>.json`（id 照舊 `upd-日期-雜湊`）。
- **日誌總表、音效特效總表不進 git**：`維護日誌/README.md`、`docs/音效與特效總表.md` 加進 .gitignore、`git rm --cached`；`npm run log:index`、`npm run fx:report` 照舊能在本機產生。`log_check` 不再檢查 README 是不是最新（只檢查每篇格式）；`fx_report.test` 改成「`--check`（程式掃得出來、fx_notes.json 每項都有）→ 產生一次 → 檢查產生出來的內容」。
- `tools/merge_main.cjs`：拿掉 notices.js「兩邊都留」和補括號的舊處理（`noticeCloser`），日誌索引重產的處理也拿掉（改成兩份總表若出現修改／刪除衝突就 `git rm --cached`）。
- `tools/changed_files.cjs`／`tools/ship.cjs`：公告改在 `content/notices/`（算內容，只動公告的 PR 本機跳過 test／build）；`shared/notices.js` 現在是程式，不再算內容。沒加公告的警告改看 `content/notices/`。
- 文件：`docs/現況.md`、`docs/架構.md`、`tools/README.md`、`AGENTS.md`、`content/README.md`、`維護日誌/範本.md`、PR 範本等「新公告加在 shared/notices.js 最上面」的說明改成新做法。

## 還沒做、要注意

- 拆檔前就開著的 PR（例如在舊 notices.js 插公告的）：併 main 會在 notices.js 衝突；用 `npm run merge:main`／`npm run ship` 會自動把公告拆成檔；手動併的話跑 `node tools/notices_migrate.cjs`。
- 還會撞的地方：`docs/現況.md`、`docs/未來更新.md` 這種大家都會加一行的文件、`test/run_all.cjs` 的步驟清單、`test/load_shared.cjs` 的 ORDER（merge_main 已經會兩邊都留）、`package.json`。`維護日誌/` 是一篇一個檔，不會撞。
- `shared/notices_data.js` 不在 git 裡：新 clone、新 worktree 要跑過一次 `npm test`／`npm run dev`／`npm run build`／`npm run notices:build` 才有；單獨 `node` 直接 import `shared/notices.js` 的新工具要自己先呼叫 `require("./tools/notices_build.cjs").write()`。
