## 為什麼要改

測試 session 測 PR 950／952（交代人互動）時，翊文問「模擬器登入和測試有沒有重複、可以優化的」。這次反覆卡住或重做的有：

1. 瀏覽器登入的帳號，`emu:call` 就登不進（`EMAIL_EXISTS`）。原因：網頁用假的 Google 憑證登入，`emu_call` 卻用 email＋密碼註冊，同一個名字變成兩個帳號。文件還要大家記得「先 emu:call、最後才開網頁」。
2. 備一個測試帳號要三步（emu:call peek、qa_seed_save、開 lv0 德州桌再離開來建錢包文件）。
3. 每次實測都在瀏覽器 console 手動：用 performance 找模組網址才拿得到 NET／setNowClock；一步步點「繼續參觀」、關職業視窗、點「知道了」、關公佈欄、點房間；`?user=` 在同一個分頁不會換人（停在上一個人，測了壹陣才發現）。
4. 改熟識度要手改 npcRel；找「今天剛好有臨時拜託」的帳號要自己寫暫存腳本算 hash。
5. 兩個 session 同時用第 7 套，登入和資料被搞亂（模擬器多了不認識的帳號、聊乙掉登入）。

## 改了什麼

- `tools/dev/emu_lib.cjs`（新，共用零件）：連接埠、帳號（跟網頁壹樣：`dev-` ＋名字十六進位最多 40 字元，假 Google 憑證 `signInWithIdp`）、叫 Functions。`emu_call` 改成用它，同名字網頁和腳本是同壹個 uid。
- `npm run qa:user`：登入、建 members、放挑戰存檔（呼叫 `qa_seed_save`）、建錢包文件（做壹次 giver visit 再把 npcRel 清空）。
- `npm run qa:giver`：`--lv clerk=1,scale=2` 改熟識度、`--offers` 印今天誰有拜託（沒有模擬器時用 `--uid`）。公式跟 `shared/social/giver.js` 的 giverOffers 壹樣。
- `window.__qa`（`web/src/core/qa_hooks.js`，只有 `npm run dev`／模擬器的網頁，`import.meta.env.DEV` 才載入，dist 裡確認沒有）：`enter(房間)`、`as(名字)`、`casino(資料)`、`date(天數)`、`NET`、`me()`。
- `npm run local -- --list`：看哪幾套有人在用、是哪個資料夾開的；pid 檔記下開的人，想開已經有人用的套數時印出是誰。
- 文件：`tools/README.md` 的表、`docs/操作/本機模擬器實測.md`（拿掉「先 emu:call 再開網頁」的順序限制）。
- 測試：`test/tools/tools.test.cjs` 加 emu_lib、qa_giver 兩項。

## 怎麼確認的

npm test、npm run build 過。模擬器第 7 套實跑：`qa:user` 備好帳號、`qa:giver` 改級並印出拜託、`emu:call` 用同名字叫得動；瀏覽器 `__qa.enter("銀行")` 從登入畫面走到銀行，店員／阿秤顯示認得／熟悉（跟 qa:giver 設的壹致）、`__qa.date(1)` 前端的今天變 11-22、`date(0)` 還原、`as` 會換網址（沒走完整個換人流程）。

## 還沒做、要注意

- 舊的「用 email＋密碼建的模擬器帳號」跟網頁的 Google 帳號 email 相同；模擬器關掉重開資料就清了，不影響，但同壹套沒關的模擬器裡舊帳號可能還是 EMAIL_EXISTS。
- `__qa.enter` 靠畫面文字找按鈕（繼續參觀、知道了、`.job-modal`、`.l2-room`）；畫面改版它會壞，壞了照 `tools/dev/browser_snippets.md` 的方法更新。
- 「聊乙掉登入」的原因沒查到（可能是別的 session 重開了第 7 套）；`local --list` 只能提醒，不能強制擋。
- 聲音沒聽過（沒改聲音）。

## 給下一個人

`qa:user` 建錢包文件會把 npcRel 清成 `{}`；之後要改錢包別的欄位用 `emu_doc data`。`__qa.date` 只撥前端的今天，伺服器的時間撥不動。
