# 經濟自我檢查（11-14，翊文：「經濟數值平衡的也寫一些腳本來自己做檢查」）

改經濟數字（`shared/config.js` 的 `NUM.casino`、`NUM.auction`、`NUM.art`…）**前後都要跑**，紅字（沒過）不准合併。

```bash
npm run econ:check                              # 規則面：讀 NUM、跑小模擬
node tools/econ_check.cjs --ledger 檔案.json    # 帳面：壹份莊家文件或日報文件，印摘要、標異常
```

## 規則面（不用正式資料）

壹次驗所有已知的套利條件和上限，**把散在各 sim 的結論變成會失敗的檢查**：

- 館內股：預告活動預先進場的期望報酬 K×p×b、劇情日最大跳空 K×b ＜ 來回成本（手續費 ×2 ＋ 持有成本）；突發事件期望；NPC 占店人數上限。
- 館外股票：手續費、持有成本 ＞ 0；真實價合理範圍；staleMin ≤ 槓桿的落後上限。
- 利率順序：活存 ＜ 定存 ＜ 館債最低壹週 ＜ 借款；文化部館債利率 ＜ 外面世界貸款。
- 畫：賣回只拿現價的 sellPct%（短線必虧）；拍賣底價下限。
- 槓桿：強平線在保證金內；強平後再碰到壹天漲跌停也不會賠光保證金（無壞帳）；淨賺、部位上限有設。
- 外面世界：NPC 壹天花費上限（來館花錢＋買畫）≤ 每天成長（**警告**）；吃緊線、賣出上限；每年成長 ≤ 30%。
- 館方投資：持股上限、每天比例、保留金 ≥ 莊家準備金；借款額度上限 ≤ 莊家壹開始的錢；文化部館債分期單靠現金撐得住。
- 小模擬（固定種子）：預告活動隔天平均跳空 ＜ 來回成本；NPC 來館花錢的平均每天。

「沒過」＝結束碼 1；「警告」不擋但要看；加新的套利條件就在 `tools/econ_check.cjs` 加壹行 `check(...)`。

## 帳面

吃壹份 JSON：`casinoHouse/main` 的內容（莊家文件，有 `bankroll`、`budget`、`world`、`debt`…），或日報 `casinoReport/日期` 的內容（有 `snap`、`gap`）。印：莊家、預算池、館方帳、外面世界、莊家的債、文化部館債進度（剩多少、幾天後到期、平均每天要還）、NPC 昨天帶進館多少、館方投資持股和累計賺賠、外面世界每個來源的累計。標出異常：

- 對帳差 ≠ 0、莊家破產、外面世界資金吃緊（＜ 起始 10%）；
- 文化部館債逾期、莊家現金加預算池不夠還、莊家現金小於今天這期；
- NPC 帶進館超過上限、館方投資虧太多；來源累計超過池子 25%。

正式站的資料怎麼拿：**要翊文同意**，跑固定動作 `econ-status`（只讀，11-14 翊文同意加；白名單欄位，不印名字、uid、email、亂數祕密、錢包），把 log 裡的 `ECON_HEX 幾行（H 莊家、R 日報；或整份 log）存成檔，餵 `--ledger`。想看每個來源和每個錢包的細項才用 `house-ledger`。這個腳本本身不連網路、不碰正式資料。
