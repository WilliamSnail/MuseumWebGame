# 0025 退休換人：看完結局可以退休，館長室的名片上也可以自己退休

- 日期：2026-11-08
- 誰決定：翊文要做（「好，加些其他的」，見第 0020 篇最後一條）；有哪幾種、條件是 Claude（subagent）提的，翊文看過再定
- 狀態：有效（先照這篇做了，等翊文看）

## 背景

- 原本只有理智歸零會換下一位參觀者（第 0016 篇）。
- 繼承的 subagent 問：「現在只有理智歸零會換人，其他結局要不要也能退休換人？」翊文：

  > 「好，加些其他的」

- 第 0020 篇寫：其他結局（館長、地下館長、你的佩佩博物館）也能退休；再加幾種退休的方式，怎麼加由做的人提，翊文看過再定。

## 決定

- **退休跟理智歸零走同一條路**（`nextVisitor`）：
  - 先留一樣東西給下一位（遺物或最拿手的技能，也可以什麼都不留）。
  - 這一位掛上歷任參觀者牆，牆上寫怎麼結束的。
  - 下一位在同一個位子：擲心情、從 3 位候選人挑、取名字。
- **第一種：看完結局退休**。
  - 哪幾個結局：館長（圖鑑全部亮了）、地下館長（走完 B5）、你的佩佩博物館（展廳 100 分）。
  - 結局畫面有兩顆按鈕：「繼續當參觀者」（主要）、「退休，換下壹位」。按退休會再問一次。
  - 理由：這三個結局都是「做完一件大事」，很像退休的時候。每間博物館各看一次（`P.endings`），之後就沒有這個按鈕了，所以還要有第二種。
  - 看完結局退休，不用等「來了幾天」。
- **第二種：館長室名片上的「退休」**，不用等到理智用完。
  - 要確認兩次（兩個問題都按「退休」）。
  - 條件：這一位要來了 1 天以上（遊戲裡的天，`LEGACY.retireDays`）。不然可以一直退休、重抽候選人的優缺點。
  - 燈熄了（要先走進那扇門）、正在發作、還在地下收藏庫、還沒挑職業：都不能退休。這些是正在發生的事，要先處理完。
  - 理由：理智歸零本來就會換一位理智 50 的新人，留東西、挑候選人都一樣。所以自己退休不會比歸零多拿什麼，只是能自己挑時候。
- 不能退休的時候，按鈕是灰的，下面寫原因（例如「剛來沒多久，再過 1 天才能退休。」）。
- **先不做（想法，等翊文挑）**：
  - 怪癖太多（例如 3 個）時，館長室建議這位「去休養」。
  - 理智太低就不能自己退休。現在可以，因為歸零也會換人，差別只在能不能挑時候。
  - 好好退休多留一點東西（例如可以留兩樣），讓退休比歸零好。
  - 標題畫面的位子卡片上也放「退休」。

## 影響

- `shared/legacy.js`：`RETIRE_ENDINGS`（可以退休的結局）、`retireCheck(P, "ending" | "office")`（可不可以退休、為什麼不行）。數字在 `config.js` 的 `LEGACY.retireDays`。
- 牆上的紀錄 `endedBy` 多了幾種：`"retire"`（在館長室自己退休）、`"curator"`、`"cellar"`、`"museum"`（看完結局退休）。牆上寫「自己決定退休了。」「看完「館長」，退休了。」
- 遺物、前一位留下的東西多記名字（`P.relics[].name`、`P.legacy.fromName`）。「第 N 位參觀者留下的」「要走了」這些字有名字就寫名字。
- 畫面：
  - `ui_screens3.js`：`retireFlow`（留東西→換人→擲心情→挑候選人，理智歸零也改用這個）、`retireBox`（名片下面）。
  - `ui_screens2.js`：結局畫面的兩顆按鈕。
- 節奏：沒有改數字。模擬（`sim.cjs`、`sim_san.cjs`）不會退休，沒有跑。
